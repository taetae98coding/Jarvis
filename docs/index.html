스펙 우선 규칙

코드를 구현하기 전에 항상 스펙 문서를 먼저 완성한다. 순서는 다음과 같다.

  1. 공통 스펙을 쓴다. 사용자 지시를 원문 그대로 옮기고, 거기서 요구사항을 뽑는다. 플랫폼에 상관없이 성립해야 하는 화면·동작·상태를 적는다.
  2. 플랫폼 스펙을 쓴다. Android / iOS / JVM / Web 각각에 대해 기술 조사를 하고, 구현 가능한지 판정한다. 기술 한계로 그대로 구현할 수 없으면 어떻게 우회했는지, 우회도 안 되면 어떤 대체 동작을 하는지 적는다.
  3. 그다음 코드를 구현한다. 구현하다 스펙과 어긋나는 것을 발견하면 코드가 아니라 스펙부터 고친다.
플랫폼 지원 범위 Android / iOS / Web은 기능을 전부 구현한다. 데스크톱(JVM)은 macOS만 구현한다. Linux·Windows 분기는 만들지 않고, 호출되면 조용히 no-op으로 빠진다.

공통 스펙 문서 하나는 플랫폼 스펙 네 문서의 같은 기능 섹션을 가리키고, 플랫폼 스펙의 기능 섹션은 자기 공통 스펙을 가리킨다. 기능 관점으로 읽으려면 common/에서, 플랫폼 관점으로 읽으려면 platform/에서 시작한다.

판정 범례

플랫폼 스펙의 기능 섹션은 반드시 다음 중 하나로 판정한다.

판정뜻
구현플랫폼이 제공하는 정식 API로 요구사항을 그대로 구현했다.
우회정식 경로가 없거나 막혀 있어 다른 방법으로 구현했다. 무엇이 막혔고 어떻게 돌아갔는지 적는다.
조건부구현했지만 환경 조건(브라우저, 보안 컨텍스트, OS 설정 등)에 따라 동작하지 않을 수 있다.
불가기술 한계로 구현하지 않았다. 대신 어떤 대체 동작(예: 0개 표시, no-op)을 하는지 적는다.
미검증구현은 했지만 자동 테스트가 없다. 컴파일 또는 수동 확인으로만 보장된다.

기기 목록·화면·제스처와 실행도 개수와 같은 경로를 탄다. JVM 외에는 같은 머신에서 데스크톱 앱이 떠 있어야 하고, iOS 시뮬레이터에는 어느 타깃에서도 제스처를 보낼 수 없다(이유). 실물 iOS 기기는 목록에만 나오고 화면을 볼 수 없다.

에뮬레이터 개수는 네 타깃 모두 실제 숫자를 내지만, JVM 외에는 같은 머신에서 데스크톱 앱이 떠 있어야 한다. 앱이 종료된 뒤에도 화면을 켜 두는 것은 Android에서만 가능하고 사이드로드를 전제로 한다. 두 조건의 근거는 공통 한계에 있다.

공통 스펙

  • 공통 규약과 한계

    expect/actual 목록, 앱 구조, 모든 플랫폼에 공통인 한계

  • 모듈 구조

    기능마다 domain / data / ui 모듈, core 와 앱 셸, 빌드 컨벤션 플러그인

  • 의존성 주입

    Koin 모듈로 리포지토리·유스케이스·ViewModel·라우트를 등록하고 주입한다

  • 화면 상태 소유 (ViewModel)

    화면 하나가 쓰는 상태와 유스케이스 호출을 ViewModel 이 소유한다

  • 화면 이동 (Navigation3)

    홈·기기 목록·기기 화면 사이를 백스택과 NavDisplay 로 옮긴다

  • 재생성을 넘기는 상태 (retain)

    마지막 프레임을 컴포지션보다 오래 들고 있는다

  • 앱 정보 카드

    앱 버전과 실행 중인 플랫폼을 보여준다

  • 화면 꺼짐 방지

    토글이 켜져 있는 동안 화면이 꺼지지 않게 한다

  • 화면 꺼짐 방지 (시스템 전역)

    앱이 없는 동안에도 화면이 꺼지지 않게 한다. Android만 가능하다

  • 설정 영구 저장

    토글 값이 앱을 껐다 켜도 남고, 외부 변경도 따라간다

  • 상태 조회 규칙

    콜백이 있으면 콜백으로, 없으면 N초마다 다시 읽는다

  • 에뮬레이터 개수

    개발자 머신의 Android 에뮬레이터·iOS 시뮬레이터를 실행 중/전체로 센다

  • 기기 목록·화면·제스처

    가상 기기와 연결된 실물 기기 목록을 보고, 화면을 보면서 탭·스와이프를 보낸다

  • 꺼진 에뮬레이터 실행

    목록에서 꺼져 있는 AVD·시뮬레이터를 그 자리에서 켠다

  • 꺼진 화면 깨우기

    연결은 됐지만 화면이 꺼진 기기를 목록에서 알아보고 켠다

  • Wi-Fi 기기 페어링

    QR 코드나 6자리 코드로 실물 Android 기기를 케이블 없이 adb 에 붙인다. iPhone·iPad 는 불가

  • 기기 목록 좌우 분할

    기기 목록을 두 열로 나눠 왼쪽에 Android, 오른쪽에 iOS 기기를 둔다

  • 카드 물결 효과

    누를 수 있는 카드의 물결이 카드의 둥근 모서리 안에서만 퍼진다

  • 화면 회전

    화면을 0·90·180·270도로 돌리고 그 각도에 고정한다

  • 홈 화면 위젯

    Android 홈 화면에서 앱을 열지 않고 화면 회전과 시스템 전역 화면 꺼짐 방지를 조작한다

  • 알림 위젯과 빠른 설정 타일

    Android 알림 창에 고정한 컨트롤과 빠른 설정 타일로 화면 회전과 시스템 전역 화면 꺼짐 방지를 조작한다

  • 홈 그리드 세로 배치

    높이가 제각각인 기능 카드를 행으로 묶지 않고 가장 짧은 열에 이어 붙인다

  • 디자인 시스템

    M3 위의 JarvisTheme 토큰, *Defaults 와 Style 로 정의한 컴포넌트, ImageVector 아이콘

  • 터미널

    iTerm 처럼 셸을 띄우고 좌우·상하 분할과 탭을 쓴다. JVM 은 pty, Android 는 파이프, iOS·Web 은 불가

  • 터미널에서 Claude 실행

    터미널 새 탭(+) 메뉴에서 골라 새 탭에 Claude Code 를 YOLO 모드로 띄운다. JVM 만 가능

  • 터미널 패널과 세션 유지

    왼쪽 패널 목록에 패널마다 탭·분할을 두고, 배치·작업 디렉터리·Claude sessionId 를 앱을 다시 켜도 유지한다. Claude 는 백그라운드에서 계속 일한다

  • 탭 끌어 놓기 분할

    상단 막대의 동작 버튼을 없애고, 새 탭은 탭 줄 끝의 + 로, 좌우·상하 분할은 탭을 창의 변에 끌어 놓아 정한다

  • 분할 그룹마다 탭 줄

    패널을 나눈 칸(그룹)마다 자기 탭 줄을 두고, 탭은 그 그룹의 + 로 붙이고 ✕ 로 닫는다. 탭 하나가 창 하나다

  • 터미널에서 웹 브라우저

    새 탭(+) 메뉴에서 골라 그 그룹에 웹 페이지 탭을 연다. 시스템 웹뷰를 쓰고 마지막 주소를 저장한다. JVM(macOS)·Android

  • 터미널에서 기기 화면

    새 탭(+) 메뉴에 화면을 볼 수 있는 에뮬레이터·실물 기기가 나오고, 고르면 그 그룹에 기기 화면 탭을 열어 탭·스와이프를 보낸다. JVM(macOS)·Android

  • 탭 종류 표시와 이름 바꾸기

    탭 제목 앞의 아이콘·색으로 터미널·Claude·브라우저·Android·iOS 탭을 가르고, 탭 제목을 두 번 눌러 이름을 바꾼다. 이름은 저장된다

  • Chrome 쿠키 가져오기

    브라우저 탭 주소 줄의 버튼으로 이 PC 의 Chrome 프로필을 골라 모든 사이트 쿠키를 웹뷰로 옮긴다. 영구 저장소라 앱을 껐다 켜도 로그인이 이어진다. JVM(macOS)

  • 기기 화면 영상 스트림·호버

    Android 기기 화면을 기기 안 에이전트의 H.264 영상으로 받고, 누름·끌기·마우스 호버를 그 자리에서 기기에 넣는다. JVM 은 직접, 나머지는 호스트가 푼 프레임을 JPEG 로

  • 새 패널 제목·폴더

    "새 패널" 이 제목(비우면 "패널 N")과 폴더를 받는 창을 띄우고, "확인" 이 그 제목·폴더의 빈 패널을 만든다. 탭은 빈 패널의 + 로 그 폴더에서 연다

  • 패널에서 git 워크트리 추가·지우기

    git 저장소 폴더의 패널에 + 가 붙고, 브랜치와 기준 브랜치를 받아 git worktree add 로 만든 워크트리를 그 패널 아래 들여쓴 빈 패널로 열고, 줄에 기준 → 현재 브랜치를 보인다. 워크트리 패널의 ✕ 는 워크트리·브랜치와 폴더를 지울지 묻는다. JVM(macOS)

  • 패널 줄의 Claude 상태 표시

    패널 줄마다 그 패널 Claude 탭의 상태를 작업 중·응답 대기·확인함·모니터링 중 네 표시 중 하나로 보인다. 응답 대기는 끝난 결과를 사용자가 아직 보지 않은 것이다. JVM(macOS)
