스펙 우선 규칙

코드를 구현하기 전에 항상 스펙 문서를 먼저 완성한다. 순서는 다음과 같다.

  1. 공통 스펙을 쓴다. 사용자 지시를 원문 그대로 옮기고, 거기서 요구사항을 뽑는다. 플랫폼에 상관없이 성립해야 하는 화면·동작·상태를 적는다.
  2. 플랫폼 스펙을 쓴다. Android / iOS / JVM / Web 각각에 대해 기술 조사를 하고, 구현 가능한지 판정한다. 기술 한계로 그대로 구현할 수 없으면 어떻게 우회했는지, 우회도 안 되면 어떤 대체 동작을 하는지 적는다.
  3. 그다음 코드를 구현한다. 구현하다 스펙과 어긋나는 것을 발견하면 코드가 아니라 스펙부터 고친다.
플랫폼 지원 범위 Android / iOS / Web은 기능을 전부 구현한다. 데스크톱(JVM)은 macOS만 구현한다. Linux·Windows 분기는 만들지 않고, 호출되면 조용히 no-op으로 빠진다.

공통 스펙 문서 하나는 플랫폼 스펙 네 문서의 같은 기능 섹션을 가리키고, 플랫폼 스펙의 기능 섹션은 자기 공통 스펙을 가리킨다. 기능 관점으로 읽으려면 common/에서, 플랫폼 관점으로 읽으려면 platform/에서 시작한다.

판정 범례

플랫폼 스펙의 기능 섹션은 반드시 다음 중 하나로 판정한다.

판정뜻
구현플랫폼이 제공하는 정식 API로 요구사항을 그대로 구현했다.
우회정식 경로가 없거나 막혀 있어 다른 방법으로 구현했다. 무엇이 막혔고 어떻게 돌아갔는지 적는다.
조건부구현했지만 환경 조건(브라우저, 보안 컨텍스트, OS 설정 등)에 따라 동작하지 않을 수 있다.
불가기술 한계로 구현하지 않았다. 대신 어떤 대체 동작(예: 0개 표시, no-op)을 하는지 적는다.
미검증구현은 했지만 자동 테스트가 없다. 컴파일 또는 수동 확인으로만 보장된다.

기기 목록·화면·제스처와 실행도 개수와 같은 경로를 탄다. JVM 외에는 같은 머신에서 데스크톱 앱이 떠 있어야 하고, iOS 시뮬레이터에는 어느 타깃에서도 제스처를 보낼 수 없다(이유). 실물 iOS 기기는 목록에만 나오고 화면을 볼 수 없다.

에뮬레이터 개수는 네 타깃 모두 실제 숫자를 내지만, JVM 외에는 같은 머신에서 데스크톱 앱이 떠 있어야 한다. 앱이 종료된 뒤에도 화면을 켜 두는 것은 Android에서만 가능하고 사이드로드를 전제로 한다. 두 조건의 근거는 공통 한계에 있다.

공통 스펙

  • 공통 규약과 한계

    expect/actual 목록, 앱 구조, 모든 플랫폼에 공통인 한계

  • 모듈 구조

    domain / data / ui 계층 모듈과 조립 모듈, 패키지 규칙

  • 앱 정보 카드

    앱 버전과 실행 중인 플랫폼을 보여준다

  • 화면 꺼짐 방지

    토글이 켜져 있는 동안 화면이 꺼지지 않게 한다

  • 화면 꺼짐 방지 (시스템 전역)

    앱이 없는 동안에도 화면이 꺼지지 않게 한다. Android만 가능하다

  • 설정 영구 저장

    토글 값이 앱을 껐다 켜도 남고, 외부 변경도 따라간다

  • 상태 조회 규칙

    콜백이 있으면 콜백으로, 없으면 N초마다 다시 읽는다

  • 에뮬레이터 개수

    개발자 머신의 Android 에뮬레이터·iOS 시뮬레이터를 실행 중/전체로 센다

  • 기기 목록·화면·제스처

    가상 기기와 연결된 실물 기기 목록을 보고, 화면을 보면서 탭·스와이프를 보낸다

  • 꺼진 에뮬레이터 실행

    목록에서 꺼져 있는 AVD·시뮬레이터를 그 자리에서 켠다

  • 꺼진 화면 깨우기

    연결은 됐지만 화면이 꺼진 기기를 목록에서 알아보고 켠다

  • 카드 물결 효과

    누를 수 있는 카드의 물결이 카드의 둥근 모서리 안에서만 퍼진다

  • 화면 회전

    화면을 0·90·180·270도로 돌리고 그 각도에 고정한다

플랫폼 스펙

  • 플랫폼 스펙 읽는 법

    섹션 구성과 판정 기준

  • Android

    :androidApp + :shared, minSdk 24

  • iOS

    iosApp Xcode 프로젝트 + Shared 프레임워크, iOS 16.0+

  • JVM (Desktop, macOS)

    :desktopApp + :shared, Java 21

  • Web (Wasm)

    :webApp + :shared, Kotlin/Wasm

템플릿

새 기능은 아래 두 뼈대를 복사해서 시작한다. 채워야 할 자리는 HTML 주석으로 표시되어 있다.

  • 공통 스펙 템플릿 — docs/common/<기능>.html로 복사
  • 플랫폼 스펙 섹션 템플릿 — 네 플랫폼 문서 각각에 <section class="feature">로 붙인다
코드를 고칠 때 스펙도 함께 고친다. 코드와 어긋난 스펙은 없느니만 못하다.
