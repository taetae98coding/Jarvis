사용자 지시

토글 상태는 앱을 완전히 껐다 켜도 복원되어야 한다.

커밋 503bff1에서 복원.

설정과 에뮬레이터 상태를 Flow로 관찰하게 바꿔라. 앱 밖에서 값이 바뀌면 UI가 따라가야 한다.

커밋 c49ff47 "Observe settings and emulator status through Flows"에서 복원.

요구사항

  1. R1. boolean 설정을 키로 읽고 쓸 수 있다. 키가 없으면 호출자가 준 기본값을 돌려준다.
  2. R2. 값은 프로세스 종료 후에도 남는다. 다음 실행의 첫 프레임부터 저장된 값이 보인다.
  3. R3. 저장소가 바뀌면(이 앱이 썼든, 밖에서 썼든) 화면이 따라간다.
  4. R4. 플랫폼별 저장소의 차이는 SettingsStore 뒤에 숨긴다. 공용 코드는 어떤 저장소인지 모른다.

동작

  • 토글을 바꾸면 즉시 저장소에 쓴다. 쓰기가 성공했는지 화면에 알리지는 않는다.
  • 화면은 저장소의 변경 알림을 구독한다. 이 앱이 쓴 값도 그 경로로 되돌아와 화면에 반영된다. 즉 화면 상태의 원본은 메모리가 아니라 저장소다.
  • 앱 시작 시 저장소를 동기로 한 번 읽어 초기값을 잡는다. Flow의 첫 방출은 컴포지션이 한 번 끝난 뒤에야 도착하므로, 그것만 기다리면 첫 프레임에 기본값이 깜빡인다.

공통 구현

인터페이스
shared/platform/SettingsStore.kt
상태
shared/settings/AppSettings.kt
공급
@Composable expect fun rememberSettingsStore(): SettingsStore
internal interface SettingsStore {
    fun getBoolean(key: String, defaultValue: Boolean): Boolean
    fun putBoolean(key: String, value: Boolean)
    val changes: Flow<Unit>?

    fun observeBoolean(key: String, defaultValue: Boolean): Flow<Boolean> =
        observeSystemState(signals = changes, interval = SettingsPollInterval) {
            getBoolean(key, defaultValue)
        }
}
결정: changes는 어떤 키가 바뀌었는지 담지 않는다 iOS의 NSUserDefaultsDidChangeNotification이 바뀐 키를 알려주지 않는다. 네 플랫폼에 같은 계약을 주기 위해 키별 필터링 대신 "무언가 바뀌었다" 신호만 받고, 값을 다시 읽어 걸러낸다. 첫 값·중복 제거·신호 합치기는 상태 조회 규칙이 담당한다.
결정: changes는 nullable이다 변경을 알려주지 않는 저장소는 null을 두고 2초 폴링으로 대체한다는 계약을 타입에 적었다. 지금 네 플랫폼은 모두 콜백을 제공하므로 폴링 경로는 쓰이지 않지만, 저장소를 갈아끼울 때 알림 없는 구현을 넣어도 R3이 깨지지 않는다.

AppSettings는 observeBoolean을 stateIn(scope, SharingStarted.Eagerly, store.getBoolean(...))으로 StateFlow로 바꾼다. 초기값을 동기로 읽는 이유가 R2의 "첫 프레임부터"다. 쓰기는 store.putBoolean에 위임만 하고 메모리 상태를 직접 바꾸지 않는다.

한계

  • 동기 API다. 값이 늘면 DataStore로 갈아끼운다.
  • 쓰기 실패를 알리지 않는다. Web의 시크릿 모드처럼 저장소 접근이 예외를 던지는 경우 지금은 잡지 않는다.
  • boolean만 지원한다. 다른 타입이 필요하면 인터페이스에 메서드를 추가하고 네 actual을 함께 늘린다. 이미 그 벽에 부딪힌 곳이 하나 있다. 시스템 전역 화면 유지가 되돌릴 화면 꺼짐 시간(Int)을 여기 넣지 못하고 Android 전용 SharedPreferences 파일에 따로 보관한다.
