터미널에서 Claude 실행

터미널 상단 막대의 Claude 아이콘을 누르면 새 탭에서 Claude Code 를 YOLO 모드(권한 확인 없이)로 띄운다.

사용자 지시

terminal에서 claude icon 추가해서 클릭 시 claude yolo모드로 실행하도록 구현할 수 있어?

2026-09-24 대화. "yolo 모드" 는 Claude Code CLI 의 --dangerously-skip-permissions(모든 권한 확인을 건너뜀)로 읽었다. "terminal에서" 는 터미널 화면의 상단 막대로 읽었다.

요구사항

  1. R1. 터미널 화면 상단 막대에 Claude 아이콘 버튼(contentDescription "Claude (YOLO)")이 있다. 새 탭 버튼 바로 앞에 놓인다.
  2. R2. 누르면 새 탭(터미널 R7 과 같은 자리·선택 규칙)이 열리고, 그 패널에서 claude --dangerously-skip-permissions 가 실행된다.
  3. R3. claude 는 사용자가 셸에서 치는 것과 같은 환경에서 찾는다 — 로그인 셸의 PATH 와 대화형 셸 설정(~/.zshrc 등)이 적용된 뒤에 실행한다.
  4. R4. Claude 가 끝나면(또는 claude 를 찾지 못하면) 그 패널은 닫히지 않고 같은 작업 디렉터리의 로그인 셸로 이어진다. 출력은 화면에 남는다.
  5. R5. Claude 탭의 패널을 분할하면 새 패널은 일반 셸이다. Claude 는 버튼을 누른 패널에서만 뜬다.
  6. R6. Claude 를 실행할 수 없는 타깃에서는 버튼이 보이지 않는다. 나머지 터미널 기능은 그대로다.
  7. R7. Jarvis 자신이 Claude Code 세션 안에서 띄워졌어도(개발 중 ./gradlew :desktopApp:run 을 Claude 가 실행한 경우) 터미널의 셸은 그 세션의 자식으로 취급되지 않는다. 부모 세션이 남긴 환경 변수를 셸에 물려주지 않는다.
스코프에서 뺀 것
  • 단축키. 지시에 없고, ⌘ 조합은 셸·Claude 쪽 입력과 겹치기 쉽다.
  • Claude 옵션 고르기(모델, 이어하기 --continue, 작업 디렉터리). 작업 디렉터리는 셸과 같은 홈이다.
  • YOLO 모드를 끄고 켜는 설정. 지시가 YOLO 모드 실행 하나다.
  • Claude 설치 여부를 미리 검사해 버튼을 잠그기. 로그인 셸을 한 번 띄워야 알 수 있어 화면 진입이 느려진다. 없으면 셸이 "command not found" 를 보여주고 R4 대로 셸이 남는다.

공통 구현

도메인
enum class TerminalProgram { Shell, Claude } — 패널이 처음 띄울 프로그램.
TerminalRepository.isClaudeSupported: Boolean, open(size, program = Shell).
IsClaudeSupportedUseCase. OpenTerminalSessionUseCase(size, program) 는 지원하지 않는 프로그램이면 저장소를 부르지 않고 null.
공급
TerminalDataSource.isClaudeSupported, open(size, program). createTerminalDataSource 의 expect 시그니처는 그대로다
상태
TerminalViewModel.isClaudeSupported: Boolean, addClaudeTab(). 작업 공간 변경으로 새로 생긴 패널 id 에 붙일 프로그램을 update 가 받는다 — 탭 추가·분할은 Shell, Claude 버튼만 Claude(R5)
UI
TerminalScreen 의 상단 막대. isClaudeSupported 가 false 면 버튼을 그리지 않는다(R6)
결정: 프로그램은 작업 공간이 아니라 ViewModel 이 패널을 만들 때 넘긴다 PaneNode.Leaf 에 프로그램을 넣으면 탭·분할 규칙이 모르는 값이 트리에 섞이고, 패널 id 로 형제를 찾는 비교(first == Leaf(paneId))가 깨진다. 프로그램은 셸을 띄우는 순간에만 쓰이고 그 뒤로 패널의 동작을 바꾸지 않으므로, 새 패널을 만드는 쪽(TerminalViewModel.reconcile)이 한 번 넘기고 잊는다.
결정: Claude 를 셸 안에서 실행하고 끝나면 셸로 이어 간다 후보는 셋이었다. (1) 일반 셸을 띄우고 claude …\n 을 입력으로 흘려 넣기 — 셸이 준비되기 전에 pty 가 입력을 한 번 에코하고, zsh 가 프롬프트 뒤에 다시 그려 같은 명령이 두 번 보인다. 버렸다. (2) claude 를 직접 실행 — 로그인·대화형 셸 설정이 적용되지 않아 ~/.zshrc 에서 PATH 를 잡는 설치(~/.local/bin, nvm)에서 찾지 못하고, 끝나면 패널이 닫혀 출력도 사라진다. 버렸다. (3) 채택: 셸을 로그인·대화형으로 띄워 -c 로 claude --dangerously-skip-permissions; exec <셸> -l 을 실행한다. 설정이 적용된 뒤 Claude 가 뜨고(R3), 끝나면 같은 pty 위에서 로그인 셸로 바뀐다(R4). 명령 문자열의 셸 문법(;, exec)은 zsh·bash·fish 가 모두 받는다.

한계

  • YOLO 모드는 Claude 가 파일 수정·명령 실행을 묻지 않고 한다. 작업 디렉터리가 홈이므로 홈 아래 전부가 그 범위다. 버튼 이름에 "YOLO" 를 남겨 모드를 드러낸다.
  • claude 를 찾지 못하면 셸의 "command not found" 한 줄 뒤에 셸이 뜬다. 앱이 따로 알려 주지 않는다.
  • R7 은 Claude Code 2.1.281 이 자식 프로세스에 넘기는 환경 변수 이름을 기준으로 한다. 버전이 바뀌어 새 이름이 생기면 목록을 고쳐야 한다(JVM).
  • 터미널의 한계가 그대로 든다. 특히 텍스트 선택·복사가 없다.
