터미널에서 Claude 실행

터미널 상단 막대의 새 탭(+) 버튼을 누르면 "터미널" 과 "Claude (YOLO)" 중 하나를 고르는 메뉴가 뜬다. Claude 를 고르면 새 탭에서 Claude Code 를 YOLO 모드(권한 확인 없이)로 띄운다.

사용자 지시

terminal에서 claude icon 추가해서 클릭 시 claude yolo모드로 실행하도록 구현할 수 있어?

2026-09-24 대화. "yolo 모드" 는 Claude Code CLI 의 --dangerously-skip-permissions(모든 권한 확인을 건너뜀)로 읽었다. "terminal에서" 는 터미널 화면의 상단 막대로 읽었다.

plus 누를 때 claude or terminal 선택할 수 있도록 하자. 그리고 actions에 claude 제거해줘.

2026-09-24 대화. "plus" 는 상단 막대의 새 탭(Add) 버튼, "actions" 는 JarvisTopBar 의 오른쪽 동작 버튼 줄로 읽었다. 이 지시로 R1·R6 이 바뀌었다.

뒤따른 패널 지시로 Claude 는 앱 안에서 직접 뜨지 않고 Claude Code 의 백그라운드 세션으로 돌며, 창은 그 세션에 붙는다. sessionId 를 저장하고 이어 가는 규칙은 그 문서의 R11·R12 다. 이 문서의 R2·R4 와 구현을 거기에 맞춰 고쳤다. 그 뒤 탭 끌어 놓기 지시로 상단 막대의 동작 버튼이 전부 없어지고 새 탭(+) 버튼은 탭 줄 끝으로 옮겨 갔다. R1·R6 의 "상단 막대" 는 그렇게 읽는다. 그 뒤 분할 그룹 지시로 + 버튼은 그룹마다 하나가 됐고, 고른 것은 그 그룹의 탭이 된다.

요구사항

  1. R1. 상단 막대에는 Claude 버튼이 없다(지금은 동작 버튼이 아예 없다 — 탭 끌어 놓기 R1). 탭 줄 끝의 새 탭(+) 버튼을 누르면 그 아래로 메뉴가 뜨고 항목은 위에서부터 "터미널", "Claude (YOLO)" 다(그 뒤에 웹 브라우저가 붙을 수 있다). 메뉴 바깥을 누르거나 항목을 고르면 메뉴가 닫힌다.
  2. R2. "Claude (YOLO)" 를 고르면 새 탭(터미널 R7 과 같은 자리·선택 규칙)이 열리고, 그 창에 YOLO 모드(--dangerously-skip-permissions)의 Claude 백그라운드 세션이 붙는다(패널 R11). 세션의 작업 디렉터리는 포커스돼 있던 창의 작업 디렉터리다(패널 R8).
  3. R3. claude 는 사용자가 셸에서 치는 것과 같은 환경에서 찾는다 — 로그인 셸의 PATH 와 대화형 셸 설정(~/.zshrc 등)이 적용된 뒤에 실행한다.
  4. R4. 창에서 Claude 가 끝나거나 attach 에서 빠져나오면(또는 claude 를 찾지 못하면) 그 창은 닫히지 않고 로그인 셸로 이어진다. 출력은 화면에 남는다. 백그라운드 세션은 attach 에서 빠져나와도 계속 돈다.
  5. R5. Claude 탭이 있는 그룹을 분할하면 새 그룹의 탭은 일반 셸이다. Claude 는 메뉴에서 고른 그룹에서만 뜬다(분할 그룹).
  6. R6. Claude 를 실행할 수 없는 타깃에서는 메뉴에 "Claude (YOLO)" 가 없다. 남은 항목이 "터미널" 하나뿐이면 메뉴를 띄우지 않고 새 탭 버튼이 곧바로 셸 탭을 연다(항목 하나뿐인 메뉴는 한 번 더 누르게 할 뿐이다, 웹 브라우저 R1). 나머지 터미널 기능은 그대로다.
  7. R8. 메뉴의 "터미널" 과 ⌘T 는 일반 셸 탭을 연다(터미널 R7).
  8. R7. Jarvis 자신이 Claude Code 세션 안에서 띄워졌어도(개발 중 ./gradlew :desktopApp:run 을 Claude 가 실행한 경우) 터미널의 셸은 그 세션의 자식으로 취급되지 않는다. 부모 세션이 남긴 환경 변수를 셸에 물려주지 않는다.
스코프에서 뺀 것
  • Claude 탭 단축키. 지시에 없고, ⌘ 조합은 셸·Claude 쪽 입력과 겹치기 쉽다. ⌘T 는 메뉴를 거치지 않고 셸 탭을 연다.
  • Claude 옵션 고르기(모델, 이어하기 --continue, 작업 디렉터리). 작업 디렉터리는 셸과 같은 홈이다.
  • YOLO 모드를 끄고 켜는 설정. 지시가 YOLO 모드 실행 하나다.
  • Claude 설치 여부를 미리 검사해 버튼을 잠그기. 로그인 셸을 한 번 띄워야 알 수 있어 화면 진입이 느려진다. 없으면 셸이 "command not found" 를 보여주고 R4 대로 셸이 남는다.

항목값

고른 뒤메뉴가 닫히고 탭 줄 끝에 탭이 붙어 선택된다. 탭 이름은 셸·Claude 가 OSC 로 정한 제목, 없으면 "셸 N"(터미널 R13)

공통 구현

도메인
enum class TerminalProgram { Shell, Claude } — 창이 처음 띄울 프로그램.
TerminalRepository.isClaudeSupported: Boolean, open(size, pane), stopClaude(sessionId).
IsClaudeSupportedUseCase. OpenTerminalSessionUseCase(size, pane) 는 지원하지 않는 프로그램이거나 Claude 창에 sessionId 가 없으면 저장소를 부르지 않고 null.
공급
TerminalDataSource.isClaudeSupported, open(size, pane), stopClaude(sessionId). createTerminalDataSource 의 expect 시그니처는 그대로다
상태
TerminalViewModel.isClaudeSupported: Boolean, addClaudeTab(). 새 잎을 program = Claude 와 새 sessionId 로 만든다. 분할은 늘 Shell 잎을 만든다(R5)
UI
TerminalScreen 탭 줄 끝의 NewTabButton(처음에는 상단 막대에 있었다). 메뉴가 열렸는지는 화면 안에서만 쓰는 값이라 ViewModel 이 아니라 remember 로 둔다. isClaudeSupported 가 false 면 onNewClaudeTab 이 null 이라 항목이 빠진다. 브라우저 항목(onNewBrowserTab)도 null 이면 버튼이 곧바로 addTab() 을 부른다(R6)
결정: 프로그램은 탭(TerminalTab, 이전 PaneNode.Leaf)에 둔다 처음에는 프로그램을 작업 공간에 넣지 않고 ViewModel 이 창을 만들 때 한 번 넘기고 잊었다. 탭·분할 규칙이 모르는 값이 트리에 섞이지 않고, 형제를 찾는 비교(first == Leaf(paneId))도 그대로 둘 수 있었다. 패널 지시로 배치를 저장해 다시 열게 되면서, 다시 열 때 무엇을 띄울지(프로그램·작업 디렉터리·sessionId)를 잎이 알아야 해서 잎으로 옮겼다. 형제 비교는 id 로 한다.
결정: Claude 명령을 셸 안에서 실행하고 끝나면 셸로 이어 간다 후보는 셋이었다. (1) 일반 셸을 띄우고 claude …\n 을 입력으로 흘려 넣기 — 셸이 준비되기 전에 pty 가 입력을 한 번 에코하고, zsh 가 프롬프트 뒤에 다시 그려 같은 명령이 두 번 보인다. 버렸다. (2) claude 를 직접 실행 — 로그인·대화형 셸 설정이 적용되지 않아 ~/.zshrc 에서 PATH 를 잡는 설치(~/.local/bin, nvm)에서 찾지 못하고, 끝나면 창이 닫혀 출력도 사라진다. 버렸다. (3) 채택: 셸을 로그인·대화형으로 띄워 -c 로 claude attach <id>; exec <셸> -l 을 실행한다(처음에는 claude --dangerously-skip-permissions 였다. 백그라운드 세션으로 바꾼 이유는 패널 결정). 설정이 적용된 뒤 Claude 가 뜨고(R3), 끝나면 같은 pty 위에서 로그인 셸로 바뀐다(R4). 명령 문자열의 셸 문법(;, exec)은 zsh·bash·fish 가 모두 받는다.

한계

  • YOLO 모드는 Claude 가 파일 수정·명령 실행을 묻지 않고 한다. 작업 디렉터리(기본은 홈) 아래 전부가 그 범위이고, 앱을 끈 뒤에도 백그라운드에서 그렇게 한다. 메뉴 항목 이름에 "YOLO" 를 남겨 모드를 드러낸다.
  • claude 를 찾지 못하면 셸의 "command not found" 한 줄 뒤에 셸이 뜬다. 앱이 따로 알려 주지 않는다.
  • R7 은 Claude Code 2.1.281 이 자식 프로세스에 넘기는 환경 변수 이름을 기준으로 한다. 버전이 바뀌어 새 이름이 생기면 목록을 고쳐야 한다(JVM).
  • 터미널의 한계가 그대로 든다. 특히 텍스트 선택·복사가 없다.
