터미널에서 기기 화면

그룹의 새 탭(+) 메뉴에 지금 화면을 볼 수 있는 에뮬레이터·시뮬레이터·연결된 실물 기기가 나오고, 하나를 고르면 그 그룹에 기기 화면 탭이 붙는다. 탭 안에서 기기 화면을 누르고 끌면 기기 목록의 스트리밍 화면과 똑같이 탭·스와이프가 기기로 간다.

사용자 지시

terminal에서 탭 추가할 때 에뮬레이터, 연결된 디바이스도 추가할 수 있도록 구현해줘. 당연히 에뮬레이터 스펙처럼 터치 드래그도 지원해야해.

2026-09-24 대화. "탭 추가" 는 그룹마다 있는 새 탭(+) 메뉴(웹 브라우저와 같은 자리)로, "에뮬레이터 스펙처럼 터치 드래그" 는 기기 목록·화면·제스처 R6·R7·R8(탭 = 탭, 드래그 = 스와이프, 보낼 수 없는 기기는 화면만)으로 읽었다.

요구사항

  1. R1. 새 탭(+) 메뉴의 "터미널", "Claude (YOLO)", "웹 브라우저" 아래에 구분선과 "기기" 머리글이 붙고, 그 아래에 지금 화면을 볼 수 있는 기기(canStream)가 한 줄씩 나온다. 가상 기기와 실물 기기, Android 와 iOS 가 섞이며 순서는 기기 목록이 준 순서다. 꺼진 가상 기기와 화면을 볼 수 없는 실물 기기(실물 iOS)는 나오지 않는다.
  2. R2. 기기 줄은 이름과, 그 아래 한 줄의 종류("Android 에뮬레이터", "Android 실물 기기", "iOS 시뮬레이터")다. 첫 목록이 오기 전에는 누를 수 없는 "기기를 찾는 중…" 한 줄, 볼 수 있는 기기가 없으면 누를 수 없는 "화면을 볼 수 있는 기기가 없습니다" 한 줄이다.
  3. R3. 기기 목록은 메뉴가 떠 있는 동안에만 센다. 메뉴를 다시 열면 지난번 목록을 곧바로 보이고 새 목록이 오면 바꾼다.
  4. R4. 기기를 고르면 그 그룹의 탭 줄 끝에 기기 탭이 붙어 선택되고 그 그룹이 포커스를 받는다(셸 탭과 같은 자리·선택 규칙). 같은 기기를 여러 탭에 열 수 있다.
  5. R5. 기기 탭의 창은 기기 화면이다. 첫 프레임 전 "화면을 가져오는 중…", 한 장도 못 받으면 "화면을 가져올 수 없습니다.", 받은 뒤 실패하면 마지막 프레임을 그대로 둔다(기기 화면 R5·R11).
  6. R6. 기기 화면을 누르고 끌고 떼면 각각 그 순간 기기 좌표의 DOWN·MOVE·UP 으로 가고, 마우스가 누르지 않고 움직이면 호버로 간다. 좌표 변환·레터박스 규칙은 기기 화면과 같다(같은 코드다). 마우스와 터치 모두 된다. 2026-09-24 이전에는 뗀 뒤 탭·스와이프 하나로 보냈다(영상 스트림).
  7. R7. 제스처를 보낼 수 없는 기기(iOS 시뮬레이터)는 화면만 보이고 위에 "이 기기에는 제스처를 보낼 수 없습니다. 화면만 볼 수 있습니다." 를 적는다. 화면이 꺼진 실물 기기에는 기기 화면과 같은 "화면 켜기" 카드가 겹친다(꺼진 화면 깨우기).
  8. R8. 기기 화면을 누르면 그 그룹이 포커스를 받는다. 누름은 제스처로도 그대로 간다.
  9. R9. 탭 이름은 고를 때의 기기 이름이다. 기기 이름은 탭에 저장되어 가려진 탭과 앱을 다시 켠 뒤에도 그대로 보인다.
  10. R10. 기기 탭은 기기 식별자와 이름을 저장한다. 앱을 다시 켜면 같은 식별자의 기기 화면을 다시 연다. 그 기기가 없으면(뽑혔거나 꺼졌으면) R5 대로 "화면을 가져올 수 없습니다." 가 보이고, 다시 나타나면 화면이 이어진다.
  11. R11. 프레임은 탭이 보이는 동안에만 찍는다. 가려진 탭, 다른 패널의 탭, 터미널 화면을 벗어난 뒤, 앱이 백그라운드로 간 뒤에는 촬영이 멈춘다(기기 화면 R10).
  12. R12. 기기 탭은 셸을 띄우지 않는다. 닫기(✕), 끌어 놓아 분할·옮기기, 탭 고르기 단축키는 셸 탭과 같다. 기기 탭이 선택된 그룹을 ⌘D 로 나누면 새 그룹의 탭은 셸이고, 기기 탭에는 작업 디렉터리가 없으므로 패널의 폴더(없으면 홈)에서 시작한다.
  13. R13. 기기 화면을 보여 줄 수 없는 조립(기기 기능이 빠진 앱)에서는 메뉴에 "기기" 구획이 없다. 그런 조립에서 저장된 기기 탭을 열면 "[기기 화면을 열 수 없습니다]" 만 보인다.
  14. R14. 메뉴에 고를 것이 "터미널" 하나뿐일 때만 메뉴 없이 곧바로 셸 탭을 연다(웹 브라우저 R1). "기기" 구획이 있으면 기기가 없더라도 메뉴가 뜬다 — 기기가 없다는 것도 메뉴가 알려 준다.
스코프에서 뺀 것
  • 꺼진 에뮬레이터를 메뉴에서 켜는 것. 켜는 것은 기기 목록 화면이 한다(꺼진 에뮬레이터 실행). 메뉴에는 지금 볼 수 있는 것만 둔다.
  • 키 입력(텍스트·하드웨어 키), 멀티터치·핀치, 길게 누르기. 기기 화면 스펙이 빼 둔 것을 그대로 뺀다.
  • 기기 탭 단축키. ⌘T 는 셸 탭 그대로다.
  • 탭 이름을 기기의 지금 이름으로 따라 바꾸는 것(R9). 가려진 탭의 이름을 알려고 목록을 계속 세지 않는다.
  • AVD 가 다시 켜져 시리얼(emulator-5554 → emulator-5556)이 바뀐 것을 따라가는 것. 한계.

화면·동작

항목값
메뉴 구획HorizontalDivider 뒤에 머리글 "기기"(labelMedium, onSurfaceVariant). 그 아래 기기 줄
기기 줄앞 아이콘 JarvisIcons.Smartphone. 글자는 이름(bodyLarge) 아래 종류(bodySmall, onSurfaceVariant)
종류Android 가상 = "Android 에뮬레이터", Android 실물 = "Android 실물 기기", iOS 가상 = "iOS 시뮬레이터"
빈 줄"기기를 찾는 중…" / "화면을 볼 수 있는 기기가 없습니다" — 누를 수 없다
기기 탭 창그룹 안 남은 칸 전부. 위에 제스처 불가 문구(있으면), 아래 가운데에 원본 비율 그대로(ContentScale.Fit) 기기 화면. 상단 막대·뒤로 버튼은 없다
탭 이름저장된 기기 이름. 비어 있으면 "기기 N"
테스트 태그terminal:new-tab-menu:device:<deviceId>(메뉴 줄), terminal:new-tab-menu:devices-empty(빈 줄), terminal:device:<tabId>(기기 탭 창). 창 안의 프레임은 기기 화면과 같은 emulator:frame

공통 구현

도메인 (terminal)
TerminalProgram.Device. TerminalTab.deviceId: String?, deviceName: String? — Device 탭에만 있다.
TerminalWorkspace.addTab(groupId, program = Device, deviceId = …, deviceName = …). OpenTerminalSessionUseCase 는 Device 탭이면 저장소를 부르지 않고 null(R12)
공급 (terminal)
저장 형식에 program = "device" 와 deviceId·deviceName 키가 는다. deviceId 가 없는 device 탭은 셸로 읽는다. expect 선언은 늘지 않는다
기능 사이
:core:ui 의 DeviceScreens(인터페이스)와 DeviceChoice(id, name, kind). :feature:emulator:ui 가 구현을 Koin 에 single<DeviceScreens> 로 등록하고, :feature:terminal:ui 가 getKoin().getOrNull<DeviceScreens>() 로 받는다(없으면 R13)
상태
DeviceScreens.choices(): List<DeviceChoice>?(@Composable, null = 아직 모름)은 emulator 의 DeviceChoicesViewModel(초기값 null, WhileSubscribed)을 모은다. 메뉴 내용은 메뉴가 떠 있을 때만 컴포즈되므로 그때만 센다(R3). 이 ViewModel 은 터미널 화면의 백스택 항목에 붙어 있어 메뉴를 닫아도 지난 목록을 들고 있다.
DeviceScreens.Screen(deviceId, modifier) 는 EmulatorScreenViewModel(deviceId) 를 key = "device-screen:$deviceId" 로 받는다 — 기기마다 ViewModel 이 따로다.
TerminalViewModel.isDeviceSupported, addDeviceTab(groupId, choice). reconcile 은 Device 탭의 셸 창을 열지 않는다
UI
EmulatorStreamScreen 의 상단 막대 아래를 EmulatorStream(viewModel, modifier) 로 떼어 내 두 곳(기기 목록의 화면, 터미널 탭)이 같은 컴포저블을 쓴다(R5–R7). 수집은 그 안의 repeatOnLifecycle(STARTED) 이라 컴포지션에서 빠지거나 앱이 백그라운드로 가면 멈춘다(R11).
feature/terminal/ui/.../TerminalDevice.kt — 탭 창. PointerEventPass.Initial 에서 누름만 보고 소비하지 않은 채 그룹 포커스를 준다(R8)
결정: 기능 사이를 :core:ui 의 인터페이스 하나로 잇는다 터미널이 기기 화면을 그려야 하지만 기능은 서로를 의존하지 않는다(모듈 구조 R3). 후보는 넷이었다. (1) :feature:terminal:ui 가 :feature:emulator:ui 를 의존한다 — R3 을 그대로 깬다. 버렸다. (2) 기기 스트리밍 코드(화면·ViewModel·유스케이스)를 :core:* 로 내린다 — 두 기능이 쓰게 되니 R4 로는 맞지만 emulator 의 domain·data·ui 가 통째로 core 로 옮겨 가고 core 에 기능 하나가 생긴다. 버렸다. (3) 터미널이 EmulatorRoute.Screen 으로 이동한다 — 탭 안에 들어가지 않는다. 버렸다. (4) 채택: Navigator 와 같은 방식으로 이음새만 공용에 둔다. :core:ui 에 인터페이스 DeviceScreens(기기 고르기용 목록, 기기 화면 컴포저블)와 값 DeviceChoice 만 두고, emulator 가 구현을 Koin 에 등록한다. 경계를 넘는 것은 식별자·이름·종류 문자열뿐이고 EmulatorDevice 는 넘지 않는다. 터미널은 구현이 없어도 동작한다(R13).
결정: 기기 탭도 TerminalTab 이다 브라우저 탭과 같은 이유다(웹 브라우저). 탭 줄·끌어 놓기·닫기·저장이 전부 TerminalTab 을 단위로 돈다. program 을 하나 늘리고 셸을 띄우는 두 곳과 창을 그리는 한 곳(TerminalGroup)만 갈랐다.
결정: 메뉴에 기기를 바로 늘어놓는다 "기기…" 항목 하나를 두고 대화 상자에서 고르게 하는 안도 있었다. 한 번 더 누르게 할 뿐이고 기기는 많아야 몇 대다. 메뉴 안에 두면 목록을 세는 시간도 메뉴가 떠 있는 동안으로 저절로 묶인다(R3). 메뉴가 길어지면 DropdownMenu 가 스스로 스크롤한다.
결정: 웹 페이지처럼 가리지 않는다 기기 화면은 Compose 가 그리는 Image 라서 메뉴·끄는 탭·놓을 자리 미리 보기가 그 위에 그대로 올라간다. 브라우저 탭의 R9(가리는 동안 치우기)는 필요 없다.

한계

  • AVD 의 식별자는 adb 시리얼(emulator-5554)이다. 에뮬레이터를 끄고 다른 것과 함께 다시 켜면 시리얼이 바뀔 수 있고, 그러면 저장된 기기 탭은 "화면을 가져올 수 없습니다." 로 남는다. 닫고 메뉴에서 다시 연다.
  • 같은 기기를 두 탭에 띄우면 JVM 은 스트림 하나를 나눠 쓴다(영상 스트림 R5). 다른 타깃은 탭마다 따로 폴링한다.
  • 보이는 기기 탭마다 기기 목록도 5초마다 센다(EmulatorScreenViewModel 이 이름·능력 플래그를 목록에서 찾는다).
  • 프레임률·지연은 영상 스트림의 한계를 따른다. 디스플레이가 둘인 접이식 기기는 첫 디스플레이만 보인다(JVM).
