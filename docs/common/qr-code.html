QR 코드 만들기

홈의 "QR 코드" 카드를 누르면 텍스트·URL, Wi-Fi, 연락처, 전화, 문자, 이메일을 QR 코드로 바로 만들고, 담긴 문자열을 복사한다. 카드는 마지막으로 만든 코드를 작게 보인다.

사용자 지시

사람들이 많이 접속하는 url이나 appStore, playStore 다운로드 순위 참고해서 구현할 도구들 조사 후 추가해줘.

2026-09-26 대화.
왜 이 기능인가 App Store·Play Store 의 무료 유틸리티 차트 상위권에는 QR 코드 판독·생성 앱(QR Code Reader, QR Scanner, QRCodeSuite 류)이 꾸준히 올라 있고, 웹에서도 QR 생성 페이지(qr-code-generator.com, qrcode-monkey.com)가 방문자가 많은 도구 페이지다. 손님에게 Wi-Fi 를 알려 주거나, 개발 중인 앱의 딥 링크·빌드 URL 을 휴대폰 카메라로 넘기는 일은 Jarvis 사용자가 매일 하는 일이다. 생성은 순수 Kotlin 이라 Android·iOS·macOS·Web 네 곳에서 같은 코드를 낸다.

요구사항

  1. R1. 홈 그리드 맨 끝에 "QR 코드" 카드가 있고, 누르면 QR 코드 화면으로 간다. 화면의 뒤로 버튼은 홈으로 돌아간다. 만들 수 있는 입력이 저장돼 있으면 카드는 그 코드를 작게 그리고 옆에 담긴 문자열을 보인다. 없으면 설명 문구만 보인다.
  2. R2. 화면 위쪽의 칩 여섯 개(텍스트·URL, Wi-Fi, 연락처, 전화, 문자, 이메일)로 종류를 고른다. 고른 칩 하나만 선택 상태이고, 종류마다 입력 칸이 바뀐다.
  3. R3. Wi-Fi: 네트워크 이름, 보안(WPA·WPA2·WPA3 / WEP / 없음), 비밀번호, 숨긴 네트워크 스위치로 WIFI:T:WPA;S:<이름>;P:<비밀번호>;H:true;; 를 만든다. 이름과 비밀번호의 \ ; , : " 앞에는 \ 를 붙인다. 보안이 없음이면 T:nopass 이고 P 를 뺀다. 숨긴 네트워크가 아니면 H 를 뺀다. 이름이 없거나, 보안이 있는데 비밀번호가 없으면 코드 대신 "칸 이름 칸을 채워야 QR 코드가 나타납니다." 를 보인다.
  4. R4. 연락처: 이름·전화번호·이메일 중 채운 것만으로 MECARD MECARD:N:…;TEL:…;EMAIL:…;; 를 만든다. 값은 R3 과 같은 규칙으로 이스케이프하고, 전화번호의 공백은 뺀다.
  5. R5. 전화 tel:<번호>, 문자 SMSTO:<번호>[:<내용>], 이메일 mailto:<주소>[?subject=…&body=…]. 번호의 공백은 빼고, 이메일 제목·본문은 UTF-8 %XX(RFC 3986 비예약 문자만 그대로, 공백은 %20)로 적는다. 내용·제목·본문만 있고 번호·주소가 없으면 R3 과 같은 문구로 빠진 칸을 알린다.
  6. R6. 텍스트·URL 은 친 그대로 담는다. 어느 종류든 칸이 모두 비어 있으면 "내용을 넣으면 QR 코드가 나타납니다." 를 보인다.
  7. R7. 오류 정정 칩 넷(L 7%, M 15%, Q 25%, H 30%)으로 단계를 고른다. 기본은 M 이다. 코드는 그 단계를 그대로 쓰고, 남는 자리가 있어도 단계를 올리지 않는다.
  8. R8. 마지막 종류, 칸마다의 값, 오류 정정 단계가 앱을 껐다 켜도 남는다. Wi-Fi 비밀번호만은 저장하지 않고 앱이 떠 있는 동안만 기억한다(결정).
  9. R9. 코드는 ISO/IEC 18004 QR 코드 모델 2 다. 입력이 전부 숫자면 숫자 모드, 전부 영숫자 45자(0–9 A–Z, 공백, $%*+-./:)면 영숫자 모드, 아니면 UTF-8 바이트 모드로 한 세그먼트에 담는다. 버전은 1–40 중 들어가는 가장 작은 것이고, 여덟 마스크 중 벌점(N1–N4)이 가장 낮은 것을 고른다.
  10. R10. 버전 40 에도 들어가지 않으면 코드 대신 오류 색으로 "QR 코드에 담기에 너무 깁니다. 지금 n바이트, 이 오류 정정 단계의 최대는 m바이트입니다." 를 보인다 (숫자·영숫자 모드면 단위가 "자"). 바이트 모드의 최대는 L 2953, M 2331, Q 1663, H 1273 이다.
  11. R11. 코드는 테마와 상관없이 흰 바탕에 검은 모듈로, 둘레에 4 모듈 이상의 조용한 영역을 두고 그린다. 모듈 한 칸은 1 px 이상이면 정수 픽셀로 맞춘다.
  12. R12. 코드 아래에 버전·크기·오류 정정 단계와 담긴 문자열(선택 가능)을 보이고, "텍스트 복사" 버튼은 그 문자열을 시스템 클립보드에 넣는다.
스코프에서 뺀 것
  • QR 판독(스캔). 차트 상위 앱의 절반은 판독기지만, 카메라 권한과 미리보기·판독 API 가 플랫폼마다 다르다(Android CameraX + ML Kit, iOS AVCaptureMetadataOutput, macOS 는 카메라가 없는 기기도 많고, Web 은 BarcodeDetector 가 Chrome 계열에만 있다). 이 변경은 생성만 하고 판독은 따로 스펙을 세워 뒤따른다. 판독 없이도 휴대폰 기본 카메라가 만든 코드를 읽으므로 생성만으로 쓸모가 있다.
  • 이미지 저장·공유. PNG 로 저장하거나 공유 시트에 넘기려면 Android MediaStore·Intent.ACTION_SEND, iOS UIActivityViewController, macOS 저장 대화상자, Web <a download> 로 네 개의 actual 이 생긴다. 지금은 문자열 복사만 두고, 이미지는 화면을 보여 주거나 스크린숏으로 넘긴다. 뒤따를 일로 남긴다.
  • 여러 모드를 섞는 세그먼트 최적화(예: 숫자 긴 구간만 숫자 모드). 이 앱의 입력은 대부분 소문자가 섞인 URL·Wi-Fi·연락처라 어차피 바이트 모드이고, 얻는 것이 몇 비트다.
  • ECI(UTF-8 지정자). 바이트 모드에 ECI 26 을 붙이면 표준대로 UTF-8 임을 밝히지만, 오래된 판독기 일부는 ECI 를 모르면 통째로 읽지 못한다. iOS·Android 카메라와 ZXing 계열은 ECI 없이도 UTF-8 을 알아보므로 붙이지 않는다.
  • vCard, 일정(BEGIN:VEVENT), 위치(geo:), 색·로고를 넣은 꾸민 코드, Micro QR.

결정: 인코더를 domain 의 순수 Kotlin 으로 직접 짠다 domain 은 kotlinx-coroutines-core·koin-core 만 쓴다(모듈 구조). 플랫폼 생성기(iOS·macOS CIQRCodeGenerator, Android 는 ZXing 을 들여야 함, Web 은 없음)를 쓰면 actual 이 넷이 되고 버전·마스크 선택이 플랫폼마다 달라진다. 구조는 Project Nayuki 의 QR Code generator library(MIT, nayuki.io)를 옮겼다: 세그먼트 → 비트열(종결자·바이트 정렬·0xEC 0x11 채움) → 블록마다 리드–솔로몬(원시 다항식 0x11D) → 짧은 블록·긴 블록 교차 배치 → 지그재그 배치 → 여덟 마스크 벌점 → 형식 정보 BCH(15,5, 0x537, XOR 0x5412)·버전 정보 BCH(18,6, 0x1F25). Nayuki 의 boostEcl(남는 자리에서 단계를 올림)은 사용자가 고른 단계를 그대로 보이려고 뺐다(R7). 벌점의 N4 는 정수로만 계산해 네 타깃이 같은 마스크를 고른다.
결정: 연락처는 vCard 3.0 이 아니라 MECARD 같은 이름·번호·이메일이 MECARD 로는 약 50 바이트, vCard 3.0(BEGIN:VCARD·VERSION:3.0·FN·N·END:VCARD 와 CRLF)으로는 약 100 바이트다. 코드가 한두 버전 작아지면 모듈이 커져 화면을 멀리서도 읽는다. iOS 카메라와 Android 카메라(Google 렌즈)·ZXing 계열이 모두 MECARD 를 연락처로 연다. 이스케이프 규칙이 Wi-Fi 와 같아 QrPayload.escape 하나로 끝난다. vCard 가 필요한 항목(주소·회사·여러 번호)은 입력 칸을 늘릴 때 다시 본다.
결정: Wi-Fi 비밀번호는 저장하지 않는다 SettingsStore 는 평문이다: Android SharedPreferences XML(자동 백업에 실려 클라우드로 간다), iOS NSUserDefaults plist(iCloud·기기 백업), macOS ~/Library/Preferences plist, Web localStorage(같은 출처의 모든 스크립트가 읽는다). 네트워크 이름·보안 방식은 남기고 비밀번호는 앱이 떠 있는 동안만 메모리에 둔다. 앱을 다시 열면 Wi-Fi 종류의 카드는 비밀번호가 빠져 코드를 만들지 않고 설명 문구를 보이며, 화면은 비밀번호 칸을 채우라고 알린다. 키체인·Keystore 에 넣는 길은 actual 넷과 Web 의 대안 부재 때문에 버렸다.
결정: 코드 색은 테마를 따르지 않는 토큰 판독기는 밝은 바탕의 어두운 모듈을 가정하고, 반전(다크 테마의 흰 모듈) 코드를 못 읽는 판독기가 많다. 그래서 다크 테마에서도 검정 #000000 모듈과 흰 #FFFFFF 바탕을 쓴다. ui 에 Color(…) 를 쓰지 않도록 JarvisColors 에 두 테마 공통 토큰 scanCodeDark·scanCodeLight 를 더했다(토큰 표, 터미널 색과 같은 방식). 조용한 영역 4 모듈은 dp 가 아니라 모듈 수라 QrCodeImageDefaults.QuietZoneModules 상수다. 모듈 크기를 정수 픽셀로 내리는 것은, 소수 픽셀 칸 사이에 안티에일리어싱 회색 실선이 생겨 모듈 경계를 흐리지 않게 하려는 것이다.
결정: 입력 칸은 화면이 들고, 저장소는 뒤따라 적는다 개발자 도구와 같다. 칸마다 TextFieldState 를 종류가 바뀔 때 한 번 채우고 스스로 들며, 바뀔 때마다 SetQrFieldUseCase 로 적는다. ViewModel 은 칸마다 마지막으로 받은 값을 저장값 위에 덮어 코드를 만들므로, 저장 신호가 늦게 와도 코드가 입력을 곧바로 따라간다. 복사는 LocalClipboardManager.setText 로, 개발자 도구와 같은 사정이다.

한계

  • 카드의 작은 코드는 미리보기다. 긴 입력(버전 20 이상)은 모듈이 1 px 안팎이라 카드에서는 읽히지 않을 수 있고, 화면의 큰 코드를 써야 한다.

  • Web 은 HTTPS·localhost 가 아니면 복사가 조용히 실패한다(web.html).
