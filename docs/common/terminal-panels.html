터미널 패널과 세션 유지

터미널 화면 왼쪽에 이름 붙인 패널을 세로로 두고, 패널마다 탭과 분할 창을 따로 가진다. 패널·탭·창 배치와 창마다의 작업 디렉터리·Claude sessionId 는 앱을 다시 켜도 그대로이고, Claude 는 화면이나 앱이 꺼져도 백그라운드에서 계속 일한다.

사용자 지시

개념을 분리해서 창을 나누자.

패널이라는 개념을 도입해줘.
- 패널은 좌측에 상하로 노출하고 각 패널에는 이름을 붙일 수 있고 수정할 수 있어.
- 앱 종료 재시작에서도 패널 유지하도록 해줘.

그리고 각 패널에서 탭이 있고 탭을 상하/좌우 분리할 수 있어.
- 각 탭에는 클로드나 터미널이 들어갈 수 있지.
- 이것도 앱 종료/재시작시 유지하도록 해줘.
- claude는 sessionId를 기록해서 이어서 시작하도록 해줘.
- claude는 지침 시킨 것도 bg로 계속 진행해야해 앱을 종료하거나 화면 밖을 나가도 지속적으로 진행하도록 해줘.
- 터미널도 이어서 하면 좋을 것 같아. 이어서 못한다면 디렉토리라도 유지해줘.

앱에서 DB나 properties를 사용해야한다면 Room3나 DataStore androidx를 통해 Multiplatform 구현해줘.

2026-09-24 대화. "창을 나누자" 는 지금까지 한 층이던 탭·분할 위에 패널 층을 하나 더 두는 것으로 읽었다. "탭을 상하/좌우 분리" 는 터미널의 분할(R5·R6)이 패널 안의 탭마다 그대로 되는 것으로 읽었다. "지침 시킨 것도 bg로" 는 Claude 에게 맡긴 작업이 창을 보고 있지 않아도, 앱이 꺼져도 멈추지 않는 것으로 읽었다.

왼쪽 사이드에 새 패널 버튼을 Button으로 해서 backgroundColor가 있는 버튼으로 수정해줘.

2026-09-25 대화. "Button" 은 Material 3 의 Button(filled) 으로 읽었다. 배경 없는 TextButton 이던 "새 패널" 버튼이 primary 배경을 갖는다. 이 지시로 R2 와 아래 표의 "패널 목록" 이 바뀌었다.

뒤따른 버튼을 아래 줄로 지시로 패널 줄의 ✎·✕ 는 이름 옆이 아니라 이름 아래 따로 된 줄에 있다. 아래 그림은 그 전 모양이다.

뒤따른 탭 끌어 놓기 지시로 상단 막대의 동작 버튼이 없어지고 새 탭(+)은 탭 줄 끝으로 갔다. 아래 그림과 R6 의 "새 탭(+) 메뉴" 는 그 자리를 가리킨다. 탭을 끌어 놓아 나누는 규칙은 그 문서에 있다. 다시 뒤따른 분할 그룹 지시로 분할 트리는 탭이 아니라 패널에 붙고 나뉜 칸마다 탭 줄을 가진다. 아래 그림의 탭 줄은 그룹마다 하나씩 있다고 읽는다(그 문서의 그림).

용어

이 지시 전까지 문서와 코드는 분할된 한 칸을 "패널" 이라 불렀다. 지시의 "패널" 과 겹치므로 분할된 한 칸은 이제 창이라 부른다. 코드 이름(PaneNode, TerminalPane)은 영어로 이미 구분되므로 그대로 둔다. 뒤따른 분할 그룹 지시로 나뉜 칸은 그룹이 되고 탭 하나가 창 하나가 됐다. 아래 표는 그 뒤의 뜻이다.

요구사항

패널

  1. R1. 터미널 화면 왼쪽에 패널 목록이 세로로 놓인다. 위에서부터 만든 순서이고 선택된 패널이 강조된다. 패널을 누르면 그 패널이 선택되고, 오른쪽 영역(탭 줄과 창)이 그 패널의 것으로 바뀐다.
  2. R2. 목록 아래의 "새 패널" 버튼은 배경색이 있는 버튼이다. 이 버튼은 이름이 "패널 N"(N 은 지금 패널 수 + 1)이고 터미널 탭 하나를 가진 패널을 목록 끝에 붙이고 선택한다. 뒤따른 새 패널 제목·폴더 지시로 버튼은 제목·폴더를 받는 창을 먼저 띄운다. 그 뒤 빈 패널 지시로 창의 "확인" 은 탭 없는 패널을 만든다 — 이 문장의 "터미널 탭 하나" 는 빈 패널의 새 탭(+)으로 연다.
  3. R3. 패널 줄의 "이름 바꾸기" 아이콘을 누르면 이름이 입력 필드로 바뀌고 포커스를 받는다. Enter 나 포커스를 잃으면 확정되고 Esc 는 취소한다. 앞뒤 공백을 떼고, 비어 있으면 이전 이름을 그대로 둔다.
  4. R4. 패널 줄의 "패널 닫기" 아이콘은 그 패널을 목록에서 지우고 그 안의 창을 전부 닫는다(R12). 패널이 하나뿐이면 닫기 아이콘이 없다. 선택된 패널을 닫으면 그 자리에 오는 패널(없으면 앞 패널)이 선택된다.

탭과 창

  1. R5. 탭 추가·분할·닫기·포커스·탭 선택은 선택된 패널의 그룹 안에서 터미널 R5–R12 와 분할 그룹 R1–R11 대로 동작한다. 단축키도 선택된 패널의 포커스된 그룹에 작용한다. 탭은 만든 패널에 속하고 다른 패널로 옮기지 않는다.
  2. R6. 탭마다 내용은 터미널(셸) 또는 Claude 다. 새 탭은 그룹의 새 탭(+) 메뉴에서 고르고(Claude 실행 R1), 분할로 생긴 그룹의 탭은 터미널이다. 탭을 끌어 놓아 나누면 끌어온 탭이 새 그룹의 탭이 된다(분할 그룹 R7).
  3. R7. 패널의 마지막 그룹이 사라져도 패널은 남는다. 탭 자리에 + 버튼과 "탭이 없습니다. 새 탭(+)으로 터미널이나 Claude 를 엽니다." 가 보인다. 화면은 홈으로 돌아가지 않는다.
  4. R8. 새 탭과 분할로 생긴 탭은 그 그룹에서 선택돼 있던 탭의 작업 디렉터리에서 시작한다. 알 수 없으면 패널의 폴더(새 패널 제목·폴더 R8), 그것도 없으면 홈 디렉터리다.

저장과 복원

  1. R9. 다음을 바뀔 때마다 저장하고, 앱을 끝냈다 다시 켜면 그대로 복원한다: 패널 목록(이름·폴더·순서·선택), 패널마다 탭 목록과 선택된 탭, 탭마다 분할 트리(방향·비율)와 포커스된 창, 창마다 내용 종류·작업 디렉터리·Claude sessionId·Claude 결과를 확인한 기록(Claude 상태 표시 R6). 처음 켤 때는 "패널 1" 하나에 터미널 탭 하나다.
  2. R10. 분할 경계선을 끄는 동안의 비율은 화면에서만 바뀌고, 손을 뗄 때 한 번 저장한다.

세션 유지

  1. R11. Claude 창은 만들 때 sessionId(UUID)를 정해 저장한다. Claude 는 앱 밖의 Claude Code 백그라운드 세션으로 돌고, 창은 그 세션에 붙어 보여 줄 뿐이다. 다른 탭·패널로 가도, 터미널 화면을 벗어나도, 앱을 끝내도 세션은 맡은 일을 계속한다. 창이 다시 보이면 같은 세션에 다시 붙는다. 세션이 멈춰 있으면(재부팅 등) 같은 sessionId 로 다시 띄워 대화를 이어 간다.
  2. R12. 사용자가 Claude 창을 닫으면(창 닫기·탭 닫기·패널 닫기) 그 백그라운드 세션을 멈춘다. 대화 기록은 지우지 않는다.
  3. R13. 터미널 창의 셸은 앱이 켜져 있는 동안 창이 보이지 않아도(다른 탭·패널, 터미널 화면 밖) 살아 있다. 다시 보이면 화면과 스크롤백이 그대로다.
  4. R14. 앱을 끝내면 셸은 끝난다. 다시 켜면 그 창은 저장된 작업 디렉터리에서 새 셸로 시작한다. 이전 출력과 실행 중이던 명령은 이어지지 않는다.
  5. R15. 셸의 작업 디렉터리는 셸 출력이 잠시 멎을 때(명령이 끝나고 프롬프트가 다시 그려질 때)마다 다시 읽어 바뀌었으면 저장한다.
  6. R16. 셸이 스스로 끝나면(exit) 그 창이 닫힌다. 창이 보이지 않을 때도 그렇다.
스코프에서 뺀 것
  • 패널 순서 바꾸기, 탭을 다른 패널로 옮기기, 패널 단축키. 지시에 없다.
  • 앱을 다시 켠 뒤 셸 프로세스와 출력까지 이어 가기. 셸이 앱보다 오래 살려면 앱 밖에서 pty 를 붙잡는 프로세스(tmux 등)가 있어야 한다. macOS 에 기본으로 없고 앱이 설치할 수 없어서, 지시의 대안("디렉토리라도 유지")으로 간다(JVM).
  • 스크롤백·화면 내용 저장. 셸이 이어지지 않으므로 옛 화면만 보여 주면 지금 셸과 맞지 않는다.
  • Claude 대화 기록 지우기. 닫을 때 세션을 멈출 뿐이다(R12).

TerminalScreen 에 TerminalPanelList·TerminalPanelItem(패널 목록), EmptyPanel. 창 선택·이름 편집 여부는 화면 안의 remember
결정: 저장은 DataStore 에 한 문서로 한다 (Room3 은 버렸다) 지시는 Room3 이나 DataStore 를 허락했다. 둘 다 다섯 타깃을 퍼블리시한다(androidx.datastore:datastore-core-okio 1.2.1, androidx.room3:room3-runtime 3.0.3 의 Gradle 모듈 메타데이터로 확인). 저장할 것은 패널 → 탭 → 분할 트리라는 나무 하나이고, 늘 통째로 읽어 통째로 그린다. 부분 조회가 없다. 작업 공간 규칙은 이미 불변 값을 받아 새 값을 돌려주는 함수라 DataStore.updateData { transform(it) } 에 그대로 들어가고, 한 번의 변경이 원자적으로 쓰인다.
Room3 은 나무를 부모 id 가 달린 행으로 펼쳐야 해서 분할·닫기마다 여러 행을 고치는 트랜잭션과, 읽을 때 다시 나무로 엮는 코드가 생긴다. KSP 와 스키마 마이그레이션 관리도 더해진다. 얻는 것(질의, 인덱스)이 이 기능에는 쓸 데가 없어 버렸다.
형식은 kotlinx.serialization JSON 이다. DTO(TerminalWorkspaceDto)를 data 에 따로 두어 도메인 모델 이름이 바뀌어도 파일 형식이 흔들리지 않게 한다. 모르는 키는 무시하고 없는 키는 기본값을 쓴다. 파일이 깨졌으면 초기값으로 되돌린다(ReplaceFileCorruptionHandler).
결정: Claude 는 Claude Code 의 백그라운드 세션으로 돌리고 창은 claude attach 로 붙는다 R11 은 앱이 꺼져도 Claude 가 일을 계속하라고 한다. 앱이 띄운 프로세스는 앱과 함께 끝나므로 앱 밖의 무언가가 Claude 를 붙잡고 있어야 한다. Claude Code 2.1.281 에는 그 일을 하는 백그라운드 세션이 있다: claude --bg 가 세션을 자기 서비스에 맡기고 곧바로 돌아오고, claude attach <id> 가 그 세션을 지금 터미널에 그린다. 붙어 있던 attach 를 죽여도 세션은 계속되고, 멈춘 세션(claude stop, 재부팅)에 attach 하면 다시 띄운다. 2026-09-24 에 직접 확인했다(JVM).
창의 sessionId 는 앱이 정한다. 창을 만들 때 uuid 를 정해 저장하고(R9), 창을 열 때마다 "그 sessionId 에 묶인 백그라운드 세션이 있으면 붙고, 없으면 만든 뒤 묶고 붙는다". --bg 는 --session-id 를 무시하고, 처음 보는 uuid 를 --bg --resume 에 주는 방법은 Claude Code 2.1.281 에서 세션이 곧 죽는다(jvm.html). 그래서 실제 sessionId 는 Claude 가 정하게 두고 세션 이름으로 창 sessionId 와 잇는다. 도메인의 claudeSessionId 는 "Claude 세션을 찾는 열쇠" 로 뜻이 넓어질 뿐 모양은 그대로다 — 실제 sessionId 를 받아 저장소에 되돌려 쓰는 안은 열기 결과가 도메인까지 올라와 워크스페이스를 고쳐야 해서 버렸다.
버린 후보: (1) tmux 안에서 claude 를 돌리기 — macOS 에 기본으로 없다. (2) 앱이 Claude 를 직접 띄우고 다음에 claude --resume — 대화는 이어지지만 앱이 꺼져 있는 동안 일이 멈춘다. R11 의 "앱을 종료하거나" 를 어긴다. 백그라운드 세션을 만들 수 없을 때(작업 디렉터리를 신뢰하지 않았을 때 등)의 대체 동작으로만 남긴다.
결정: 창의 세션과 에뮬레이터는 ViewModel 이 아니라 앱 수명의 TerminalPaneHost 가 든다 R13 은 터미널 화면을 벗어나도 셸이 살아 있고 돌아오면 화면이 그대로이길 요구한다. 화면을 벗어나면 ViewModel 이 치워지므로, 세션을 ViewModel 이 들면 셸을 끝내거나(이전 동작) 출력을 버려야 한다. 출력을 바이트로 모아 두었다가 돌아올 때 새 에뮬레이터에 다시 흘리는 방법도 봤지만, 잘린 앞부분에 걸친 제어 시퀀스와 전체 화면 프로그램(Claude 의 TUI)의 화면이 복원되지 않아 버렸다. 에뮬레이터를 통째로 살려 두면 스크롤백까지 그대로다.
이것은 상태 조회 R12·R13 이 막는 "구독과 무관하게 붙잡는 상태" 가 아니라 사용자가 띄운 프로세스라는 자원이다. 사용자가 창을 닫거나 셸이 끝날 때 풀린다. 그래도 앱 수명 스코프이므로 그 문서의 수집 표에 한 줄을 더한다.
창은 처음 보일 때 연다. 앱을 켜자마자 모든 패널의 창을 띄우면 Claude 창마다 백그라운드 세션 조회와 로그인 셸이 한꺼번에 돈다. 보이지 않은 셸은 아직 할 일이 없고, 보이지 않은 Claude 는 앱 밖에서 이미 일하고 있다(R11).
결정: 작업 디렉터리는 셸 출력이 멎을 때 읽는다 (폴링하지 않는다) 셸의 작업 디렉터리가 바뀌었다는 콜백은 운영체제에 없다. 셸이 알려 주게 하는 OSC 7 은 zsh 가 기본으로 내지 않고(macOS 의 /etc/zshrc_Apple_Terminal 은 Terminal.app 에서만 켠다), 사용자 셸 설정에 훅을 끼워 넣어야 한다. 대신 디렉터리는 명령을 친 뒤에만 바뀌고, 명령이 끝나면 셸이 프롬프트를 그린다는 점을 신호로 쓴다. 출력이 DirectoryReadDelay 동안 멎으면 셸 프로세스의 작업 디렉터리를 운영체제에 한 번 묻는다. 출력이 없는 동안에는 아무것도 하지 않는다. 묻는 방법은 플랫폼 스펙에 있다.

한계

  • 셸은 앱이 끝나면 끝난다(R14). 오래 도는 명령은 nohup·tmux 로 돌려야 한다. Claude 창은 그렇지 않다.
  • Claude 창 안에서 Claude 가 끝나면(/exit) 그 창은 셸이 된다. 앱을 다시 켜거나 창이 다시 열리면 같은 sessionId 에 다시 붙어 Claude 가 다시 뜬다 — 창의 내용 종류는 만들 때 정해진다.
  • 닫은 Claude 창의 세션은 멈춘 채 claude agents --all 목록에 남는다(R12). 지우려면 claude rm 을 직접 친다.
  • 작업 디렉터리는 출력이 멎을 때 읽으므로, 출력 없이 디렉터리를 바꾸고 곧바로 앱을 끝내면 이전 디렉터리가 저장된다.
  • 여러 창에서 같은 파일에 쓰지 않는다. 데스크톱 앱을 두 개 띄우면 마지막에 쓴 쪽이 남는다.
