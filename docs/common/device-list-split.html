기기 목록 좌우 분할

기기 목록 화면을 좌우 두 열로 나눠 왼쪽에 Android 기기, 오른쪽에 iOS 기기를 둔다. 한 줄씩 섞여 있던 목록에서 플랫폼을 글자로 읽어 가려내지 않아도 된다.

사용자 지시

deviceList에서 2등분해서 좌우 분리 후 android/ios 구분해줘.

2026-09-24 대화.

요구사항

  1. R1. 기기 목록 화면의 본문을 가로로 같은 너비 두 열로 나눈다. 창 너비와 무관하게 항상 두 열이다.
  2. R2. 왼쪽 열에는 EmulatorPlatform.ANDROID 기기만, 오른쪽 열에는 EmulatorPlatform.IOS 기기만 나온다. 가상 기기와 실물 기기는 같은 열 안에 섞인다. 열 안의 순서는 받은 목록의 순서를 그대로 따른다.
  3. R3. 각 열 맨 위에 "Android" / "iOS" 머리글이 붙는다. 열이 플랫폼을 말하므로 항목 보조 문구 맨 앞의 플랫폼 이름(Android ·, iOS ·)은 뺀다.
  4. R4. 두 열은 따로 스크롤한다. 한쪽 기기가 많아도 다른 쪽 목록이 밀려 내려가지 않는다.
  5. R5. 한쪽 열만 비면 그 열의 머리글 아래에 "Android 기기가 없습니다." / "iOS 기기가 없습니다." 를 적는다. 두 열 모두 비면 지금처럼 열을 나누지 않고 "연결된 기기가 없거나 개발자 머신에 물어볼 수 없습니다." 한 줄만 보인다.
  6. R6. 항목 하나의 모양과 동작(누르기, 실행, 화면 켜기, 비활성 규칙, 테스트 태그)은 바뀌지 않는다. 상단 바와 Wi-Fi 페어링 버튼도 그대로다.
스코프에서 뺀 것 좁은 창에서 한 열로 접는 반응형 배치는 하지 않는다. 지시가 "2등분"이라 폰 세로 화면에서도 두 열이다. 열 머리글에 개수를 붙이는 것도 하지 않는다. 개수는 홈 카드가 이미 보여준다.

결정: 열마다 LazyColumn
  • 채택. Row 안에 LazyColumn 두 개. 열이 따로 스크롤해서(R4) 한쪽이 길어도 다른 쪽이 화면 밖으로 밀리지 않는다.

  • 분류를 ViewModel 로 옮긴다. 화면 배치 하나 때문에 상태 모양과 기존 테스트(EmulatorDevicesViewModelTest, launchingDevices 계산)를 바꿔야 한다. 목록은 많아야 수십 개라 화면에서 나눠도 비용이 없다. 버렸다.

한계

  • 폰 세로 화면(약 360dp)에서는 열 하나가 170dp 안팎이다. 실행·화면 켜기 버튼이 붙은 항목은 이름이 두세 줄로 접힌다. 지시가 항상 2등분이라 받아들인다.
  • 너비가 같다는 것과 따로 스크롤된다는 것은 좌표·스크롤 위치의 성질이라 자동 테스트로 가리지 않는다(홈 그리드와 같은 이유).
