터미널 출력의 링크 열기

셸·Claude 탭의 출력에 찍힌 웹 주소를 마우스로 누르면 시스템 브라우저와 Jarvis 앱 안 브라우저 중 어디에서 열지 고르는 메뉴가 뜬다. Jarvis 브라우저를 고르면 그 그룹에 브라우저 탭이 그 주소로 열린다.

사용자 지시

claude에서 제공하는 링크를 클릭해서 열 수 있도록 해줘. 클릭시 System Browser로 열지, Jarvis inapp browser로 열지 선택할 수 있어야해.

2026-09-25 대화. "claude에서 제공하는 링크" 는 Claude 탭의 창에 Claude Code 가 출력한 웹 주소(로그인 주소, 문서 주소, PR 주소 등)로 읽었다. Claude 의 출력은 셸 출력과 같은 경로로 에뮬레이터에 들어오므로 셸 탭의 출력에 찍힌 주소도 같이 링크가 된다. "System Browser" 는 운영체제의 기본 브라우저(앱 밖), "Jarvis inapp browser" 는 터미널에서 웹 브라우저의 브라우저 탭으로, "클릭시 … 선택" 은 누를 때마다 메뉴로 고르는 것으로 읽었다(설정으로 한 번 정해 두는 것이 아니다).

요구사항

  1. R1. 셸·Claude 탭의 창에서 다음이 링크다. (a) 프로그램이 OSC 8(ESC ] 8 ; params ; URI ST)로 감싼 글자 — 주소는 URI 그대로다. (b) 출력 본문에서 http:// 또는 https:// 로 시작하는 글자 묶음 — 공백·제어 문자·< > " ' `·전각 글자가 나오기 전까지가 주소다. 끝에 붙은 . , ; : ! ? 와 여는 짝이 없는 ) ] } 는 주소에서 뺀다(문장 끝의 마침표, 괄호 안의 주소를 위해서다).
  2. R2. 본문 주소는 자동 줄바꿈(창 너비에 닿아 에뮬레이터가 다음 줄로 이은 것)을 넘어 이어진다. 프로그램이 스스로 줄을 끊어 쓴 주소(Claude Code 는 긴 줄을 창 너비에서 끊어 쓴다)도, 주소가 그 줄의 마지막 칸까지 닿고 다음 줄이 앞의 빈칸 뒤에 주소 글자로 이어지면 한 주소로 본다. 스크롤백으로 올라간 줄도 같다.
  3. R3. 마우스를 링크 위에 올리면 그 링크의 글자 전체(여러 줄에 걸치면 전부)에 밑줄이 생기고 커서가 손 모양이 된다. 링크를 벗어나면 돌아온다. 마우스가 없는 타깃(터치)에는 이 표시가 없다.
  4. R4. 링크를 누르면(수정 키 없는 왼쪽 버튼 한 번, 터치 한 번) 누른 자리에 메뉴가 뜬다. 맨 위 줄에 열 주소가 보이고, 항목은 위에서부터 "시스템 브라우저에서 열기", "Jarvis 브라우저에서 열기" 다. 메뉴 바깥을 누르면 아무것도 열지 않고 닫힌다. 링크가 아닌 곳을 누르면 예전처럼 창에 포커스만 간다.
  5. R5. "시스템 브라우저에서 열기" 는 운영체제의 기본 브라우저(앱 밖)로 주소를 연다. 창은 그대로다.
  6. R6. "Jarvis 브라우저에서 열기" 는 그 창이 속한 그룹의 탭 줄 끝에 브라우저 탭을 그 주소로 붙이고 선택한다(웹 브라우저 R2 와 같은 자리·선택 규칙, 첫 페이지만 다르다). 이 탭은 다른 브라우저 탭과 같다 — 주소가 저장되고 앱을 다시 켜면 그 주소로 열린다.
  7. R7. 브라우저 탭을 띄울 수 없는 타깃(웹 브라우저 R8)에서는 "Jarvis 브라우저에서 열기" 가 없다. 남은 항목이 하나뿐이면 메뉴를 띄우지 않고 누르는 즉시 시스템 브라우저로 연다(항목 하나뿐인 메뉴는 한 번 더 누르게 할 뿐이다, Claude R6).
  8. R8. 링크는 화면의 글자를 바꾸지 않는다. OSC 8 시퀀스 자체는 화면에 찍히지 않고, 본문 주소는 찍힌 그대로다. 밑줄은 마우스가 위에 있을 때만 그린다 — 프로그램이 SGR 4 로 그은 밑줄은 그대로다.
스코프에서 뺀 것
  • 파일 경로(/Users/…, file://), mailto:, ftp://, 스킴 없는 www.example.com. 지시가 "링크" 이고 Claude Code 가 내는 링크는 https:// 다. 파일 경로는 사이드 바의 파일 탭이 따로 있다.
  • ⌘·Ctrl 을 누른 채 눌러야 열리는 것(iTerm 방식). 일반 클릭과 겹치는 동작이 포커스뿐이다. 뒤에 더한 끌어 선택은 슬롭을 넘게 끌어야 시작돼 클릭과 겹치지 않는다.
  • 고른 것을 기억해 다음부터 묻지 않는 설정. 지시가 누를 때 고르는 것이다.
  • "주소 복사" 항목. 처음에는 글자 선택·복사 자체가 터미널 스코프 밖이었고, 뒤에 더한 끌어 선택으로 주소를 끌어 놓으면 복사된다.
  • 오른쪽 클릭 메뉴. 터치에서 안 된다.
  • 브라우저·파일·기기 탭 안의 링크. 브라우저 탭은 페이지가 스스로 처리하고, 파일 탭은 읽기 전용 뷰어다.

공통 구현

도메인 — 격자
TerminalLine.linkAt(column): String? — OSC 8 의 URI. 결합 문자와 같이 칸 번호를 키로 드문드문 보관하고(links: MutableMap<Int, String>?), 칸을 지우거나 밀거나 자를 때 결합 문자와 같이 옮긴다. 전각 글자는 두 칸 모두 같은 URI 다.
TerminalEmulator — OSC 8;<params>;<URI> 를 받아 URI 가 비어 있지 않으면 그때부터 찍는 글자에 붙이고, 비어 있으면 붙이기를 끝낸다. params(id=…)는 버린다. ESC c(초기화)는 붙이기도 끝낸다. 시퀀스는 화면에 찍히지 않는다(R8). 해석 범위의 OSC 줄에 8 을 더한다.
도메인 — 감지
TerminalLink.kt:
class TerminalLink(val url: String, val cells: List<TerminalCell>), data class TerminalCell(val row: Int, val column: Int) — row 는 TerminalEmulator.line(index) 의 번호(음수는 스크롤백).
fun findUrls(text: String): List<IntRange> — R1(b) 의 순수 규칙. 글자열 안의 주소 구간.
fun TerminalEmulator.linkAt(row: Int, column: Int): TerminalLink? — 그 칸의 OSC 8 링크가 있으면 같은 URI 가 이어진 칸 묶음(R1a). 없으면 그 줄을 앞뒤로 R2 대로 이은 글자열에서 findUrls 로 찾아 칸으로 되돌린다. 전각 글자의 둘째 칸과 빈칸은 글자열에서 한 글자(빈칸은 공백)로 세어 글자열 위치와 칸이 1:1 이다.
상태
TerminalViewModel.addBrowserTab(groupId, url = TerminalTab.DefaultBrowserUrl) — 주소를 받는다(R6). 메뉴가 열렸는지와 마우스가 올라간 링크는 창 안에서만 쓰는 값이라 remember 로 둔다
UI
TerminalPane(…, onOpenInJarvis: ((String) -> Unit)?) — null 이면 Jarvis 항목이 없다(R7). TerminalGroup 이 { viewModel.addBrowserTab(group.id, it) }.takeIf { viewModel.isBrowserSupported } 로 넘긴다.
마우스 움직임(pointerInput 의 Move·Exit)마다 누른 점을 칸(x / cellWidth, y / cellHeight - scrollOffset)으로 바꿔 emulator.linkAt 을 묻고 hoveredLink 에 둔다. Canvas 가 그 칸들 아래에 밑줄을 긋고, Modifier.pointerHoverIcon 이 손 커서를 보인다(R3).
detectTapGestures 의 탭에서 같은 계산으로 링크를 찾아 있으면 linkMenu = (link, offset) 으로 메뉴를 띄우고, 없으면 예전처럼 포커스를 옮긴다(R4).
시스템 브라우저는 Compose 의 LocalUriHandler.current.openUri(url) 로 연다(R5). 플랫폼마다 어떤 API 를 부르는지는 플랫폼 문서에 있다.
결정: 시스템 브라우저는 expect 를 만들지 않고 Compose 의 UriHandler 로 연다 LocalUriHandler 는 네 타깃 모두에 있고(JVM Desktop.browse, Android ACTION_VIEW, iOS UIApplication.openURL, Web window.open), 이 프로젝트는 Compose 가 플랫폼 API 를 대신 불러 주면 expect 를 두지 않는다(공통 규약의 keepScreenAwake 예외와 같다). 테스트에서는 CompositionLocalProvider 로 기록하는 핸들러를 넣어 실제 브라우저가 뜨지 않게 한다. 버린 후보: data 모듈에 OpenUrlDataSource expect — 같은 일을 네 번 다시 짜는 것이다.
결정: 본문 주소는 격자를 그릴 때가 아니라 마우스가 닿은 칸에서만 찾는다 매 프레임 모든 줄에서 주소를 찾아 두면 출력이 빠를 때(cat 큰 파일) 해석에 더해 검색까지 프레임을 먹는다. 마우스가 움직이거나 누를 때 그 줄(과 이어진 줄)만 보면 한 번에 몇백 글자다. 대가는 링크가 항상 밑줄로 보이지 않는 것인데, R3 이 마우스를 올렸을 때만 밑줄을 긋기로 했으므로 맞는다. OSC 8 은 프로그램이 이미 칸에 붙여 놓아 찾을 것이 없다.
결정: 프로그램이 끊어 쓴 주소는 "마지막 칸까지 닿았을 때만" 잇는다(R2) Claude Code(ink)는 긴 글자 묶음을 창 너비에서 강제로 끊고 다음 줄을 들여쓴다. 이때 에뮬레이터의 자동 줄바꿈이 아니라 프로그램의 줄바꿈이라 wrapped 가 서지 않는다. 자동 줄바꿈만 이으면 Claude 의 로그인 주소(200자 넘는다)가 첫 줄까지만 링크가 되어 쓸 수 없다. 그래서 주소가 줄의 마지막 칸에 닿았고 다음 줄이 (들여쓰기 빈칸 뒤) 주소 글자로 시작하면 잇는다. 마지막 칸에 정확히 닿는 일반 문장은 드물어서 잘못 잇는 일은 적지만 있을 수 있다(한계). 버린 후보: 다음 줄이 무엇이든 무조건 잇기 — 문장의 다음 줄까지 주소가 된다. 잇지 않기 — Claude 의 주소가 쓸 수 없다.
결정: 메뉴 위에 열 주소를 보인다 OSC 8 은 보이는 글자와 여는 주소가 다를 수 있다(내 PR 이라는 글자가 https://… 를 연다). 본문 주소도 끊긴 줄을 이은 결과가 눈에 보이는 것과 다를 수 있다. 무엇을 열지 누르기 전에 보여야 한다.

플랫폼판정어떻게문서
Android구현 미검증공통 코드. 시스템 브라우저는 AndroidUriHandler 의 ACTION_VIEW, Jarvis 브라우저는 시스템 웹뷰 탭. 호버가 없어 밑줄·손 커서는 보이지 않는다android.html

자동으로 확인하지 못하는 것: 밑줄과 손 커서(R3, 테스트 화면의 호버 이벤트가 Canvas 그리기까지 닿는지 확인할 수단이 없다), Jarvis 항목이 실제로 브라우저 탭을 여는 것(R6, 위의 이유), 실제 기본 브라우저가 뜨는지, 실제 Claude Code 가 끊어 쓴 주소가 한 링크로 잡히는지. ./gradlew :desktopApp:run 에서 손으로 확인한다.

한계

  • R2 의 잇기는 어림이다. 마지막 칸에 정확히 닿은 주소 뒤에 오는 문장의 첫 낱말이 주소에 붙을 수 있고, 프로그램이 주소를 마지막 칸 앞에서 끊었으면(오른쪽 여백을 둔 상자) 첫 줄까지만 링크다. 메뉴의 주소 줄로 무엇이 열릴지 보고 누른다.
  • 주소 안의 전각 글자(한글 경로 등)는 주소를 끝낸다. 퍼센트 인코딩된 주소는 문제없다.
  • 대체 화면(vim·less)에서도 링크가 잡힌다. 그 프로그램이 마우스로 무엇을 하는지와 무관하다 — 이 에뮬레이터는 마우스 보고(DECSET 1000 계열)를 켜도 휠만 보내고 누르기는 창이 받는다(휠 스크롤 R8).
  • Android 는 호버가 없어 어디가 링크인지 누르기 전에는 알 수 없다. 눌러서 메뉴가 뜨면 링크다.
  • 터미널의 한계와 웹 브라우저의 한계가 그대로 든다.
