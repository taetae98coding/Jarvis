파일 탭에 git diff 표시

사이드 바의 "파일"·"Git" 구획에서 연 파일 탭이, 파일 내용 안에 HEAD 대비 바뀐 줄을 겹쳐 보인다. 더한 줄은 초록 바탕에 +, 지운 줄은 그 자리에 빨간 바탕의 − 줄로 끼워 넣고, 위에 "HEAD 대비 +n −m" 을 붙인다.

사용자 지시

git이나 fileDirectory에서 파일 열어서 볼 때 diff도 보였으면 좋겠어.

2026-09-25 대화.

용어

파일 탭
사이드 바 R9·R17 로 여는 읽기 전용 탭(TerminalProgram.File). 지시의 "fileDirectory" 는 "파일" 구획, "git" 은 "Git" 구획이다
diff
파일의 HEAD 커밋 내용과 지금 디스크(작업 트리) 내용의 차이. stage 여부와 무관하게 커밋 뒤에 바뀐 것 전부다
더한 줄
지금 파일에 있고 HEAD 에 없는 줄. 바꾼 줄은 지운 줄 + 더한 줄이다
지운 줄
HEAD 에 있고 지금 파일에 없는 줄

요구사항

  1. D1. 파일 탭의 파일이 git 작업 트리 안에 있고 HEAD 와 다르면, 파일 내용의 줄마다 더한 줄은 successContainer 바탕에 표시 칸 "+", 지운 줄은 원래 있던 자리(그 뒤에 오는 지금 파일의 줄 바로 앞)에 errorContainer 바탕에 표시 칸 "−" 로 끼워 보인다. 지운 줄은 줄 번호 칸이 비어 있고, 나머지 줄 번호는 지금 파일 기준 그대로다. 바뀌지 않은 줄은 표시 칸이 비어 있다.
  2. D2. 바뀐 줄이 하나라도 있으면 내용 위에 "HEAD 대비 +n −m" 이 붙는다. n 은 더한 줄 수, m 은 지운 줄 수다.
  3. D3. 추적하지 않는 파일(.gitignore 로 빠진 것 제외)은 모든 줄이 더한 줄이다. 커밋이 하나도 없는 저장소에서는 무시되지 않는 모든 파일이 그렇다.
  4. D4. HEAD 에 있고 디스크에서 지워진 파일은 "파일을 읽을 수 없습니다" 대신 HEAD 의 모든 줄을 지운 줄로 보이고 D2 의 요약을 붙인다.
  5. D5. 저장소 밖이거나, 무시된 파일이거나, HEAD 와 같거나, git 을 쓸 수 없는 플랫폼이면 파일 탭은 diff 이전(사이드 바 R11)과 똑같다. 텍스트가 아닌 파일은 diff 가 있어도 R11 의 문구 그대로다.
  6. D6. diff 는 파일 탭이 보이는 동안만 읽고, 셸에서 파일을 고치거나 커밋하면 플랫폼 스펙의 간격 안에 따라간다. 파일 내용(R13)과 diff 는 따로 따라가므로 두 간격 사이에는 잠깐 어긋날 수 있다.
  7. D7. 파일이 FileViewerMaxBytes 보다 커서 앞부분만 보일 때는 보이는 줄 범위의 표시만 붙이고, 그 뒤의 지운 줄은 보이지 않는다. 요약(D2)은 파일 전체 기준이다.
  8. D8. 글자 고르기·복사(R11)는 줄 번호·표시 칸을 뺀 내용만 고른다. 지운 줄의 글자도 고를 수 있다.
스코프에서 뺀 것 diff 끄기·켜기 버튼, 좌우 나란히 보기, index(스테이지된 쪽)만 따로 보기, 다른 커밋·브랜치와 비교, 줄 단위 stage, 단어 단위 강조. 지시는 "diff 도 보였으면" 이라 내용 보기에 겹치는 한 가지로 둔다. 스테이지된 것만 보려면 셸에서 git diff --cached 한다.

바탕더한 줄 JarvisTheme.colors.successContainer, 지운 줄 JarvisTheme.colorScheme.errorContainer. 줄 전체 폭(보이는 영역 폭 이상)을 칠한다
요약"HEAD 대비 +n −m", labelMedium onSurfaceVariant. 512 KiB 문구(R11)가 있으면 그 아래

공통 구현

domain
GitDiffHunk(oldStart, oldCount, newStart, newCount, removed), GitFileDiff(hunks)(added·removed 합계), GitChangesRepository.observeFileDiff(path): Flow<GitFileDiff?>(null 은 저장소 밖·git 없음, 같거나 무시된 파일은 빈 hunks), 유스케이스 ObserveGitFileDiffUseCase. 줄 만들기는 순수 함수 diffedLines(lines, diff): List<DiffedLine>(Current(number, text, added) / Removed(oldNumber, text)) — 지금 파일의 줄에 더한 줄 표시를 붙이고, 덩어리마다 지운 줄을 끼운다. newCount 가 0 이면 지운 줄은 지금 파일의 newStart 번째 줄 뒤, 아니면 newStart 번째 줄 앞이다. 보이는 줄 범위 밖의 표시는 버린다(D7)
data
GitDataSource.observeFileDiff. 해석은 공통 함수 parseGitDiff(-U0 출력의 @@ -a,b +c,d @@ 머리와 - 줄). JVM 은 사이드 바 Git 구획과 같은 신호(폴링 + stage·unstage 신호)로 다시 읽는다
UI
TerminalFileViewer(tab, content, diff, onFocus) 가 diffedLines 를 그린다. 지운 파일(D4)은 빈 줄 목록에 diff 를 겹친 것이다. TerminalViewModel.fileDiff(path) 가 fileContent(path) 와 같이 경로마다 stateIn(viewModelScope, WhileSubscribed(replayExpirationMillis = 0), null) 로 내놓는다
결정: 파일 내용 위에 -U0 덩어리를 겹친다. git diff -U<아주 큰 수> 로 파일 전체를 diff 출력으로 받아 그것만 그리는 방법을 버렸다. 파일 탭의 내용 읽기(512 KiB 자르기, 바이너리 판정, 디스크 변경 따라가기)를 git 출력으로 한 번 더 만들어야 하고, git 이 없는 플랫폼에서는 내용 보기와 갈라진다. -U0 는 바뀐 줄만 오므로 출력이 작고, 더한 줄은 번호만 쓰면 되며 지운 줄의 글자만 받으면 된다.
결정: 비교 대상은 HEAD 다. 작업 트리 대 index(git diff)만 보이면 stage 한 순간 표시가 사라져, "Git" 구획의 "스테이지된 변경" 에서 연 파일에 아무것도 보이지 않는다. HEAD 대비면 어느 목록에서 열어도 커밋할 것 전체가 보인다. stage·unstage 가 표시를 바꾸지 않는 것도 같은 이유다.
결정: 한 화면에 겹쳐 보이고 끄는 버튼을 두지 않는다. "내용 / Diff" 전환이나 좌우 보기는 탭마다 상태가 늘고, 바뀐 것이 없는 파일에서는 둘이 같다. 바뀌지 않은 파일은 표시가 없어 예전과 같으므로(D5) 겹쳐도 방해가 되지 않는다.

한계

  • 파일 경로가 심볼릭 링크를 지나 저장소 밖을 가리키면 git 이 경로를 저장소 밖으로 보아 diff 가 없다(D5).
  • 파일이 든 폴더째 지웠으면 남아 있는 가장 가까운 위 폴더에서 git 을 불러 D4 대로 보인다. 저장소 폴더까지 지웠으면 diff 가 없다.
  • 이름 바꾼 파일은 새 경로의 diff 만 본다. git diff 는 경로를 하나 주면 이름 바꿈을 찾지 않아, stage 한 이름 바꿈도 추적하는 새 파일처럼 모든 줄이 더한 줄이 될 수 있다.
  • 줄 끝(CRLF)·core.autocrlf 로 바뀐 줄은 글자가 같아 보여도 더한·지운 줄로 나온다.
  • UTF-8 이 아닌 파일은 지운 줄 글자가 깨진다(R11 과 같다).
