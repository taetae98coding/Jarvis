파일 탭 줄 코멘트를 Claude 에 보내기

파일 탭(diff 가 겹친 것 포함)에서 줄 번호를 눌러 그 줄에 코멘트를 남기고, 패널에 모인 코멘트를 "Claude 에 보내기" 한 번으로 그 패널의 Claude 탭에 한 메시지로 보낸다.

사용자 지시

터미널 화면 git diff와 fileDirectory에서 라인넘버를 선택해서 comment를 남기고 claude에게 보낼 수 있는 기능 추가해줘. 한번에 보낼 수 있도록 comment들을 남겼다가 전송버튼 같은 걸로 한번에 보내도록 해줘.

2026-09-25 대화. "git diff" 는 사이드 바 "Git" 구획에서 연 파일 탭(diff 가 겹친 것), "fileDirectory" 는 "파일" 구획에서 연 파일 탭으로 읽었다. 둘은 같은 파일 탭이다. "claude" 는 같은 패널의 Claude 탭으로 읽었다.

용어

파일 탭
사이드 바 R9·R17 로 여는 읽기 전용 탭. 줄은 diff D1 의 DiffedLine — 지금 파일의 줄과 끼워 넣은 지운 줄이다
줄 번호 칸
줄 앞의 번호와 표시 칸("+", "−", 빈칸). 지운 줄은 번호가 비어 있어도 칸은 있다
코멘트
고른 줄(한 줄 또는 이어진 여러 줄)과 사용자가 적은 글 하나
모인 코멘트
한 패널에서 남기고 아직 보내지 않은 코멘트 전부. 그 패널의 어느 파일 탭에서 남겼든 함께 모인다
보낼 곳
그 패널의 Claude 탭(TerminalProgram.Claude). 하위 워크트리 패널의 탭은 들지 않는다

요구사항

  1. C1. 파일 탭의 줄 번호 칸을 누르면 그 줄이 골라져 바탕이 primaryContainer 가 되고, 그 줄 바로 아래에 코멘트 입력 칸이 열려 포커스를 받는다. 지운 줄도 같다. 입력 칸이 열린 채 다른 줄 번호 칸을 누르면 고른 줄이 그 줄로 바뀐다(적던 글은 남는다).
  2. C2. 한 줄을 고른 뒤 Shift 를 누른 채 다른 줄 번호 칸을 누르면 두 줄 사이(둘 포함)의 모든 줄이 골라지고, 입력 칸은 고른 범위의 마지막 줄 아래로 간다. 범위에는 지운 줄이 섞일 수 있다.
  3. C3. 입력 칸은 여러 줄 글을 받는다. "코멘트 추가" 버튼이나 ⌘Enter(macOS 밖에서는 Ctrl+Enter)로 추가하고, "취소" 버튼이나 Esc 로 닫는다. 앞뒤 공백을 뺀 글이 비어 있으면 추가할 수 없다. 추가하면 입력 칸이 닫히고 고른 줄이 풀린다.
  4. C4. 추가한 코멘트는 그 범위의 마지막 줄 아래에 카드로 보인다 — 줄 범위 이름("12–14행", 지운 줄만이면 "HEAD 5행 (지운 줄)")과 글, 삭제(✕) 버튼. 코멘트가 걸린 줄은 번호 칸이 primary 색이다. ✕ 를 누르면 그 코멘트만 지워진다.
  5. C5. 모인 코멘트가 하나라도 있으면 그 패널의 모든 파일 탭 아래에 막대가 붙는다: "코멘트 N개"(N 은 패널 전체), "모두 지우기", "Claude 에 보내기". 모두 지우면 막대가 사라진다.
  6. C6. "Claude 에 보내기" 의 보낼 곳: 패널에 Claude 탭이 하나면 곧바로 그 탭이다. 둘 이상이면 버튼 아래 메뉴에 탭 이름이 패널의 탭 순서로 나오고 고른 탭이다. 하나도 없으면 버튼 글이 "새 Claude 탭에 보내기" 이고, 누르면 그 파일 탭이 있는 그룹에 새 Claude 탭(Claude R2 와 같은 탭, 작업 디렉터리는 패널 폴더)을 열어 거기로 보낸다.
  7. C7. 보내면 보낼 곳 탭이 선택되어 보인다. 그 탭의 Claude 가 입력을 받을 수 있게 되면(Claude 준비) C8 의 글을 붙여넣기(bracketed paste)로 입력 칸에 넣고 Enter 를 보내 제출한다. 제출하면 보낸 코멘트가 모인 코멘트에서 빠진다. 기다리는 동안 추가한 코멘트는 남는다.
  8. C8. 보내는 글은 첫 줄 "아래 코드 줄에 남긴 코멘트 N개를 반영해 주세요." 뒤에 코멘트마다 빈 줄, "k. 경로:줄 범위", 고른 줄을 담은 코드 블록, 코멘트 글이다. 코멘트는 파일(처음 코멘트를 남긴 순서)끼리 모으고 파일 안에서는 남긴 순서다. 경로는 보낼 곳 탭의 작업 디렉터리 아래면 그 기준 상대 경로, 아니면 절대 경로다. 줄 범위는 지금 파일의 줄 번호 "12" 또는 "12-14"(지운 줄은 세지 않는다), 지운 줄만이면 " (HEAD 5-6, 지운 줄)" 이다. 코드 블록의 줄은 "번호 표시 글자"이고, 표시 칸("+", "−")은 고른 줄 중 더한·지운 줄이 있을 때만 붙는다. 코드 블록의 울타리는 글자 안의 가장 긴 백틱 연속보다 하나 길다(최소 3).
  9. C9. 보낸 뒤 ClaudeReadyTimeout(30초) 안에 Claude 가 준비되지 않으면 아무것도 입력하지 않고, 코멘트를 그대로 둔 채 막대에 "Claude 가 준비되지 않아 보내지 못했습니다" 를 보인다. 다시 보내거나 코멘트를 고치면 이 문구가 사라진다. 보내는 동안 버튼은 "보내는 중…" 이고 누를 수 없다.
  10. C10. 모인 코멘트는 앱이 켜져 있는 동안 남는다. 탭을 닫거나 터미널 화면을 떠났다 돌아와도 그대로고, 같은 파일을 다시 열면 다시 보인다. 패널을 닫으면 그 패널의 코멘트가 사라진다. 앱을 끄면 사라진다(저장하지 않는다).
  11. C11. 코멘트는 줄 번호에 붙는다 — 지금 줄은 지금 파일의 번호, 지운 줄은 HEAD 의 번호. 파일이 바뀌어 번호가 옮겨 가도 같은 번호의 줄 아래에 보이고, 그 번호의 줄이 없으면 파일 끝에 보인다. 보내는 글(C8)의 코드 블록은 코멘트를 남길 때의 줄 글자다.
  12. C12. Claude 를 띄울 수 없는 타깃(Claude R6)에서는 줄 번호 칸을 눌러도 아무 일도 없고 막대도 없다. 파일 탭은 이 기능 이전과 같다. 글자 고르기·복사(사이드 바 R11, diff D8)는 줄 번호 칸 밖에서 그대로다.
스코프에서 뺀 것 코멘트 고치기(지우고 다시 남긴다), 코멘트 저장·복원, 다른 패널의 Claude 에 보내기, 줄 번호 칸을 끌어 범위 고르기, 보내기 전에 글 미리 보기·다듬기, 보낸 코멘트 기록, 클립보드로 복사. 지시는 "남겼다가 한번에 보내기" 까지다.

Claude 준비

Claude 탭의 창은 셸이 claude attach 를 돌리다 끝나면 로그인 셸로 이어진다(Claude R4). 셸에 글을 붙여넣고 Enter 를 보내면 코멘트 글이 명령으로 실행되므로, 창이 지금 Claude 를 보이고 있을 때만 보낸다. 창의 에뮬레이터가 bracketed paste(DECSET 2004) 와 포커스 보고(DECSET 1004)를 둘 다 켰을 때를 준비로 본다. Claude Code 는 입력을 받기 시작할 때 ESC[?2004h ESC[?2031h ESC[?1004h 를 쓰고(2.1.282 로 확인), zsh·bash 의 줄 편집기는 2004 만 켠다. 창이 아직 없으면(한 번도 보이지 않은 탭, 새 탭) 보낼 때 연다.

공통 구현

domain
LineComment(id, path, lines: List<DiffedLine>, body) — lines 는 남길 때의 줄. DiffedLine.sameLine(other) 는 지금 줄끼리 번호, 지운 줄끼리 HEAD 번호가 같은지(C11). 순수 함수 lineCommentsPrompt(comments, directory): String(C8), LineComment.rangeLabel(C4 카드 제목). TerminalEmulator.focusReporting(DECSET 1004)을 bracketedPaste 처럼 든다
UI 상태
LineCommentHost — 패널 id 마다 PanelLineComments(comments, sending, failed) 를 StateFlow 로 든다. 추가·지우기·모두 지우기·보내기, 사라진 패널 치우기(retain). 보내기는 UpdateTerminalWorkspaceUseCase 로 보낼 곳 탭을 고르거나(없으면 새 Claude 탭을 열고), TerminalPaneHost.acquire 로 창을 얻어 TerminalPaneState.revision 이 readyForPaste(2004 ∧ 1004)가 될 때까지 ClaudeReadyTimeout 만큼 기다리고, TerminalPaneState.paste(text) 뒤 ClaudeSubmitDelay 를 두고 "\r" 를 보낸다. 앱 수명 스코프 단일 객체로 Koin 에 둔다
UI
TerminalViewModel 이 host 의 상태와 명령을 넘기고, TerminalFileViewer 가 FileLineComments(이 파일의 코멘트, 패널 전체 수, 보내는 중·실패, 보낼 곳 목록, 콜백)를 받아 줄 번호 칸·입력 칸·카드·막대를 그린다. null 이면 C12 다. 고른 줄과 입력 중인 글은 화면 안에서만 쓰는 값이라 remember 로 둔다
결정: 창에 붙여넣기로 입력하고 Enter 를 보낸다. 후보: (1) Claude Code 에 백그라운드 세션으로 메시지를 넣는 명령 — 2.1.282 의 claude --help 에 attach·logs·stop·rm·respawn 만 있고 넣는 명령이 없다. 버렸다. (2) 앱의 MCP 서버에 도구를 두고 Claude 가 가져가게 — 사용자가 Claude 에게 "가져가" 라고 따로 말해야 해서 "한 번에 보내기" 가 아니다. 버렸다. (3) 채택: 사용자가 붙여넣고 Enter 를 친 것과 같은 바이트를 창에 쓴다. 여러 줄 글이 한 입력으로 들어가려면 bracketed paste 여야 하고, Enter 는 붙여넣기 끝 뒤에 따로 보내야 줄바꿈이 아니라 제출로 읽힌다.
결정: 코멘트는 패널마다 모으고 저장하지 않는다. 파일마다 보내면 "한번에" 가 아니고, 앱 전체로 모으면 다른 저장소의 코멘트가 한 Claude 에 섞인다. 패널은 폴더(워크트리) 하나와 그 Claude 탭들이라 단위가 맞다. 보내기 전의 초안이라 앱을 끄면 버려도 되고, 저장하면 줄이 옮겨 간 뒤 다시 켰을 때 엉뚱한 줄에 붙는다. ViewModel 에 두면 터미널 화면을 떠날 때 사라지므로 TerminalPaneHost 처럼 앱 수명 객체에 둔다 — 관측이 아니라 사용자가 만든 초안을 드는 것이다.
결정: 범위는 Shift+누름으로 고른다. 줄 번호 칸을 끌어 고르기는 칸이 SelectionContainer 안에 있어 글자 고르기 끌기와 겹치고, 손을 떼는 자리를 찾는 코드가 는다. 파일 탭은 데스크톱에서만 열 수 있어(C12) Shift 가 늘 있다.

  • 준비 판정(2004 ∧ 1004)은 Claude Code 2.1.282 의 동작을 기준으로 한다. Claude 가 끝나고 이어진 셸에서 vim 처럼 두 모드를 다 켜는 프로그램이 돌고 있으면 그 프로그램에 붙여넣는다.

  • 긴 글은 Claude Code 가 입력 칸에 "[Pasted text #1 +N lines]" 로 접어 보이지만 제출되는 글은 전부다.
  • 파일이 바뀐 뒤에는 카드가 붙은 줄의 글자가 코멘트를 남길 때와 다를 수 있다(C11). 보내는 글은 남길 때의 글자다.
