파일 탭 보기 방식 (마크다운·HTML 미리보기)

파일 이름으로 그 파일을 그려 볼 수 있는지 가려, 마크다운·HTML·SVG 파일 탭에는 도구 줄에 "미리보기"·"원문" 보기 버튼을 저절로 붙이고 미리보기로 연다. "원문" 은 곧 편집 보기라 고친 내용이 알아서 저장되고, 미리보기로 돌아오면 저장한 모양이 보인다.

사용자 지시

md파일, html 파일 같은 것은 자동으로 viewMode 옵션 노출해서 편집이나 viewing 할 수 있도록 해줘.

2026-09-25 대화. 마크다운 미리보기·원문 전환과 편집은 파일 탭 편집·꾸며 보기(M1–M5, E1–E8)에 이미 있다. 이 지시는 그 보기 전환을 "그려 볼 수 있는 파일" 전반의 규칙으로 넓히고, HTML 을 더하는 것으로 읽었다. "같은 것" 에는 브라우저가 그대로 그리는 SVG 를 넣었다(결정).

용어

보기 방식
지시의 "viewMode". 파일 탭이 내용을 어떤 모양으로 보이는지. 미리보기·원문·편집 보기 셋이다
미리보기
파일을 그 형식대로 그린 화면. 마크다운 미리보기(M2)와 웹 미리보기 두 가지다
웹 미리보기
HTML·SVG 파일을 웹 엔진(브라우저 탭과 같은 엔진)으로 그린 화면
원문
미리보기가 아닌 쪽. 편집할 수 있으면 편집 보기, 아니면 읽기 보기(문법 색·diff·줄 코멘트)다(M1)
편집 보기
자동 저장되는 입력 칸(E2·E3). 편집할 수 있는 파일의 원문은 처음부터 이 보기다

요구사항

  1. V1. 파일 탭의 미리보기 종류는 파일 이름(대소문자 무시한 확장자)으로 정한다. .md·.markdown 은 마크다운 미리보기, .html·.htm·.xhtml·.svg 는 웹 미리보기다. 그 밖의 파일은 미리보기가 없다.
  2. V2. 미리보기가 있는 파일 탭(작업 트리 파일 탭과 커밋 파일 탭)의 도구 줄 오른쪽에는 "미리보기"·"원문" 두 버튼이 저절로 붙는다. 고른 쪽은 primary 색·굵은 글자다. 미리보기가 없는 파일에는 두 버튼이 없다.
  3. V3. 미리보기가 있는 파일 탭은 미리보기로 열린다. 고른 보기는 탭마다 따로이고, 같은 그룹의 다른 탭을 골랐다 돌아오거나 터미널 화면을 떠났다 돌아와도 남는다. 탭을 닫거나 앱을 끄면 버린다(다시 열면 미리보기).
  4. V4. 편집은 마크다운과 같은 규칙(M1·M5)을 HTML·SVG 에도 쓴다. 편집할 수 있는 파일(E1)의 "원문" 은 편집 보기이고, 원문 안에서 "읽기 보기"·"편집" 아이콘 버튼으로 오간다(E5). 미리보기에는 "편집" 버튼이 없다. "미리보기" 를 누르면 저장을 기다리던 변경을 곧장 저장하고, 미리보기는 저장한 내용을 그린다(V6).
  5. V5. 웹 미리보기는 작업 트리 파일 탭이면 그 파일의 file:// 주소를 열어, 같은 폴더 기준 상대 경로의 CSS·이미지·스크립트가 함께 붙는다. 커밋 파일 탭이면 커밋 시점의 내용을 그린다. 이때 상대 경로 자원은 붙지 않는다(작업 트리의 자원을 붙이면 커밋 시점과 다른 모양이 된다).
  6. V6. 웹 미리보기는 파일 내용이 바뀌면(디스크 변경은 R13 의 간격, 저장은 E8) 다시 그린다.
  7. V7. 웹 미리보기의 페이지는 미리보기가 보이는 동안만 있다. 원문·편집 보기로 바꾸거나 다른 탭을 고르거나 탭을 닫으면 닫고, 다시 보이면 파일을 새로 연다. 미리보기 안의 링크·스크립트는 그 미리보기 안에서 돈다.
  8. V8. 웹 페이지를 띄울 수 없는 타깃(브라우저 R8 과 같은 조건 — 지원하지 않는 곳에는 "웹 브라우저" 메뉴가 없다)에서는 HTML·SVG 파일에 웹 미리보기가 없다. 그 파일은 원문으로 열리고 "미리보기"·"원문" 버튼이 없다.
  9. V9. 새 탭 메뉴가 떠 있거나 탭을 끄는 동안 웹 미리보기가 메뉴를 가리는 타깃에서는 그동안 웹 미리보기를 치운다(브라우저 R9 과 같은 규칙).
  10. V10. 바이너리·읽을 수 없는 파일은 확장자가 무엇이든 예전 문구만 보이고 보기 버튼이 없다. 잘린 파일(512 KiB 초과)은 "앞 512 KiB 만 보입니다" 를 붙이고, 마크다운 미리보기와 커밋 파일 탭의 웹 미리보기는 읽은 만큼 그린다. 작업 트리 파일 탭의 웹 미리보기는 엔진이 파일을 직접 읽어 전체가 보이므로 문구를 붙이지 않는다.
스코프에서 뺀 것 미리보기와 원문 나란히 보기, 입력하는 동안 미리보기를 따라 그리기, 웹 미리보기의 주소 줄·뒤로 가기, 웹 미리보기를 Claude 의 브라우저 도구(MCP)에 내놓기, 그 밖의 형식(이미지·PDF·CSV 표·JSON 트리). 지시는 md·html "같은 것" 이라 문서로 그려 볼 수 있는 텍스트 형식까지로 둔다. 이미지는 텍스트가 아니라 파일 탭이 바이너리로 읽는다(V10).

화면·동작

┌ 파일 탭: index.html — 웹 미리보기 ─────────────┐
│ HEAD 대비 +2 −1            [미리보기|원문] [✎]  │ ← 도구 줄(V2)
│ ┌─────────────────────────────────────────────┐ │
│ │  (웹 엔진이 그린 페이지)                     │ │
│ └─────────────────────────────────────────────┘ │
└─────────────────────────────────────────────────┘
항목값
보기 버튼도구 줄 오른쪽, "편집" 아이콘 버튼 앞. "미리보기"·"원문" 두 글자 버튼(TextButton). 고른 쪽 primary·SemiBold, 다른 쪽 onSurfaceVariant
웹 미리보기도구 줄 아래 남은 칸 전부. 바탕은 페이지가 칠한다(칠하지 않으면 엔진 기본값 흰색). 빠른 스크롤 막대는 없고 페이지 자체의 스크롤을 쓴다
엔진을 띄우지 못했을 때"[웹 페이지를 열 수 없습니다]" (브라우저 탭과 같은 문구)
테스트 태그terminal:file-viewer:preview, terminal:file-viewer:source(기존), terminal:file-viewer:markdown(기존), terminal:file-viewer:web-preview

공통 구현

domain
enum class FilePreview { Markdown, Web } 와 순수 함수 filePreviewOf(path): FilePreview?(V1)
상태
TerminalViewModel.sourceViewTabs: StateFlow<Set<Long>> — 원문을 고른 탭(V3). 예전 markdownSource 를 이름만 넓혔다. setSourceView(tabId, source). 탭이 작업 공간에서 사라지면 reconcile 이 뺀다
UI
TerminalFileViewer 가 filePreviewOf 로 종류를 고르고, 웹 미리보기는 webPreviewSupported(= isBrowserSupported)일 때만 둔다(V8). 도구 줄의 보기 버튼은 종류가 있으면 붙는다(V2)
공급
@Composable internal expect fun HtmlFilePreview(tabId: Long, path: String, html: String, fromDisk: Boolean, hidden: Boolean, onFocus: () -> Unit, modifier: Modifier) — fromDisk 는 작업 트리 파일 탭이다(V5). html 이 바뀌면 다시 그리고(V6), 컴포지션을 떠나면 페이지를 닫는다(V7). hidden 은 TerminalTabDragState.coversPages(V9)
결정: 웹 미리보기는 브라우저 탭의 엔진을 그대로 쓴다 JVM 은 :core:browser 의 Chromium(JCEF) 페이지를 파일 탭 id 로 하나 만들고, Android 는 시스템 웹뷰(composewebview)다. 엔진을 새로 싣지 않는다. 버린 후보: (1) HTML 을 Compose 로 직접 그리기 — CSS·스크립트·레이아웃을 흉내 낼 수 없어 "보이는 대로" 가 되지 않는다. (2) 시스템 브라우저로 열기(LocalUriHandler) — 지시는 파일 탭 안의 보기 방식이고, 저장해도 다시 그려지지 않는다(V6).
결정: 웹 미리보기 페이지는 보이는 동안만 산다(V7) 브라우저 탭은 Claude 가 가려진 탭을 조작해야 해서 페이지를 탭 수명 동안 붙잡지만(R6), 미리보기는 사람이 보려는 것이라 가려지면 닫는다. JVM 에서 Chromium 렌더러가 HTML 파일 탭마다 남아 메모리를 쥐지 않게 하려는 것이다. 대가로 탭을 다시 고르면 페이지를 새로 연다(스크롤·페이지 안 상태가 남지 않는다).
결정: SVG 도 웹 미리보기다 SVG 는 XML 텍스트라 원문은 문법 색(XML)으로 이미 보이고, 웹 엔진이 그대로 그린다. 지시의 "같은 것" 에 든다고 봤다. XML·JSON 같은 데이터 파일은 그려 볼 모양이 없어 넣지 않았다.

한계

  • 커밋 파일 탭의 웹 미리보기는 HTML 한 파일만 그린다. 따로 떨어진 CSS·이미지·스크립트를 쓰는 페이지는 모양이 빠진 채 보인다(V5).
  • 웹 미리보기는 파일이 바뀔 때마다 페이지를 다시 불러 스크롤이 처음으로 돌아갈 수 있다.
  • 미리보기 안에서 링크를 눌러 다른 페이지로 가면 돌아올 버튼이 없다. "원문" 을 눌렀다 "미리보기" 로 오면 파일로 돌아온다(V7).
  • 원문(편집 보기)에서는 미리보기가 없다. "미리보기" 를 눌러야 바뀐 모양을 본다.
