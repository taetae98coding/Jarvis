커밋 파일 탭 (커밋의 파일 diff)

사이드 바 Git 구획에서 펼친 커밋의 파일 줄을 누르면, 그 커밋 시점의 파일 내용 위에 첫 부모 대비 더한 줄·지운 줄을 겹쳐 보이는 읽기 전용 탭이 열린다. 모양은 파일 탭의 git diff와 같고, 비교 대상만 "HEAD 와 작업 트리" 가 아니라 "그 커밋의 부모와 그 커밋" 이다.

사용자 지시

파일 줄 누르면 그 커밋 diff도 볼 수 있게 해줘

2026-09-25 대화. "파일 줄" 은 사이드 바 R26 의 커밋의 파일 줄이다.

용어

커밋 파일 탭
파일 탭(TerminalProgram.File)에 커밋 해시가 붙은 것. 디스크의 지금 파일이 아니라 그 커밋 시점의 파일을 보인다. 같은 경로의 보통 파일 탭과는 다른 탭이다
첫 부모
커밋의 첫째 부모 커밋. 병합 커밋은 병합을 받은 쪽이고, 첫 커밋은 부모가 없어 빈 트리다. 사이드 바 용어 "커밋의 파일" 과 같은 기준이다
더한 줄 · 지운 줄
그 커밋에 있고 첫 부모에 없는 줄, 첫 부모에 있고 그 커밋에 없는 줄. 파일 탭의 diff 용어에서 "지금 파일" 을 "그 커밋", "HEAD" 를 "첫 부모" 로 바꾼 것이다

요구사항

  1. K1. 사이드 바 Git 구획에서 펼친 커밋의 파일 줄을 누르면, 사이드 바 R9 와 같이 선택된 패널의 포커스된 그룹 탭 줄 끝에 그 파일의 커밋 파일 탭이 열려 선택된다. 같은 패널에 같은 경로·같은 커밋의 탭이 이미 있으면 새로 열지 않고 그 탭을 고른다. 같은 경로의 보통 파일 탭이나 다른 커밋의 탭은 고르지 않는다.
  2. K2. 탭의 종류 아이콘·설명은 "파일" 이고 자동 제목은 "<파일 이름> @ <짧은 해시 7자리>" 다. 이름 바꾸기·닫기·끌어 놓기·분할은 다른 탭과 같다. 경로·해시와 함께 저장돼 앱을 다시 켜면 같은 커밋의 파일로 되살아난다.
  3. K3. 내용은 그 커밋 시점의 파일이다. 사이드 바 R11 과 같이 고정폭·줄 번호·줄바꿈 없이 보이고, FileViewerMaxBytes(512 KiB) 자르기와 앞 8 KiB 의 NUL 바이트로 텍스트가 아닌 파일 판정도 같다. 디스크나 git 을 따라가지 않는다 — 커밋은 바뀌지 않으므로 탭을 열 때 한 번 읽는다.
  4. K4. 첫 부모 대비 더한 줄·지운 줄을 파일 탭 diff 의 D1 과 똑같은 모양으로 겹치고, 내용 위에 "커밋 <짧은 해시> +n −m" 을 붙인다. 이름 바꾼 파일은 옛 경로의 내용과 비교한다. 첫 커밋과 그 커밋에서 새로 더한 파일은 모든 줄이 더한 줄이다. 바뀐 줄이 없으면(같은 이름으로만 바꿈, 모드만 바뀜) 요약이 없다.
  5. K5. 그 커밋에서 지운 파일은 D4 와 같이 "파일을 읽을 수 없습니다" 대신 첫 부모의 모든 줄을 지운 줄로 보이고 K4 의 요약을 붙인다.
  6. K6. 커밋이 없어졌거나(rebase·reset 뒤 저장했던 탭), 저장소 밖이거나, git 을 쓸 수 없는 플랫폼이면 "파일을 읽을 수 없습니다" 다. 텍스트가 아닌 파일은 diff 가 있어도 R11 의 "텍스트가 아닌 파일이라 보일 수 없습니다" 그대로다.
  7. K7. 줄 코멘트(C1)는 커밋 파일 탭에서 남길 수 없다 — 줄 번호 칸을 눌러도 아무 일도 없고 코멘트 막대도 없다. 글자 고르기·복사는 D8 과 같다.
스코프에서 뺀 것 둘째 부모 대비(병합의 다른 쪽), 커밋 전체 diff 를 한 탭에, 두 커밋 사이 비교, 커밋 본문 보기, 커밋 파일 탭에서 파일 탭(작업 트리)으로 건너가기, 커밋 파일 탭의 줄 코멘트. 지시는 "그 커밋 diff" 라 파일 하나의 첫 부모 대비 diff 로 둔다.

화면·동작

┌ 탭 영역 ──────────────────────────────────────────────┐┌ 내용 ──────────────┐
│ [셸 1] [Foo.kt @ 613d315 ✕] [+]                        ││ 커밋 그래프          │
│ 커밋 613d315 +2 −1                                     ││ * [HEAD -> main] …  │  ← 선택
│   1    package app                                     ││ |  613d315 · dev …  │
│   2 +  import Bar                                      ││    파일 2개          │
│      − fun old() = 1                                   ││    M  Foo.kt  app   │  ← 눌러서 열림
│   3 +  fun new() = 2                                   ││    A  Bar.kt  app   │
└────────────────────────────────────────────────────────┘└─────────────────────┘
항목값
여는 곳사이드 바 Git 구획, 펼친 커밋의 파일 줄(terminal:git:commit-file:<경로>). 줄은 clickable 이다
탭종류 아이콘 File, 설명 "파일", 자동 제목 "Foo.kt @ 613d315"(짧은 해시는 해시 앞 7자리)
요약"커밋 <짧은 해시> +n −m" — 파일 탭 diff 의 "HEAD 대비 +n −m" 과 같은 자리·글꼴(labelMedium onSurfaceVariant)
줄 표시파일 탭 diff 와 같다: 더한 줄 successContainer "+", 지운 줄 errorContainer "−", 줄 번호는 그 커밋의 파일 기준
문구"파일을 읽을 수 없습니다", "텍스트가 아닌 파일이라 보일 수 없습니다", "앞 512 KiB 만 보입니다"
테스트 태그파일 탭과 같다: terminal:file-viewer:<탭 id>, terminal:file-viewer:diff-summary, terminal:file-viewer:added:<번호>, terminal:file-viewer:removed:<옛 번호>, terminal:file-viewer:notice, 탭 제목 terminal:tab:title:<탭 id>

공통 구현

domain
TerminalTab.commitHash: String?(File 탭에만, null 이면 보통 파일 탭), TerminalWorkspace.openCommitFile(path, hash)(K1; openFile 은 commitHash == null 인 탭만 고른다), GitCommitFile(content: FileContent, diff: GitFileDiff), GitChangesRepository.observeCommitFile(path, hash): Flow<GitCommitFile?>(null 은 저장소 밖·커밋 없음·git 없음, 지운 파일은 Unreadable + 모두 지운 hunk), 유스케이스 ObserveGitCommitFileUseCase. 줄 만들기는 파일 탭 diff 의 diffedLines 그대로다
data
TerminalTabDto.commitHash(없으면 null 로 읽어 옛 저장 파일과 호환), GitDataSource.observeCommitFile. 해석은 공통 함수 parseGitCommitDiff(output, path) — 여러 파일의 -p 출력에서 diff --git 구획을 나눠 +++ b/<경로>(지운 파일은 --- a/<경로> 와 +++ /dev/null)인 구획만 parseGitDiff 로 읽는다. 내용 판정(512 KiB, NUL)은 파일 읽기와 같은 공통 함수 fileContentOf(bytes, truncated) 다
UI
사이드 바 TerminalGitPanel 의 파일 줄이 onOpenCommitFile(저장소 최상위 + 경로, 해시) 를 부르고, 화면이 TerminalViewModel.openCommitFile 로 잇는다. TerminalViewModel.commitFile(path, hash) 가 fileContent(path) 와 같이 (경로, 해시)마다 stateIn(viewModelScope, WhileSubscribed(replayExpirationMillis = 0), null) 로 내놓고, 탭이 사라지면 버린다. TerminalFileViewer 는 요약 앞말(diffLabel: "HEAD 대비" / "커밋 613d315")만 다르고 나머지는 같다. 커밋 파일 탭은 lineComments = null 로 그린다(K7)
결정: 새 탭 종류가 아니라 파일 탭에 커밋 해시를 붙인다. TerminalProgram.CommitFile 을 새로 두는 방법을 버렸다. 아이콘·제목 규칙·저장 형식·닫기·끌기·분할이 파일 탭과 같고 다른 것은 "어디서 읽느냐" 뿐이라, 프로그램을 늘리면 탭 종류 분기(when)가 화면·저장·MCP 곳곳에서 하나씩 는다. 해시 하나를 더하는 쪽이 다른 코드를 건드리지 않는다. 같은 경로의 보통 파일 탭과는 해시 유무로 갈라 따로 연다 — 작업 트리의 파일과 옛 커밋의 파일은 다른 내용이다.
결정: 그 커밋의 내용 위에 첫 부모 대비 -U0 덩어리를 겹친다. 파일 탭 diff 의 결정(내용 + -U0)을 그대로 따른다. 좌우 나란히 보기나 diff 출력만 그리는 방법은 파일 탭 diff 에서 버린 이유가 그대로 든다. 비교 대상이 첫 부모인 것은 사이드 바의 "커밋의 파일" 목록과 같은 기준을 써서, 목록에 M 으로 보인 파일을 열면 그 M 의 내용이 보이게 하기 위해서다.
결정: 한 번 읽고 따라가지 않는다. 커밋 객체는 바뀌지 않으므로 폴링·신호가 필요 없다. 파일 탭처럼 디스크를 따라가면 "커밋 시점의 파일" 이 아니게 된다. 커밋이 rebase 로 사라지는 경우는 탭을 다시 열 때(앱 재시작, 화면 복귀) "파일을 읽을 수 없습니다" 로 드러난다(K6).
결정: 커밋 파일 탭에는 줄 코멘트를 두지 않는다. 줄 코멘트는 작업 트리의 줄 번호에 붙고 Claude 가 고치는 것도 지금 파일이다(C11). 옛 커밋의 줄 번호를 보내면 Claude 가 엉뚱한 줄을 고친다. 커밋을 보다 고칠 것이 있으면 사이드 바에서 같은 파일의 파일 탭을 열어 남긴다.

한계

  • 파일 하나·첫 부모 대비만 보인다. 병합 커밋의 둘째 부모 쪽 변경과 커밋 전체 diff 는 셸에서 git show 로 본다.
  • 내용은 앞 512 KiB 까지이고, 그 뒤의 지운 줄은 보이지 않는다(파일 탭 diff D7 과 같다).
  • 이름 바꿈은 git 의 유사도 판정(-M, 기본 50%)을 따른다. 내용이 절반 넘게 바뀐 이름 바꿈은 새 파일로 보여 모든 줄이 더한 줄이다.
  • 탭·경로 이름에 탭 문자·줄바꿈이 든 파일은 git 이 경로를 따옴표로 감싸 구획을 찾지 못해 diff 없이 내용만 보인다.
  • 저장한 탭의 커밋이 사라지면(rebase·gc) "파일을 읽을 수 없습니다" 다. 탭을 닫고 그래프에서 다시 연다.
