터미널에서 실행

탭 줄의 실행(▶) 메뉴에서 패널 폴더의 Android·iOS 앱을 빌드 변형·구성과 기기를 골라 실행하면 빌드 로그 탭과 그 기기의 화면(미러링) 탭이 열리고, 패널에 저장한 사용자 명령을 새 탭에서 실행한다.

사용자 지시

터미널에서 실행 기능 추가하자.
1. Android 프로젝트인지 감지해서 buildVariant, device(실기기/에뮬 포함) 실행할 수 있도록, 실행 시 탭 새로 열리면서 미러링 제공.
2. iOS 프로젝트 감지해서 configuration, device(실기기/에뮬 포함) 실행할 수 있도록, 실행 시 탭 새로 열리면서 미러링 제공.
3. custom terminal 명령어 입럭 가능(패널마다 저장해서 재시작시 사용할 수 있고, 워크트리마다 명령어 공유, Orca 참고)

2026-09-25 대화. "탭 새로 열리면서 미러링 제공" 은 빌드·설치·실행 로그를 보이는 탭과, 고른 기기의 화면을 보이는 기기 탭을 함께 여는 것으로 읽었다(R9·R10). "패널마다 저장" 과 "워크트리마다 공유" 는 명령 목록을 최상위 패널에 저장하고 그 아래 워크트리 패널이 같은 목록을 보고 고치는 것으로 읽었다(R14). "Orca 참고" 는 Orca 의 orca.yaml defaultTabs(저장소마다 {title, command} 목록을 두고 워크트리마다 탭 하나씩 명령을 돌린다)를 본떠, 명령 하나 = 이름(선택) + 명령 줄, 실행 = 새 탭 하나로 정했다.

요구사항

실행 메뉴

  1. R1. 그룹마다 탭 줄의 새 탭(+) 버튼 오른쪽에 실행(▶) 버튼이 있다. 그룹이 없는 빈 패널에도 + 옆에 있다. 누르면 실행 메뉴가 뜬다.
  2. R2. 실행 메뉴는 위에서부터 "Android 앱 실행…"(패널 폴더가 Android 프로젝트일 때), "iOS 앱 실행…"(iOS 프로젝트일 때), 구분선(프로젝트 줄이 있을 때만)과 "명령" 머리글, 저장된 명령 줄들, "명령 추가…" 다. 프로젝트 줄은 이 타깃이 앱 실행을 지원할 때만 나온다(플랫폼별 판정).
  3. R3. 프로젝트를 보는 폴더는 선택된 패널의 폴더이고, 없으면 포커스된 탭의 작업 디렉터리다(사이드 바와 같은 폴더). 둘 다 없으면 프로젝트 줄이 없다.
  4. R4. Android 프로젝트 = 그 폴더에 settings.gradle.kts 나 settings.gradle 가 있고 gradlew 가 있다. iOS 프로젝트 = 그 폴더나 바로 아래 폴더에 *.xcworkspace(.xcodeproj 안의 것 제외)나 *.xcodeproj 가 있다. 둘 다면 두 줄이 모두 나온다(Kotlin Multiplatform 저장소).
  5. R5. 판정은 메뉴가 떠 있는 동안에만 한다. 메뉴를 열 때마다 다시 본다.

Android 앱 실행

  1. R6. "Android 앱 실행…" 을 누르면 "Android 앱 실행" 창이 뜬다. 창은 Gradle 에 물어 com.android.application 모듈과 그 모듈의 빌드 변형(debug, release, flavor 조합)과 applicationId 를 읽는다. 읽는 동안 "빌드 변형을 읽는 중…", 실패하면 "빌드 변형을 읽지 못했습니다." 와 "다시 시도" 버튼, 앱 모듈이 없으면 "Android 앱 모듈이 없습니다." 다.
  2. R7. 창의 고를 거리는 "모듈"(앱 모듈이 둘 이상일 때만), "빌드 변형", "기기" 다. 기기는 Android 에뮬레이터(켜진 것·꺼진 AVD 모두)와 연결된 Android 실물 기기(유선·무선)다. 기기 줄은 이름과 종류(기기 탭의 종류 문구, 꺼진 가상 기기는 뒤에 " · 꺼짐")다. 기기가 없으면 "실행할 기기가 없습니다." 다.
  3. R8. "실행" 은 변형과 기기를 모두 골랐을 때만 누를 수 있다. 누르면 창이 닫히고 R9·R10 이 일어난다. 실행 탭은 꺼진 AVD 면 그 에뮬레이터를 켜고 부팅이 끝날 때까지 기다린 뒤, 그 기기 하나에 <모듈>:install<변형> 로 설치하고 앱의 런처 액티비티를 띄운다. 각 단계는 "▶ " 로 시작하는 한 줄을 먼저 찍고, 실패하면 거기서 멈춘다.

실행 탭과 미러링

  1. R9. 실행하면 ▶ 를 누른 그룹의 탭 줄 끝에 실행 탭이 붙어 선택되고 그 그룹이 포커스를 받는다. 실행 탭은 프로젝트 폴더에서 빌드·설치·실행 스크립트를 로그인 셸로 돌리고, 끝나면(실패해도) 같은 탭이 그 폴더의 셸 프롬프트로 남는다. 탭 이름은 "변형 · 기기 이름"(iOS 는 "구성 · 기기 이름")이고 종류 아이콘은 ▶ 다.
  2. R10. 화면을 볼 수 있는 기기(Android 전부, iOS 시뮬레이터)면 그 기기의 기기 탭도 연다. 패널에 같은 기기의 기기 탭이 이미 있으면 새로 열지 않고 그 탭을 그 그룹에서 고른다. 없으면 실행 탭 그룹을 좌우로 나눠 오른쪽 새 그룹에 기기 탭을 넣는다(실행 그룹 몫 0.6). 포커스는 실행 탭 그룹에 남는다. 실물 iOS 기기는 화면을 찍을 수 없어 기기 탭을 열지 않는다(기기 탭 R1).
  3. R11. 꺼진 AVD 로 실행하면 기기 탭은 AVD 이름(avd:<이름>)을 가리킨다. 켜지기 전에는 "화면을 가져올 수 없습니다." 이고, 그 이름의 에뮬레이터가 켜지면 스스로 그 화면으로 이어진다. 다시 켜서 시리얼이 바뀌어도 따라간다. 제스처도 켜진 기기로 간다.

iOS 앱 실행

  1. R12. "iOS 앱 실행…" 을 누르면 "iOS 앱 실행" 창이 뜬다. 창은 xcodebuild -list 로 스킴과 구성(Configuration)을 읽는다. 읽는 동안 "스킴을 읽는 중…", 실패하면 "스킴을 읽지 못했습니다." 와 "다시 시도" 다. 워크스페이스는 구성을 알려 주지 않으므로 "Debug"·"Release" 를 보인다. 고를 거리는 "스킴"(둘 이상일 때만), "구성", "기기"(iOS 시뮬레이터 — 켜진 것·꺼진 것 모두 — 와 연결된 실물 iPhone·iPad)다.
  2. R13. "실행" 을 누르면 R9·R10 이 일어난다. 실행 탭은 꺼진 시뮬레이터면 부팅하고, 그 기기를 대상으로 xcodebuild build 한 뒤 만든 .app 을 설치하고 번들 id 로 띄운다. 실물 기기는 서명 자동 갱신(-allowProvisioningUpdates)을 허용해 빌드하고 devicectl 로 설치·실행한다.

사용자 명령

  1. R14. 명령 목록은 최상위 패널마다 하나다. 워크트리 패널은 부모 패널의 목록을 그대로 보고, 거기서 더하고 고치고 지운 것이 부모와 다른 워크트리 패널에도 보인다. 목록은 작업 공간 파일에 저장되어 앱을 다시 켜도 남는다. 패널을 닫으면 그 패널의 목록도 사라진다.
  2. R15. "명령 추가…" 는 "이름"(비워도 된다)과 "명령" 입력란이 있는 "명령 추가" 창을 띄운다. "저장" 은 명령이 공백뿐이 아닐 때만 눌리고, 목록 끝에 붙인다. 앞뒤 공백은 뗀다. 명령 줄 오른쪽의 연필은 같은 창("명령 편집")을 그 값으로 띄우고, ✕ 는 확인 없이 지운다.
  3. R16. 명령 줄은 이름(없으면 명령)을 굵게, 이름이 있으면 그 아래에 명령을 작게 보인다. 누르면 ▶ 를 누른 그룹에 새 탭을 열어 선택하고, 그 패널의 폴더(없으면 R3 의 폴더, 그것도 없으면 홈)에서 명령을 로그인·대화형 셸로 돌린다. 끝나면 같은 탭이 셸 프롬프트로 남는다. 탭 이름은 명령의 이름(없으면 명령)이고 종류 아이콘은 ▶ 다. 워크트리 패널에서 누르면 그 워크트리 폴더에서 돈다.

저장·복원

  1. R17. 마지막으로 실행한 Android(모듈·변형·기기)와 iOS(스킴·구성·기기) 선택을 최상위 패널에 저장한다(워크트리 패널과 함께 쓴다). 창을 다시 열면 그 값으로 시작하고, 그 값이 지금 목록에 없으면 debug/Debug(없으면 첫 항목)와 켜진 첫 기기(없으면 첫 기기)로 시작한다.
  2. R18. 앱을 다시 켜면 실행 탭과 명령 탭은 같은 폴더의 셸 탭으로 되살아난다. 명령을 다시 돌리지 않는다. 실행 탭이 연 기기 탭은 보통 기기 탭처럼 되살아난다.
스코프에서 뺀 것
  • 저장소 안 파일(orca.yaml 같은)로 명령을 공유하는 것. 명령은 이 Mac 의 작업 공간에만 있다. 같은 저장소를 다른 패널로 열면 목록이 따로다.
  • 실행 중인 빌드를 멈추는 별도 버튼. 실행 탭은 셸 탭이라 Ctrl+C 로 멈추고, 탭을 닫으면 끝난다.
  • 실물 iOS 기기의 화면 미러링. 공개 도구로 찍을 수 없다(기기 탭 R1, JVM 기술 조사).
  • 명령 순서 바꾸기, 앱을 켤 때 명령 자동 실행(Orca 의 "Run default tab commands"), 명령마다 폴더·환경 변수 지정.
  • Android Studio 의 run configuration·Xcode 의 scheme 편집. 읽기만 한다.

공통 구현

도메인 (terminal)
TerminalTab.command: String?, commandTitle: String? — 셸 탭이 로그인 셸 대신 이 명령으로 시작한다(R9·R16). kind 는 command 가 있으면 Run.
TerminalCommand(id, title, command). TerminalPanel.commands, androidRun: AndroidRunChoice?, iosRun: IosRunChoice? — 최상위 패널에만 의미가 있다.
TerminalWorkspace.commandsOf(panelId)·addCommand·editCommand·removeCommand·rememberAndroidRun·rememberIosRun 는 워크트리 패널이면 부모에게 작용한다(R14·R17). runInGroup(groupId, directory, command, title, mirror: RunMirror?) 가 R9·R10 의 배치를 한다.
ProjectRunRepository: isSupported, observeProjectKinds(directory): Flow<Set<ProjectKind>>(R4·R5), observeAndroidProject(directory): Flow<ProjectLoad<AndroidProject>>(R6), observeIosProject(directory): Flow<ProjectLoad<IosProject>>(R12), androidRunCommand(request)·iosRunCommand(request): 실행 탭에 넣을 명령 줄(R8·R13).
유스케이스 IsProjectRunSupportedUseCase, ObserveProjectKindsUseCase, ObserveAndroidProjectUseCase, ObserveIosProjectUseCase, RunAndroidAppUseCase, RunIosAppUseCase — 뒤 둘은 명령 줄을 만들고 작업 공간을 한 번에 바꾼다(선택 저장 + 탭 배치). 사용자 명령 실행은 저장소가 필요 없어 ViewModel 이 runInGroup 을 바로 부른다.
공급 (terminal data)
internal expect fun createProjectRunDataSource(): ProjectRunDataSource. 저장 형식에 탭의 command·commandTitle(쓰기만 하고 읽을 때 버린다 — R18), 패널의 commands·androidRun·iosRun 이 는다. TerminalDataSource.open 은 command 가 있는 셸 탭을 shell -l -i -c "<command>; exec shell -l" 로 띄운다(JVM). Android 는 sh -c "<command>; exec sh -i".
기능 사이
:core:ui 의 DeviceScreens 에 @Composable runTargets(): List<DeviceChoice>? 를 더한다. 화면을 볼 수 없는 기기까지 기기 목록 전부다. DeviceChoice 에 isRunning, isPhysical, canMirror 를 더한다(기본값은 기존 choices() 의 값). emulator 의 EmulatorScreenViewModel 은 avd:<이름> 을 그 이름의 켜진 에뮬레이터로 풀어 화면·제스처를 보낸다(R11, EmulatorDevice.matches(deviceId)).
상태
TerminalViewModel.projectKinds(directory)·androidProject(directory)·iosProject(directory) 는 cold Flow 를 그대로 주고, 메뉴·창이 컴포지션에 있는 동안 collectAsStateWithLifecycle 로 모은다(창의 초기값 Loading). "다시 시도" 는 재시도 카운터를 remember 키로 써서 흐름을 새로 만든다. 여섯 유스케이스는 ProjectRunner 하나로 묶어 받는다 — TerminalViewModel 생성자가 Koin viewModelOf 의 한도(22개)를 넘지 않게.
UI
feature/terminal/ui/.../TerminalRunMenu.kt(버튼·메뉴), TerminalRunDialog.kt(Android·iOS 창), TerminalCommandDialog.kt
결정: 실행 탭은 명령을 가진 셸 탭이다 새 TerminalProgram.Run 을 두는 안은 셸을 띄우는 곳, 창을 여는 곳, 저장 형식, 제목 등 program 을 가르는 곳을 모두 늘린다. 실행 로그는 pty 에 흐르는 셸 출력이고 끝나면 셸로 남아야 하므로(R9·R16) 셸 탭과 다를 것이 시작 명령뿐이다. 그래서 Shell 에 command 만 더했다.
결정: 빌드·설치·실행을 Kotlin 이 아니라 실행 탭의 셸 스크립트가 한다 Kotlin 이 Gradle·xcodebuild 를 직접 돌리면 로그를 보일 창을 따로 만들어야 하고, 사용자가 Ctrl+C 로 멈추거나 끝난 뒤 같은 폴더에서 명령을 이어 칠 수 없다. 데이터 계층은 스크립트 문자열만 만들고(순수 함수라 테스트한다) 실행은 pty 가 한다. 스크립트는 /bin/sh -c 로 돌려 사용자 셸(zsh 의 단어 분할 등)에 흔들리지 않게 하고, 그 바깥은 로그인·대화형 셸이라 ~/.zshrc 의 JAVA_HOME·PATH 가 들어온다.
결정: 빌드 변형은 Gradle 에 묻는다 build.gradle(.kts) 를 정규식으로 읽는 안은 convention plugin·version catalog alias(alias(libs.plugins.androidApplication))·flavor 조합을 따라가지 못한다. init script 로 androidComponents.onVariants 를 걸고 help 를 돌리면 모듈 경로·변형·applicationId 를 정확히 받는다(데몬이 떠 있으면 이 저장소에서 약 3.6초). 설정 캐시가 켜진 저장소는 캐시 적중 때 onVariants 가 돌지 않으므로 --no-configuration-cache 를 준다. 결과는 빌드 파일 수정 시각이 같으면 앱이 켜져 있는 동안 다시 쓴다.
결정: 명령 목록은 최상위 패널에 둔다 후보는 (1) 저장소 폴더(git common dir) 키로 따로 저장, (2) 저장소 안 orca.yaml 같은 파일, (3) 최상위 패널. (2) 는 저장소에 파일을 쓰게 되고 사용자가 원한 "패널마다" 와 다르다. (1) 은 패널을 닫아도 남아 정리 시점이 없다. 워크트리 패널은 이미 최상위 패널 아래 한 단계로 묶여 있으므로(워크트리) (3) 을 택했다. 작업 공간 파일에 함께 저장돼 R14 의 저장·복원이 따로 필요 없다.
결정: 기기 목록은 기존 DeviceScreens 이음새로 받는다 실행 창은 꺼진 AVD·꺼진 시뮬레이터·실물 iOS 까지 필요한데 choices() 는 화면을 볼 수 있는 것만 준다. 터미널이 adb·simctl 을 따로 돌리는 안은 emulator 기능의 목록 코드를 되풀이한다. 같은 인터페이스에 runTargets() 를 더해 emulator 가 같은 목록에서 걸러 주게 했다.

한계

  • 빌드 변형을 처음 읽을 때는 Gradle 데몬이 떠야 해서 수십 초 걸릴 수 있다. 그 동안 창은 "빌드 변형을 읽는 중…" 이다.
  • 실행 탭은 install<변형> 태스크를 쓰므로 서명 설정이 없는 release 는 Gradle 이 실패를 찍고 멈춘다.
  • 런처 액티비티가 없는 앱(라이브러리성 앱, TV 전용 LEANBACK)은 설치만 되고 "▶ 앱 실행" 단계에서 실패를 찍는다.
  • iOS 실물 기기는 서명 팀이 프로젝트에 정해져 있어야 한다. 기기가 잠겨 있으면 devicectl 실행이 실패한다(JVM 한계).
  • 스킴에 앱 타깃이 여럿이면 만든 .app 중 이름순 첫 것을 설치한다.
  • 꺼진 AVD 를 이미 다른 창에서 켜는 중이면 에뮬레이터가 둘 뜨려다 하나가 실패한다. 실행 스크립트는 켜진 것을 이름으로 찾아 쓴다.
