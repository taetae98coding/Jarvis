계산기 (수식·퍼센트·BMI)

홈의 "계산기" 카드를 누르면 수식을 치는 대로 답이 보이는 계산기, 자주 쓰는 퍼센트 계산 세 가지, 대한비만학회 기준 BMI 를 한 화면의 탭으로 쓴다.

사용자 지시

사람들이 많이 접속하는 url이나 appStore, playStore 다운로드 순위 참고해서 구현할 도구들 조사 후 추가해줘.

2026-09-26 대화.
왜 이 기능인가 Similarweb 2026년 8월 자료에서 calculator.net 은 미국 Science & Education > Math 분야 1위다(최근 3개월 방문 약 4,200만, 전 세계 순위 약 1,135위). 이 사이트로 들어오는 상위 검색어는 "time calculator", "calorie calculator", "bmi calculator", "calculator", "age calculator" 이고, 비슷한 사이트로 calculatorsoup.com·omnicalculator.com·percentagecalculator.net 이 꼽힌다. 앱 스토어에서도 계산기는 가장 흔한 유틸리티 앱이고(예: 수식을 적어 가며 계산하는 CalcNote), 사람들이 가장 자주 찾는 것은 결국 일반 계산·퍼센트·BMI 다. 그래서 이 세 가지를 한 화면에 모은다. 셈은 순수 Kotlin 이라 Android·iOS·macOS·Web 네 곳에서 같은 답을 낸다.

요구사항

  1. R1. 홈 그리드 끝에 "계산기" 카드가 있고, 누르면 계산기 화면으로 간다. 화면의 뒤로 버튼은 홈으로 돌아간다.
  2. R2. 화면 위쪽 탭 셋(계산기, 퍼센트, BMI)으로 도구를 고른다. 고른 탭 하나만 선택 상태다.
  3. R3. 계산기 탭의 입력 칸에 수식을 직접 치거나 자판 버튼(숫자 0–9, ., + − × ÷, ^, %, 괄호 ( ))으로 넣는다. 자판 버튼은 커서 자리에 글자를 넣고(선택한 글자가 있으면 바꾸고), 지우기 버튼은 커서 앞 한 글자(선택이 있으면 선택)를 지우며, C 는 입력을 비운다.
  4. R4. 수식은 치는 대로 계산해 입력 칸 아래에 답을 보인다. 우선순위는 괄호 > %(뒤붙이) > ^(오른쪽 결합) > 단항 −·+ > × ÷ > + − 이다. 그래서 -2^2 = -4, 2^3^2 = 512, 2^-1 = 0.5 다. 숫자·닫는 괄호 바로 뒤의 여는 괄호는 곱셈이다(2(3+4) = 14). * / - 와 × ÷ − 를 같게 읽고 공백은 무시한다. R6 이 적는 지수 꼴(1.5e20, 1E-10)도 숫자로 읽어, = 로 입력 칸에 들어간 답을 이어서 셈할 수 있다.
  5. R5. 셈할 수 없는 수식은 예외 없이 오류 상태가 되고 까닭을 보인다: 끝나지 않은 식(3+), 닫히지 않은 괄호, 짝 없는 닫는 괄호, 잘못된 숫자(1.2.3), 읽을 수 없는 글자, 0 으로 나누기, 무한대·정의되지 않는 결과(10^400, (-8)^0.5), 괄호가 100 단계를 넘는 중첩. 끝나지 않은 식과 닫히지 않은 괄호는 아직 치는 중인 상태라 흐린 글자로, 나머지는 오류 색으로 보인다. 입력이 비면 답 줄이 없다.
  6. R6. 답은 부동소수점 잡음 없이 보인다: 유효 숫자 12자리로 반올림하고 뒤쪽 0 과 소수점을 지운다(0.1+0.2 = 0.3, 1/3 = 0.333333333333). 1015 보다 작은 정수는 자릿수를 잃지 않고 그대로 보인다. 절댓값이 1015 이상이거나 10-9 미만이면 1.5e20 꼴로, 그 사이는 지수 없이 보인다. -0 은 0 이다. 자릿수 쉼표는 넣지 않는다.
  7. R7. = 버튼(또는 입력 칸에서 Enter·완료 키)을 누르면 답이 있을 때 입력 칸이 답으로 바뀌고 그 수식이 최근 기록 맨 위에 들어간다. 오류면 아무것도 바뀌지 않는다.
  8. R8. 최근 기록은 20 개까지 새것부터 보이고, 같은 수식을 다시 계산하면 옛 줄을 지우고 맨 위로 올린다. 수식의 연속 공백은 하나로 줄여 적는다. 줄을 누르면 그 수식이 입력 칸에 들어가고, "기록 지우기" 는 기록을 모두 지운다. 기록이 없으면 "아직 계산한 식이 없습니다" 를 보인다.
  9. R9. 답 옆의 복사 버튼은 답을 시스템 클립보드에 넣는다. 답이 없으면(빈 입력·오류) 복사 버튼이 없다.
  10. R10. 퍼센트 탭은 percentagecalculator.net 의 세 가지 꼴을 한꺼번에 보인다. 칸마다 숫자(-·소수점 허용, 쉼표 불허)를 넣는다.
    • "X 의 Y% 는?" → X × Y ÷ 100
    • "X 는 Y 의 몇 %?" → X ÷ Y × 100 뒤에 %. Y 가 0 이면 오류
    • "X 에서 Y 로 몇 % 증감?" → (Y − X) ÷ |X| × 100. 양수면 "n% 증가", 음수면 "n% 감소"(n 은 절댓값), 0 이면 "변화 없음". X 가 0 이면 오류
    두 칸 중 하나라도 비면 그 꼴의 답은 없고, 숫자가 아니면 어느 칸이 잘못됐는지 보인다. 답은 R6 과 같게 적는다.
  11. R11. BMI 탭은 키(cm)와 몸무게(kg)로 몸무게 ÷ (키/100)2 를 소수 첫째 자리까지 반올림해 보이고, 반올림한 값으로 대한비만학회 성인 기준 단계를 보인다: <18.5 저체중, 18.5–22.9 정상, 23–24.9 비만 전단계, 25–29.9 1단계 비만, 30–34.9 2단계 비만, ≥35 3단계 비만. 그 키에서 정상(18.5–22.9)에 드는 몸무게 범위도 보이고, 어떤 기준인지 화면에 적는다. 키는 30–300 cm, 몸무게는 1–500 kg 을 벗어나면 그 칸이 잘못됐다고 보인다.
  12. R12. 마지막에 고른 탭, 칸마다의 입력(계산기 수식, 퍼센트 여섯 칸, 키·몸무게), 최근 기록이 앱을 껐다 켜도 남는다.
스코프에서 뺀 것
  • 시간·나이·칼로리 계산기. calculator.net 상위 검색어에 있지만 시간대·날짜 계산은 kotlinx-datetime 을 새로 들여야 하고, 칼로리는 활동량 표·공식 선택이 따로 필요한 별도 기능이다. 탭을 더하는 식으로 넓힐 수 있게 CalculatorTab 을 열거형으로 두었다.
  • 삼각함수·로그 같은 공학 계산. 자판이 두 배가 되고 각도 단위 상태가 생긴다. 파서에 함수 호출 규칙만 더하면 되므로 필요해지면 그때 넣는다.
  • 폰 계산기식 %(50+10% = 55). % 는 언제나 "÷100" 이고(50+10% = 50.1), 증감 계산은 퍼센트 탭이 맡는다. 문맥에 따라 뜻이 바뀌는 규칙은 수식만 보고 답을 예측할 수 없게 한다.
  • 임의 정밀도(BigDecimal). 공통 stdlib 에 없고 domain 은 새 의존을 들이지 않는다(모듈 구조). Double 로 셈하고 R6 의 반올림으로 잡음을 가린다.
  • 아동·청소년 BMI 백분위. 성별·나이별 성장 도표가 필요하다. 화면에 "성인 기준" 이라고 적는다.

상태
탭·칸 입력·기록은 저장소의 Flow 를 유스케이스가 stateIn(viewModelScope, WhileSubscribed(), read…()) 한다. 기록은 수식만 저장하고 읽을 때 다시 셈해 답을 붙인다. 답은 (저장된 입력 + 화면이 방금 넘긴 입력) 을 combine 해 셈한 값이다.

결정: 파서를 domain 의 순수 Kotlin 재귀 하강으로 짠다 domain 은 kotlinx-coroutines-core·koin-core 만 쓴다. 문법은 expr := term (± term)*, term := unary ((×|÷|암묵 곱) unary)*, unary := (−|+) unary | power, power := postfix (^ unary)?, postfix := primary %*, primary := 숫자(e±n 지수 포함) | ( expr ) 이다. 단항 부호를 ^ 보다 낮게 두어 수학 관례대로 -2^2 = -4 가 되고, 지수 쪽은 unary 라 2^-1 을 받는다. 오류는 CalculationResult.Error 로 돌려주고 던지지 않는다. 치는 동안 매 글자마다 셈하므로 예외를 흐름 제어에 쓰지 않는다. 중첩은 100 단계에서 멈춰 스택이 넘치지 않게 한다. JavaScript 식 eval·스크립트 엔진은 Web 에만 있고 임의 코드를 돌리므로 버렸다.
결정: 숫자는 직접 적는다 Double.toString() 은 타깃마다 다르다(JVM 은 1.0E10, JS·Wasm 은 10000000000). String.format 은 공통 stdlib 에 없다. 그래서 CalculatorNumberFormat 이 10진 지수를 구해 유효 숫자 12자리 정수로 반올림한 뒤 소수점을 손으로 찍는다. 12자리는 0.1+0.2·1-0.9·1.1×3 의 끝자리 잡음(대략 16번째 자리)을 가리면서 일상 계산에 충분하다. 15자리로 하면 1-0.9 가 0.0999999999999998 로 보여 버렸다. 대신 정수는 12자리를 넘어도 그대로 보이도록 따로 적는다.
결정: 입력 칸은 화면이 들고, 저장소는 뒤따라 적는다 개발자 도구와 같다. 입력 칸이 저장소 Flow 를 곧장 보여 주면 저장 신호가 늦게 돌아올 때 친 글자가 옛 값에 덮인다. 칸마다 TextFieldState 를 한 번 채워 스스로 들고, 바뀔 때마다 SetCalculatorInputUseCase 로 적는다. 자판·=·기록 누르기도 입력 칸에 직접 쓰고 같은 길로 저장된다. 답은 ViewModel 이 칸마다 마지막으로 받은 입력으로 셈한다.
결정: BMI 단계는 반올림한 값으로 가른다 기준표가 "18.5–22.9", "23–24.9" 처럼 소수 첫째 자리로 적혀 있어, 22.95 를 22.9(정상)로 보이면서 비만 전단계로 가르면 화면이 스스로 모순된다. 소수 첫째 자리 정수(229)로 반올림한 뒤 정수끼리 비교한다.

한계

  • Double 셈이라 유효 숫자 15–16자리를 넘는 정수(2^60+1)는 끝자리가 틀린다. 유효 숫자 12자리 반올림은 표시만 바꾸고, = 로 입력 칸에 들어간 답을 다시 셈하면 반올림한 값으로 이어진다.
  • Web 은 HTTPS·localhost 가 아니면 복사가 조용히 실패한다(web.html).
