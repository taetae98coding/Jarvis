공통 스펙

플랫폼과 무관하게 성립해야 하는 것들. 각 기능 문서는 사용자 지시에서 출발해 요구사항, 화면·동작, 공통 구현, 검증 순으로 내려간다.

기능 목록

  • 모듈 구조

    domain / data / ui 계층 모듈과 조립 모듈, 패키지 규칙

  • 앱 정보 카드

    앱 버전과 실행 중인 플랫폼을 보여준다

  • 화면 꺼짐 방지

    토글이 켜져 있는 동안 화면이 꺼지지 않게 한다

  • 화면 꺼짐 방지 (시스템 전역)

    앱이 없는 동안에도 화면이 꺼지지 않게 한다. Android만 가능하다

  • 설정 영구 저장

    토글 값이 앱을 껐다 켜도 남고, 외부 변경도 따라간다

  • 상태 조회 규칙

    콜백이 있으면 콜백으로, 없으면 N초마다 다시 읽는다

  • 에뮬레이터 개수

    개발자 머신의 Android 에뮬레이터·iOS 시뮬레이터를 실행 중/전체로 센다

  • 에뮬레이터 목록·화면·제스처

    가상 기기 목록을 보고, 실행 중인 기기의 화면을 보면서 탭·스와이프를 보낸다

  • 카드 물결 효과

    누를 수 있는 카드의 물결이 카드의 둥근 모서리 안에서만 퍼진다

  • 화면 회전

    화면을 0·90·180·270도로 돌리고 그 각도에 고정한다

모듈

공용 코드는 :domain(모델·규칙) · :data(플랫폼 구현) · :ui(Compose 화면) 세 모듈로 나뉘고, :shared는 셋을 조립해 App()과 플랫폼 진입점만 내놓는다. 의존은 한 방향이고 Gradle이 강제한다. 자세한 규칙과 패키지 배치는 모듈 구조에 있다.

:shared        App(), MainViewController(), JarvisContainer
  ├─ :ui       Compose 화면. :domain 만 본다
  ├─ :data     플랫폼 API, 저장소, 직렬화. :domain 만 본다
  └─ :domain   모델, 리포지토리 인터페이스, 유스케이스. 아무것도 안 본다

공통 규약

플랫폼 의존 코드는 전부 :data의 expect 선언으로 시작한다. 공용 코드는 expect 시그니처만 알고, 실제 API 호출은 각 <target>Main의 actual이 맡는다. :domain과 :ui에는 expect 선언이 없다.

expect패키지역할기능
platformName: Stringdata.appinfo실행 중인 플랫폼 표시용 문자열앱 정보 카드
createIdleInhibitor(): IdleInhibitordata.screenCompose가 커버하지 않는 플랫폼의 화면 꺼짐 방지. JVM만 본문이 있다화면 꺼짐 방지
createSystemScreenAwakeDataSource(context): SystemScreenAwakeDataSourcedata.screen앱이 없는 동안의 화면 유지. 상태를 읽고 효과를 적용한다. Android만 본문이 있다화면 꺼짐 방지 (시스템 전역)
createSettingsStore(context): SettingsStoredata.settings설정을 영구 저장하고 변경을 알리는 키-값 저장소설정 영구 저장
emulatorDataSource: EmulatorDataSourcedata.emulatorAndroid 에뮬레이터·iOS 시뮬레이터의 개수·목록·화면을 흘려보내고 제스처를 전달하는 데이터 소스. JVM은 SDK 도구를 직접 실행하고 나머지는 로컬 에이전트에 묻는다에뮬레이터 개수, 목록·화면·제스처

class PlatformContextdata플랫폼 핸들 상자. Android만 Context를 담고 나머지는 빈 클래스다모듈 구조

한 타깃에서만 가능한 기능이라면 나머지 actual을 "지원하지 않음"으로 둔다. createIdleInhibitor()는 JVM 외에서 NoIdleInhibitor를, createSystemScreenAwakeDataSource()는 Android 외에서 UnsupportedSystemScreenAwakeDataSource를, createDeviceRotationDataSource()는 JVM에서 UnsupportedDeviceRotationDataSource를 돌려준다. 화면 구성을 플랫폼마다 갈라지게 하지 않기 위한 선택이고, 카드를 감추는 대신 잠긴 채로 이유를 보여준다.

Modifier.keepScreenAwake(enabled)만 expect가 아니라 :ui에 있다. Compose의 Modifier.keepScreenOn()이 플랫폼 API를 대신 불러 주기 때문이고, 이 예외는 모듈 구조에 적혀 있다.

Flow로 노출하는 상태는 expect 여부와 별개로 상태 조회 규칙을 따른다.

앱 구조

화면은 하나다. 상단 Card에 앱 버전과 플랫폼을 보여주고, 하단 Grid에 기능 아이템을 나열한다. Grid는 GridCells.Adaptive(minSize = 220.dp)라 창 너비에 따라 열 수가 늘어난다.

App()                                    ← :shared. 컨테이너를 만들어 넘기는 것이 전부
└─ JarvisApp(state)                      ← :ui
   └─ MaterialTheme
      ├─ LaunchedEffect { state.applyEffects() }   ← 설정을 따라 플랫폼 효과 적용
      └─ Surface(Modifier.keepScreenAwake(keepScreenAwake))   ← 루트, 화면 수명과 무관
         └─ Column
            ├─ AppInfoCard(appInfo)
            └─ FeatureGrid(state)
               ├─ ScreenAwakeCard "화면 꺼짐 방지"
               ├─ SystemScreenAwakeCard "화면 꺼짐 방지 (시스템 전역)"
               ├─ EmulatorCard(emulatorStatus)
               └─ DeviceRotationCard(deviceRotation) "화면 회전"

플랫폼 효과는 MaterialTheme 안쪽이지만 카드보다 위인 LaunchedEffect 하나에서 적용한다. 효과가 카드의 수명보다 오래 살아야 해서다. 무엇을 언제 적용할지는 화면이 아니라 :domain의 ApplyKeepScreenAwakeUseCase·ApplySystemScreenAwakeUseCase가 정한다.

앱 범위 상태는 :ui의 JarvisAppState가 들고 FeatureGrid로 내려간다. App() 최상단에서 한 번 만들어지므로 화면을 옮겨 다녀도 값과 효과가 유지된다. 테스트는 JarvisAppState에 가짜 리포지토리로 만든 유스케이스를 끼운다. 예전의 AppSettings와 LocalAppSettings는 JarvisAppState로 합쳐졌다. 화면이 하나뿐이라 CompositionLocal로 내려보낼 이유가 없고, 상태를 만드는 곳과 쓰는 곳이 한 모듈에 있는 편이 읽기 쉽다.

모든 플랫폼에 공통인 한계

앱이 떠 있지 않으면 화면을 켜 둘 수 없다 (Android 제외)

모바일·브라우저 OS는 화면 꺼짐 방지를 "지금 보이는 앱"의 권한으로 취급하고, 앱이 물러나면 회수한다. 그래서 앱 수명 내 화면 꺼짐 방지에서 영구 저장되는 것은 설정값이고, 효과는 앱이 다시 떠 있을 때 재적용된다. 플랫폼별 근거는 Android, iOS, JVM, Web 문서에 있다.

예외는 Android다. 앱에 주어지는 권한 대신 시스템 전역 설정을 바꾸는 길이 열려 있어서, 시스템 전역 토글이 앱이 없는 동안에도 화면을 켜 둔다. 마켓 심사를 통과하기 어려운 권한을 쓰므로 사이드로드 전제다. iOS·JVM·Web은 배포 방식을 포기해도 열리지 않는다.

SettingsStore는 동기 API다

:data SettingsStore의 읽기·쓰기는 동기다. 리포지토리가 첫 값을 동기로 읽어 화면의 첫 프레임에 넘기므로 boolean 몇 개까지는 문제가 없지만, 다음 경우에는 맞지 않는다.

  • 값이 커지거나 많아져 읽기가 프레임을 막는 경우
  • 마이그레이션이나 트랜잭션이 필요한 경우

그때는 SettingsStore 구현만 androidx.datastore로 갈아끼운다. DataStore 1.2.1은 android/jvm/ios/wasmJs 변형을 모두 퍼블리시하지만, Web 쪽은 Storage 구현을 직접 넣어야 해서 boolean 두 개뿐인 현 시점에는 채택하지 않았다.

boolean이 아닌 값이 필요해진 예는 이미 하나 있다. 시스템 전역 화면 유지가 되돌릴 화면 꺼짐 시간(Int)을 SettingsStore가 아니라 Android 전용 SharedPreferences 파일에 따로 보관한다. 사용자 설정이 아니라 내부 기록이라 섞지 않은 것이기도 하다.

플랫폼 저장소 구현은 자동 테스트가 없다

테스트는 InMemorySettingsStore를 주입해 DefaultScreenAwakeSettingsRepository의 읽기·쓰기·변경 구독 계약만 검증한다. 실제 SharedPreferences / NSUserDefaults / Preferences / localStorage 왕복은 컴파일로만 보장된다. java.util.prefs만 개발 머신에서 직접 왕복 확인했다.

셀 수 없는 것은 숨기지도, 0으로 보여주지도 않는다

화면을 플랫폼마다 갈라지게 하지 않으려고, 셀 수 없는 타깃에서도 에뮬레이터 카드는 같은 자리에 남는다. 대신 숫자를 꾸며내지는 않는다. EmulatorSummary?의 null이 "셀 수 없음"이고 화면에도 그렇게 나온다.

예전에는 셀 수 없는 타깃이 0개를 답했고, 그래서 "0개"와 "셀 수 없음"이 화면에서 같아 보였다. 로컬 에이전트를 붙이면서 "데스크톱 앱이 꺼져 있음"이 흔한 상태가 되어 그 구분을 더 미룰 수 없었다. 지금 화면의 0은 정말 0개라는 뜻이다. 다만 JVM에서 SDK는 있는데 개별 명령이 실패하면 여전히 0개로 보인다.
