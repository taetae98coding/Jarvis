공통 스펙

플랫폼과 무관하게 성립해야 하는 것들. 각 기능 문서는 사용자 지시에서 출발해 요구사항, 화면·동작, 공통 구현, 검증 순으로 내려간다.

기능 목록

  • 모듈 구조

    기능마다 domain / data / ui 모듈, core 와 앱 셸, 빌드 컨벤션 플러그인

  • 의존성 주입

    Koin 모듈로 리포지토리·유스케이스·ViewModel·라우트를 등록하고 주입한다

  • 화면 상태 소유 (ViewModel)

    화면 하나가 쓰는 상태와 유스케이스 호출을 ViewModel 이 소유한다

  • 화면 이동 (Navigation3)

    홈·기기 목록·기기 화면 사이를 백스택과 NavDisplay 로 옮긴다

  • 재생성을 넘기는 상태 (retain)

    마지막 프레임을 컴포지션보다 오래 들고 있는다

  • 앱 정보 카드

    앱 버전과 실행 중인 플랫폼을 보여준다

  • 화면 꺼짐 방지

    토글이 켜져 있는 동안 화면이 꺼지지 않게 한다

  • 화면 꺼짐 방지 (시스템 전역)

    앱이 없는 동안에도 화면이 꺼지지 않게 한다. Android만 가능하다

  • 설정 영구 저장

    토글 값이 앱을 껐다 켜도 남고, 외부 변경도 따라간다

  • 상태 조회 규칙

    콜백이 있으면 콜백으로, 없으면 N초마다 다시 읽는다

  • 에뮬레이터 개수

    개발자 머신의 Android 에뮬레이터·iOS 시뮬레이터를 실행 중/전체로 센다

  • 기기 목록·화면·제스처

    가상 기기와 연결된 실물 기기 목록을 보고, 화면을 보면서 탭·스와이프를 보낸다

  • 꺼진 에뮬레이터 실행

    목록에서 꺼져 있는 AVD·시뮬레이터를 그 자리에서 켠다

  • 꺼진 화면 깨우기

    연결은 됐지만 화면이 꺼진 기기를 목록에서 알아보고 켠다

  • Wi-Fi 기기 페어링

    QR 코드나 6자리 코드로 실물 Android 기기를 케이블 없이 adb 에 붙인다. iPhone·iPad 는 불가

  • 기기 목록 좌우 분할

    기기 목록을 두 열로 나눠 왼쪽에 Android, 오른쪽에 iOS 기기를 둔다

  • 카드 물결 효과

    누를 수 있는 카드의 물결이 카드의 둥근 모서리 안에서만 퍼진다

  • 화면 회전

    화면을 0·90·180·270도로 돌리고 그 각도에 고정한다

  • 홈 화면 위젯

    Android 홈 화면에서 앱을 열지 않고 화면 회전과 시스템 전역 화면 꺼짐 방지를 조작한다

  • 홈 그리드 세로 배치

    높이가 제각각인 기능 카드를 행으로 묶지 않고 가장 짧은 열에 이어 붙인다

  • 디자인 시스템

    M3 위의 JarvisTheme 토큰, *Defaults 와 Style 로 정의한 컴포넌트, ImageVector 아이콘

  • 터미널

    iTerm 처럼 셸을 띄우고 좌우·상하 분할과 탭을 쓴다. JVM 은 pty, Android 는 파이프, iOS·Web 은 불가

  • 터미널에서 Claude 실행

    터미널 새 탭(+) 메뉴에서 골라 새 탭에 Claude Code 를 YOLO 모드로 띄운다. JVM 만 가능

  • 터미널 패널과 세션 유지

    왼쪽 패널 목록에 패널마다 탭·분할을 두고, 배치·작업 디렉터리·Claude sessionId 를 앱을 다시 켜도 유지한다. Claude 는 백그라운드에서 계속 일한다

  • 탭 끌어 놓기 분할

    상단 막대의 동작 버튼을 없애고, 새 탭은 탭 줄 끝의 + 로, 좌우·상하 분할은 탭을 창의 변에 끌어 놓아 정한다

  • 분할 그룹마다 탭 줄

    패널을 나눈 칸(그룹)마다 자기 탭 줄을 두고, 탭은 그 그룹의 + 로 붙이고 ✕ 로 닫는다. 탭 하나가 창 하나다

  • 터미널에서 웹 브라우저

    새 탭(+) 메뉴에서 골라 그 그룹에 웹 페이지 탭을 연다. 시스템 웹뷰를 쓰고 마지막 주소를 저장한다. JVM(macOS)·Android

  • 터미널에서 기기 화면

    새 탭(+) 메뉴에 화면을 볼 수 있는 에뮬레이터·실물 기기가 나오고, 고르면 그 그룹에 기기 화면 탭을 열어 탭·스와이프를 보낸다. JVM(macOS)·Android

  • Chrome 쿠키 가져오기

    브라우저 탭 주소 줄의 버튼으로 이 PC 의 Chrome 프로필을 골라 모든 사이트 쿠키를 웹뷰로 옮긴다. 영구 저장소라 앱을 껐다 켜도 로그인이 이어진다. JVM(macOS)

  • 기기 화면 영상 스트림·호버

    Android 기기 화면을 기기 안 에이전트의 H.264 영상으로 받고, 누름·끌기·마우스 호버를 그 자리에서 기기에 넣는다. Android Studio 의 Running Devices 와 같은 구조

  • 새 패널 제목·폴더

    "새 패널" 이 제목(비우면 "패널 N")과 폴더를 받는 창을 띄우고, "확인" 이 그 제목·폴더의 빈 패널을 만든다. 탭은 빈 패널의 + 로 그 폴더에서 연다

  • 패널에서 git 워크트리 추가

    git 저장소 폴더의 패널에 + 가 붙고, 브랜치를 받아 git worktree add 로 만든 워크트리를 그 패널 아래 들여쓴 빈 패널로 연다. JVM(macOS)

모듈

공용 코드는 기능마다 domain(모델·규칙) · data(플랫폼 구현) · ui(Compose 화면) 세 모듈을 갖는다. Android 홈 화면 위젯이 있는 기능(rotation, screen)은 Android 전용 widget 모듈을 하나 더 갖는다(홈 화면 위젯). 기능은 appinfo, emulator, screen, rotation, terminal 다섯이고 서로를 의존하지 않는다. 의존은 한 방향이고 Gradle이 강제한다. 자세한 규칙과 패키지 배치는 모듈 구조, 조립 규칙은 의존성 주입에 있다.

:shared                  App(), MainViewController(), startJarvisKoin(), platformModule
└─ :app:ui               JarvisApp(), Home 화면, FeatureGrid, 백스택
   ├─ :feature:<기능>:ui     카드·화면, ViewModel, 라우트. 같은 기능의 domain 만 본다
   │  └─ :feature:<기능>:domain  모델, 리포지토리 인터페이스, 유스케이스. 아무것도 안 본다
   │     └─ :feature:<기능>:data 플랫폼 API, 저장소, 직렬화. :shared 가 조립한다
   ├─ :core:ui / :core:data  두 기능 이상이 쓰는 것만(ToggleFeatureCard, Navigator, PlatformContext)
   └─ :core:designsystem    JarvisTheme, JarvisIcons, Jarvis* 컴포넌트. 모든 ui 모듈이 본다

공통 규약

플랫폼 의존 코드는 전부 data 모듈의 expect 선언으로 시작한다. 공용 코드는 expect 시그니처만 알고, 실제 API 호출은 각 <target>Main의 actual이 맡는다. domain과 ui 모듈에는 expect 선언이 없다. expect/actual 은 한 모듈 안에서만 짝이 맞으므로, 아래 표의 패키지가 곧 그 선언이 사는 모듈이다.

한 타깃에서만 가능한 기능이라면 나머지 actual을 "지원하지 않음"으로 둔다. createIdleInhibitor()는 JVM 외에서 NoIdleInhibitor를, createSystemScreenAwakeDataSource()는 Android 외에서 UnsupportedSystemScreenAwakeDataSource를, createDeviceRotationDataSource()는 Android 외에서 UnsupportedDeviceRotationDataSource를, createTerminalDataSource()는 iOS·Web에서 UnsupportedTerminalDataSource를 돌려준다. 화면 구성을 플랫폼마다 갈라지게 하지 않기 위한 선택이고, 카드를 감추는 대신 잠긴 채로 이유를 보여준다.

Modifier.keepScreenAwake(enabled)만 expect가 아니라 :ui에 있다. Compose의 Modifier.keepScreenOn()이 플랫폼 API를 대신 불러 주기 때문이고, 이 예외는 모듈 구조에 적혀 있다.

Flow로 노출하는 상태는 expect 여부와 별개로 상태 조회 규칙을 따른다.

앱 구조

화면은 넷이다. 홈은 상단 Card에 앱 버전과 플랫폼을 보여주고 하단 Grid에 기능 아이템을 나열한다. Grid는 StaggeredGridCells.Adaptive(minSize = 220.dp)라 창 너비에 따라 열 수가 늘어나고, 카드 높이가 제각각이라 행으로 묶지 않고 가장 짧은 열에 이어 붙인다. 나머지는 에뮬레이터 카드에서 들어가는 기기 목록과 기기 화면, 터미널 카드에서 들어가는 터미널이고, 그 사이의 이동은 Navigation3 의 백스택이 맡는다.

App()                                    ← :shared. JarvisApp() 을 부르는 것이 전부
└─ JarvisApp()                           ← :app:ui
   └─ MaterialTheme
      └─ Surface(Modifier.appScreenAwake())   ← 루트, 화면 수명과 무관. :feature:screen:ui
         └─ NavDisplay(backStack, entryProvider = koinEntryProvider())
            ├─ Home            HomeScreen()            ← :app:ui
            │  ├─ AppInfoCard()                        ← :feature:appinfo:ui
            │  └─ FeatureGrid()
            │     ├─ ScreenAwakeCard() "화면 꺼짐 방지"           ← :feature:screen:ui
            │     ├─ SystemScreenAwakeCard() "시스템 전역"        ← :feature:screen:ui
            │     ├─ EmulatorCard()                              ← :feature:emulator:ui
            │     ├─ DeviceRotationCard() "화면 회전"             ← :feature:rotation:ui
            │     └─ TerminalCard() "터미널"                      ← :feature:terminal:ui
            ├─ EmulatorRoute.Devices  EmulatorListScreen()   ← :feature:emulator:ui
            ├─ EmulatorRoute.Screen   EmulatorStreamScreen() ← :feature:emulator:ui
            └─ TerminalRoute          TerminalScreen()       ← :feature:terminal:ui

카드는 인자를 받지 않는다. 각 카드가 자기 기능의 ViewModel 을 Koin 에서 직접 받으므로 앱 셸은 그 기능의 유스케이스도 상태도 모른다. 플랫폼 효과는 Modifier.appScreenAwake() 안의 앱 수명 ViewModel 이 적용하고, 무엇을 언제 적용할지는 화면이 아니라 domain 의 ApplyKeepScreenAwakeUseCase·ApplySystemScreenAwakeUseCase가 정한다.

화면 상태는 ViewModel 여덟이 나눠 갖는다. 앱 범위 값(화면 꺼짐 방지 효과)은 ScreenAwakeEffectViewModel이, 화면별 값은 그 화면 엔트리의 ViewModel 이 들고 엔트리가 빠질 때 함께 정리된다. 예전에는 JarvisAppState 하나가 전부를 들고 App() 최상단에서 만들어졌다. 테스트는 상태 객체가 아니라 가짜 리포지토리를 담은 Koin 모듈을 끼운다.

모든 플랫폼에 공통인 한계

앱이 떠 있지 않으면 화면을 켜 둘 수 없다 (Android 제외)

모바일·브라우저 OS는 화면 꺼짐 방지를 "지금 보이는 앱"의 권한으로 취급하고, 앱이 물러나면 회수한다. 그래서 앱 수명 내 화면 꺼짐 방지에서 영구 저장되는 것은 설정값이고, 효과는 앱이 다시 떠 있을 때 재적용된다. 플랫폼별 근거는 Android, iOS, JVM, Web 문서에 있다.

예외는 Android다. 앱에 주어지는 권한 대신 시스템 전역 설정을 바꾸는 길이 열려 있어서, 시스템 전역 토글이 앱이 없는 동안에도 화면을 켜 둔다. 마켓 심사를 통과하기 어려운 권한을 쓰므로 사이드로드 전제다. iOS·JVM·Web은 배포 방식을 포기해도 열리지 않는다.

SettingsStore는 동기 API다

:feature:screen:data SettingsStore의 읽기·쓰기는 동기다. 리포지토리가 첫 값을 동기로 읽어 화면의 첫 프레임에 넘기므로 boolean 몇 개까지는 문제가 없지만, 다음 경우에는 맞지 않는다.

  • 값이 커지거나 많아져 읽기가 프레임을 막는 경우
  • 마이그레이션이나 트랜잭션이 필요한 경우

그때는 SettingsStore 구현만 androidx.datastore로 갈아끼운다. DataStore 1.2.1은 android/jvm/ios/wasmJs 변형을 모두 퍼블리시하지만, Web 쪽은 Storage 구현을 직접 넣어야 해서 boolean 두 개뿐인 현 시점에는 채택하지 않았다.

boolean이 아닌 값이 필요해진 예는 이미 하나 있다. 시스템 전역 화면 유지가 되돌릴 화면 꺼짐 시간(Int)을 SettingsStore가 아니라 Android 전용 SharedPreferences 파일에 따로 보관한다. 사용자 설정이 아니라 내부 기록이라 섞지 않은 것이기도 하다.

플랫폼 저장소 구현은 자동 테스트가 없다

테스트는 InMemorySettingsStore를 주입해 DefaultScreenAwakeSettingsRepository의 읽기·쓰기·변경 구독 계약만 검증한다. 실제 SharedPreferences / NSUserDefaults / Preferences / localStorage 왕복은 컴파일로만 보장된다. java.util.prefs만 개발 머신에서 직접 왕복 확인했다.

셀 수 없는 것은 숨기지도, 0으로 보여주지도 않는다

화면을 플랫폼마다 갈라지게 하지 않으려고, 셀 수 없는 타깃에서도 에뮬레이터 카드는 같은 자리에 남는다. 대신 숫자를 꾸며내지는 않는다. EmulatorSummary?의 null이 "셀 수 없음"이고 화면에도 그렇게 나온다.

예전에는 셀 수 없는 타깃이 0개를 답했고, 그래서 "0개"와 "셀 수 없음"이 화면에서 같아 보였다. 로컬 에이전트를 붙이면서 "데스크톱 앱이 꺼져 있음"이 흔한 상태가 되어 그 구분을 더 미룰 수 없었다. 지금 화면의 0은 정말 0개라는 뜻이다. 다만 JVM에서 SDK는 있는데 개별 명령이 실패하면 여전히 0개로 보인다.
