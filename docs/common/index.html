공통 스펙

플랫폼과 무관하게 성립해야 하는 것들. 각 기능 문서는 사용자 지시에서 출발해 요구사항, 화면·동작, 공통 구현, 검증 순으로 내려간다.

기능 목록

  • 앱 정보 카드

    앱 버전과 실행 중인 플랫폼을 보여준다

  • 화면 꺼짐 방지

    토글이 켜져 있는 동안 화면이 꺼지지 않게 한다

  • 설정 영구 저장

    토글 값이 앱을 껐다 켜도 남고, 외부 변경도 따라간다

  • 에뮬레이터 개수

    이 머신의 Android 에뮬레이터·iOS 시뮬레이터를 실행 중/전체로 센다

공통 규약

플랫폼 의존 코드는 전부 io.github.taetae98coding.jarvis.shared.platform의 expect 선언으로 시작한다. 공용 코드는 expect 시그니처만 알고, 실제 API 호출은 각 <target>Main의 actual이 맡는다.

expect역할기능
platformName: String실행 중인 플랫폼 표시용 문자열앱 정보 카드
PlatformIdleInhibitor(enabled: Boolean)Compose가 커버하지 않는 플랫폼의 화면 꺼짐 방지. JVM만 본문이 있다화면 꺼짐 방지
rememberSettingsStore(): SettingsStore설정을 영구 저장하고 변경을 알리는 키-값 저장소설정 영구 저장
emulatorProbe: EmulatorProbeAndroid 에뮬레이터·iOS 시뮬레이터 개수를 흘려보내는 프로브에뮬레이터 개수

한 타깃에서만 가능한 기능이라면 나머지 actual을 빈 값으로 둔다. emulatorProbe와 PlatformIdleInhibitor가 그 예다. 화면 구성을 플랫폼마다 갈라지게 하지 않기 위한 선택이고, 이유는 각 기능 문서에 있다.

앱 구조

화면은 하나다. 상단 Card에 앱 버전과 플랫폼을 보여주고, 하단 Grid에 기능 아이템을 나열한다. Grid는 GridCells.Adaptive(minSize = 220.dp)라 창 너비에 따라 열 수가 늘어난다.

App()
└─ MaterialTheme
   └─ CompositionLocalProvider(LocalAppSettings)
      ├─ PlatformIdleInhibitor(keepScreenAwake)        ← JVM 전용 훅
      └─ Surface(Modifier.keepScreenAwake(keepScreenAwake))   ← 루트, 화면 수명과 무관
         └─ Column
            ├─ AppInfoCard
            └─ FeatureGrid(emulatorProbe)
               ├─ ToggleFeatureCard "화면 꺼짐 방지"
               └─ EmulatorCard

앱 범위 상태는 AppSettings가 들고 LocalAppSettings로 내려간다. App() 최상단에 있어 화면을 옮겨 다녀도 값과 효과가 유지되고, 새 화면은 LocalAppSettings.current로 바로 읽는다. 테스트는 App(store, probe) 오버로드에 가짜 저장소와 프로브를 끼운다.

모든 플랫폼에 공통인 한계

앱이 떠 있지 않으면 화면을 켜 둘 수 없다

어떤 플랫폼에서도 앱이 종료되거나 화면에서 내려간 상태에서 화면 꺼짐을 막을 수 없다. 모바일 OS는 화면 꺼짐 방지를 "지금 보이는 앱"의 권한으로 취급하고, 앱이 물러나면 회수한다. 따라서 영구 저장되는 것은 설정값이고, 화면 꺼짐 방지는 앱이 다시 떠 있을 때 재적용된다. 플랫폼별 근거는 Android, iOS, JVM, Web 문서에 있다.

SettingsStore는 동기 API다

SettingsStore의 읽기·쓰기는 동기다. Compose 본문에서 바로 읽으므로 boolean 몇 개까지는 문제가 없지만, 다음 경우에는 맞지 않는다.

  • 값이 커지거나 많아져 읽기가 프레임을 막는 경우
  • 마이그레이션이나 트랜잭션이 필요한 경우

그때는 SettingsStore 구현만 androidx.datastore로 갈아끼운다. DataStore 1.2.1은 android/jvm/ios/wasmJs 변형을 모두 퍼블리시하지만, Web 쪽은 Storage 구현을 직접 넣어야 해서 boolean 하나뿐인 현 시점에는 채택하지 않았다.

플랫폼 저장소 구현은 자동 테스트가 없다

테스트는 InMemorySettingsStore를 주입해 AppSettings의 읽기·쓰기·변경 구독 계약만 검증한다. 실제 SharedPreferences / NSUserDefaults / Preferences / localStorage 왕복은 컴파일로만 보장된다. java.util.prefs만 개발 머신에서 직접 왕복 확인했다.

셀 수 없는 것은 숨기지 않고 0으로 보여준다

에뮬레이터 개수는 개발자 머신의 SDK 도구를 실행해야 알 수 있어서 JVM 타깃만 실제 숫자를 낸다. 나머지 타깃에서 카드를 감추는 대신 0개로 두었다. 대신 "0개"와 "셀 수 없음"이 화면에서 같아 보인다. JVM에서도 SDK를 못 찾거나 명령이 실패하면 0개로 나온다. 구분이 필요해지면 EmulatorStatus에 지원 여부를 담아 카드에서 갈라야 한다.
