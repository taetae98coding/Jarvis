홈 그리드 세로 배치

홈의 기능 카드는 높이가 저마다 다르다. 그리드가 카드를 행 단위로 묶지 않고, 열마다 가장 짧은 자리에 이어 붙인다.

2026-09-22 대화.

요구사항

  1. R1. 카드 하나의 높이는 그 카드의 내용만으로 정해진다. 같은 줄에 놓인 다른 카드가 길다고 해서 짧은 카드가 늘어나거나, 짧은 카드 아래에 빈 공간이 남지 않는다.
  2. R2. 카드는 열마다 위에서 아래로 이어 붙는다. 새 카드는 그 시점에 가장 짧은 열의 끝에 들어간다. 결과적으로 열 사이의 카드 경계가 어긋난다(staggered).
  3. R3. 열 수는 지금과 같은 규칙으로 정해진다. 최소 너비 220dp 기준으로 창 너비에 따라 늘고 준다.
  4. R4. 카드 사이 간격은 가로·세로 모두 12dp 로 지금과 같다.
  5. R5. 카드의 순서, 테스트 태그, 클릭·토글 동작은 바뀌지 않는다. 기존 UI 테스트가 그대로 통과한다. (2026-09-26 이후 순서는 홈 적응형 배치가 지원 기능 우선으로 정하고, 이 그리드는 창이 600dp 이상일 때만 쓰인다. 태그와 동작은 그대로다.)
스코프에서 뺀 것 앱 정보 카드는 그리드 밖의 전폭 카드로 남는다. 그리드 안으로 넣어 전체를 한 스크롤로 만드는 것은 카드 순서와 스크롤 구조를 같이 바꾸는 일이라 여기서 하지 않았다. 카드 내부 레이아웃(글자 수, 버튼 배치)도 건드리지 않는다. 높이가 다른 것 자체는 고칠 문제가 아니라 그리드가 받아들여야 할 전제다.

화면·동작

항목값
대상홈의 FeatureGrid — 화면 꺼짐 방지, 시스템 전역 화면 꺼짐 방지, 에뮬레이터, 화면 회전 카드 넷
열 수카드 최소 너비 220dp. 창이 좁으면 1열, 넓어지면 2·3열로 늘어난다
배치카드는 가장 짧은 열의 끝에 붙는다. 열 하나일 때는 지금과 결과가 같다
간격가로 12dp, 세로 12dp
스크롤그리드가 세로로 스크롤한다. 앱 정보 카드는 그리드 위에 고정으로 남는다
테스트 태그기존 태그를 그대로 쓴다. 이 기능은 태그를 더하지 않는다

높이가 실제로 다른 이유는 카드 내용이다. 화면 회전 카드는 칩 네 개와 버튼 두 개를 담아 가장 길고, 화면 꺼짐 방지 카드는 제목·설명·스위치뿐이라 가장 짧다. 시스템 전역 카드는 설명이 플랫폼·권한 상태에 따라 한 줄에서 세 줄까지 오간다. 행 단위 그리드에서는 이 셋이 한 줄에 놓이면 모두 가장 긴 카드의 높이로 늘어나고, 짧은 카드 밑에 빈 공간이 생긴다.

공통 구현

파일
app/ui/src/commonMain/.../ui/app/FeatureGrid.kt
컴포저블
LazyVerticalStaggeredGrid(columns = StaggeredGridCells.Adaptive(minSize = 220.dp))
간격
가로는 horizontalArrangement = Arrangement.spacedBy(12.dp), 세로는 verticalItemSpacing = 12.dp. 세로만 Arrangement 가 아닌 것은 열마다 항목 수가 달라 열 전체를 정렬할 기준이 없기 때문이다
공급
없음. commonMain 의 Compose 코드뿐이고 expect 선언이 필요 없다
결정: 그리드 종류만 바꾼다 후보는 셋이었다.
  • 채택. LazyVerticalGrid → LazyVerticalStaggeredGrid. 항목 선언은 그대로고 verticalArrangement 만 verticalItemSpacing 으로 바뀐다. 카드도 앱 셸도 다른 곳을 고치지 않는다.
  • 카드에 최소 높이를 줘서 높이를 맞춘다. 짧은 카드에 빈 공간이 남는 것은 그대로고, 설명이 길어지면 다시 어긋난다. 버렸다.
  • Row 안에 Column 을 열 수만큼 두고 직접 분배한다. 열 수 계산과 스크롤·재활용을 손으로 다시 만들어야 해서 버렸다.
카드가 많아져 지연 로딩이 의미를 갖는 시점에도 이 선택은 그대로다. LazyVerticalStaggeredGrid 도 화면 밖 항목을 만들지 않는다.

한계

  • 배치 결과는 자동 테스트로 가리지 않는다. Compose UI 테스트는 시맨틱 트리를 보고, "빈 공간이 없다"는 픽셀·좌표의 성질이다. 좌표를 직접 비교하는 테스트는 테스트 창 크기와 글꼴 지표에 묶여 네 타깃에서 제각각 깨진다.
  • 열마다 항목 수가 달라 열의 마지막 카드 아래쪽 끝선은 서로 맞지 않는다. 이것이 staggered 의 정의고, 고칠 대상이 아니다.
  • 항목 높이가 스크롤 중에 바뀌면(설명이 늘어나는 등) 아래쪽 항목의 위치가 다시 계산되며 스크롤 위치가 미세하게 흔들릴 수 있다. 홈 카드의 높이는 사용자가 토글할 때만 바뀌고 그때는 화면 맨 위라서 지금은 드러나지 않는다.
