사용자 지시

Android 에뮬레이터와 iOS 시뮬레이터가 몇 개 있고 몇 개 켜져 있는지 보여주는 카드를 추가하라.

커밋 4c40d5e "Add emulator card showing Android and iOS device counts"에서 복원.

에뮬레이터를 켜고 끄면 앱을 다시 띄우지 않아도 숫자가 바뀌어야 한다.

커밋 c49ff47에서 복원.

emulator 같은 경우 emulator뿐만 아니라 연결된 실제 디바이스도 포함시켜줘.

2026-09-22 대화. 이 지시로 연결된 실물 기기가 두 숫자에 들어왔다. 같은 메시지의 나머지는 기기 목록과 꺼진 에뮬레이터 실행에 있다.

지금 플랫폼 별로 미구현된 기능들 있잖아. 마켓 배포 포기한다면 구현할 수 있는 기능들 있어? … 전부 진행해주고

2026-09-22 대화. 이 지시로 "셀 수 없는 타깃"이 로컬 에이전트를 통해 실제 숫자를 갖게 됐다.

요구사항

  1. R1. 카드에 Android, iOS 두 줄이 있고 각 줄은 "실행 중 N개 / 전체 M개"다.
  2. R2. "전체"는 설치된 가상 기기와 연결된 실물 기기를 더한 수, "실행 중"은 부팅된 가상 기기와 연결된 실물 기기를 더한 수다. 실물 기기는 연결되어 있을 때만 보이므로 두 숫자에 함께 든다.
  3. R3. 숫자를 아직 확인하지 못했으면 0이 아니라 "확인 중…"을 보여준다.
  4. R4. 앱이 떠 있는 동안 가상 기기 상태가 바뀌면 숫자가 따라 바뀐다.
  5. R5. 셀 수 없는 플랫폼에서도 카드는 같은 자리에 있다. 화면 구성이 플랫폼마다 갈라지지 않는다.
  6. R6. 세는 작업이 UI를 막지 않는다.
  7. R7. 셀 방법이 없으면 0개가 아니라 "셀 수 없음"을 보여준다. 화면의 0은 정말 0개라는 뜻이어야 한다.
  8. R8. SDK 도구를 띄울 수 없는 타깃도, 같은 머신에서 데스크톱 앱이 떠 있으면 실제 숫자를 보여준다.

세 상태는 서로 달라야 한다. 아직 세는 중(확인 중…), 셀 방법이 없음(셀 수 없음), 세었고 결과가 0개(실행 중 0개 / 전체 0개).

JarvisAppState가 observeEmulatorStatus()를 stateIn(scope, Eagerly, initial = null)로 들고 카드에는 값만 넘긴다. 초기값이 null인 것이 R3이다. 요약이 null인 것이 R7이다. 둘은 다른 층의 null이다. 전자는 "아직 답하지 않았다", 후자는 "답했고 셀 수 없다고 했다"다.

도메인 모델에는 @Serializable을 붙이지 않는다. 와이어 포맷은 :data의 EmulatorStatusDto가 갖고, 경계에서 도메인 모델로 바꾼다. JSON 필드 이름이 바뀌어도 :domain과 :ui는 그대로다.

개수 조회는 상태 조회 규칙을 따른다. 가상 기기 상태에는 어느 플랫폼에서도 변경 콜백이 없어서 전부 폴링이다(5초).

결정: 셀 수 없는 타깃은 데스크톱 앱에 물어본다 이전에는 flowOf(EmulatorStatus())로 즉시 0개를 답했다. 개수를 세려면 emulator·adb·simctl을 실행해야 하고 그게 가능한 건 JVM 타깃뿐이라는 이유였는데, 이는 "프로세스를 띄울 수 없다"는 제약이지 "숫자를 알 수 없다"는 제약이 아니다. 같은 머신에서 데스크톱 앱이 이미 세고 있으므로, 그 결과를 로컬 HTTP로 넘기면 네 타깃 모두 실제 숫자를 갖는다.
결정: 요약을 nullable로 만들어 0개와 셀 수 없음을 가른다 에이전트를 도입하면 "데스크톱 앱이 꺼져 있음"이 흔한 상태가 된다. 그걸 0개로 표시하면 사용자가 매번 거짓 숫자를 본다. EmulatorSummary?의 null이 "이 종류는 셀 수 없다"는 뜻이고, 종류별로 갈리므로 JVM에서 Android SDK만 없는 경우도 정확히 표현된다.
결정: 타깃별 HTTP 클라이언트를 expect로 두지 않는다 hostAgentEmulatorDataSource(fetch)가 조회 함수를 인자로 받는다. expect fun fetch…로 두면 직접 세는 JVM 타깃에도 쓰이지 않는 actual을 하나 만들어야 한다. 인자로 받으면 그 자리가 비고, 공용 테스트가 가짜 조회 함수를 끼울 수 있다.

로컬 에이전트

데스크톱 앱이 개수를 세어 로컬 HTTP로 넘겨준다. startEmulatorHostAgent()를 main()이 use {}로 감싸므로 창을 닫으면 함께 닫힌다.

데스크탑 앱 ──(emulator/adb/simctl)──> 개수
     │
     └─ http://127.0.0.1:47890/emulators
             ▲          ▲            ▲
      10.0.2.2   localhost     localhost
       Android       iOS          Web
      에뮬레이터    시뮬레이터     브라우저
항목값
주소http://<host>:47890/emulators. 포트는 고정. 클라이언트가 미리 알아야 해서 임의 포트를 쓸 수 없다
바인딩루프백만. 에뮬레이터의 10.0.2.2와 adb reverse는 호스트 루프백으로 들어온다
와이어 포맷{"android":{"total":0,"running":0},"ios":{"total":11,"running":0}}. 셀 수 없는 종류는 null
응답200 + JSON / 503 아직 세지 못함 / 405 GET 이외
헤더Access-Control-Allow-Origin: * (브라우저), Cache-Control: no-store
실패포트가 쓰이고 있으면 조용히 no-op. 데스크톱 앱 자신은 에이전트 없이도 센다

요청마다 세지 않는다. JVM 데이터 소스를 shareIn(replay = 1)으로 공유해서 UI와 에이전트가 같은 값을 보고, SDK 도구는 구독자 수와 무관하게 5초에 한 번만 돈다. 데이터 소스가 :data jvmMain의 프로세스 싱글턴인 이유가 이것이다. 에이전트는 조립(DataModule)을 거치지 않고 이 데이터 소스를 직접 구독한다.

인증이 없다 토큰도 오리진 검사도 없다. 같은 머신의 다른 프로세스는 누구나 개수를 읽을 수 있다. 개발자 머신 전용 도구라 그 정도 노출은 받아들이고, 대신 LAN에는 열지 않는다. 브라우저 클라이언트의 오리진을 고정할 수 없어서 CORS도 *다.

한계

  • 데스크톱 앱이 떠 있어야 한다. JVM 타깃을 제외하면 앱이 꺼져 있는 동안 "셀 수 없음"이다.
  • R4는 폴링이라 최대 5초 늦게 반영된다. 즉시성이 필요하면 간격을 줄인다.
  • JVM에서 SDK는 있는데 개별 명령이 실패하면 0개로 보인다. SDK 디렉터리 자체가 없는 경우만 "셀 수 없음"으로 구분한다.
  • JVM에서 iOS 시뮬레이터는 macOS에만 있으므로, 다른 OS에서는 ANDROID_HOME이 잡힐 때 Android 쪽만 동작한다. 데스크톱은 macOS만 지원하므로 별도 처리하지 않는다.
  • 실물 Android 기기는 adb reverse tcp:47890 tcp:47890이 필요하고, 실물 iOS 기기는 방법이 없다. 여기서 말하는 것은 "이 앱이 도는 기기" 이고, 세는 대상인 "호스트에 연결된 기기" 와는 다르다.
  • 실물 기기 하나는 전체와 실행 중에 동시에 든다. 꽂혀 있지 않은 기기를 셀 방법이 없어서 "설치되어 있지만 꺼져 있음" 에 해당하는 상태가 없다.
  • 실물 iOS 기기를 찾는 데 xctrace가 필요하고 느리다. 5초 폴링이 그 시간만큼 늘어질 수 있다(JVM 스펙).
