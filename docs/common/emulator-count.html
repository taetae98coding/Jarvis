사용자 지시

Android 에뮬레이터와 iOS 시뮬레이터가 몇 개 있고 몇 개 켜져 있는지 보여주는 카드를 추가하라.

커밋 4c40d5e "Add emulator card showing Android and iOS device counts"에서 복원.

에뮬레이터를 켜고 끄면 앱을 다시 띄우지 않아도 숫자가 바뀌어야 한다.

커밋 c49ff47에서 복원.

요구사항

  1. R1. 카드에 Android, iOS 두 줄이 있고 각 줄은 "실행 중 N개 / 전체 M개"다.
  2. R2. "전체"는 설치된 가상 기기 수, "실행 중"은 부팅된 가상 기기 수다. 실물 기기는 세지 않는다.
  3. R3. 숫자를 아직 확인하지 못했으면 0이 아니라 "확인 중…"을 보여준다.
  4. R4. 앱이 떠 있는 동안 가상 기기 상태가 바뀌면 숫자가 따라 바뀐다.
  5. R5. 셀 수 없는 플랫폼에서도 카드는 같은 자리에 있다. 화면 구성이 플랫폼마다 갈라지지 않는다.
  6. R6. 세는 작업이 UI를 막지 않는다.

공통 구현

UI
shared/ui/EmulatorCard.kt
모델
EmulatorSummary(total, running), EmulatorStatus(android, ios)
프로브
fun interface EmulatorProbe { fun observe(): Flow<EmulatorStatus> }
공급
internal expect val emulatorProbe: EmulatorProbe (shared/platform/Emulator.kt)

카드는 probe.observe().collectAsState(initial = null)로 구독한다. 초기값이 null인 것이 R3이다. 빈 EmulatorStatus()로 시작하면 SDK 도구를 아직 실행하는 중인데도 "0개"를 사실인 것처럼 보여주게 된다.

emulatorProbe는 App()이 FeatureGrid에 넘겨 EmulatorCard가 쓴다. 테스트는 여기에 FakeEmulatorProbe를 끼운다.

결정: 셀 수 없는 플랫폼은 카드를 숨기지 않고 0개를 낸다 가상 기기를 세려면 Android SDK와 Xcode 커맨드라인 도구를 실행해야 해서, 개발자 머신에서 프로세스를 띄울 수 있는 JVM 타깃만 실제 숫자를 낸다. 나머지 타깃은 flowOf(EmulatorStatus())로 즉시 0개를 답한다. R5가 이 결정에서 나왔다.

실제로 명령을 띄우는 부분은 테스트하지 않는다. 결과가 머신에 SDK가 깔려 있는지에 따라 달라진다.

한계

  • "0개"와 "셀 수 없음"이 화면에서 같아 보인다. JVM에서도 SDK를 못 찾거나 명령이 실패하면 0개다.
  • R4는 폴링이라 최대 5초 늦게 반영된다. 즉시성이 필요하면 JVM 프로브의 interval을 줄인다.
  • JVM에서 iOS 시뮬레이터는 macOS에만 있으므로, 다른 OS에서는 ANDROID_HOME이 잡힐 때 Android 쪽만 동작한다. 데스크톱은 macOS만 지원하므로 별도 처리하지 않는다.
