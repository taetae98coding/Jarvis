사용자 지시

지금 플랫폼 별로 미구현된 기능들 있잖아. 마켓 배포 포기한다면 구현할 수 있는 기능들 있어?

2026-09-22 대화.

전부 진행해주고 Flow 형식 조회도 System에서 callback을 주면 callback을 받아서 상태 업데이트, callback을 주지 않으면 N초마다 새로 조회해서 상태 업데이트 하는 방식으로 문제 해결해줘.

2026-09-22 대화. Flow 조회 방식은 상태 조회 규칙으로 분리했다.

화면 꺼짐 방지가 앱 수명 밖을 덮지 못하는 것은 플랫폼 정책이었고, 그 정책의 정체를 다시 조사한 결과가 이 기능이다. Android에서는 마켓 심사가 막고 있었을 뿐 플랫폼은 길을 열어 두고 있었다. 사이드로드를 전제로 하면 구현할 수 있다.

요구사항

  1. R1. 기능 그리드에 "화면 꺼짐 방지 (시스템 전역)" 토글 카드가 있다. 기본값은 꺼짐이다.
  2. R2. 토글이 켜져 있으면 앱이 포그라운드가 아니거나 종료된 뒤에도 화면이 꺼지지 않는다.
  3. R3. 특별 권한이 필요한 플랫폼에서 토글을 켜면 권한 설정 화면이 열리고, 허용 여부가 카드 설명에 보인다.
  4. R4. 권한을 허용하고 앱으로 돌아오면 앱을 다시 띄우지 않아도 효과가 걸린다.
  5. R5. 토글을 끄면 이 기능을 켜기 전의 시스템 설정으로 되돌린다.
  6. R6. 지원하지 않는 플랫폼에서도 카드는 같은 자리에 있고, 잠긴 채로 왜 불가능한지 보여준다.
  7. R7. 토글 값은 설정 영구 저장을 통해 복원되고, 복원된 값이 켜짐이면 효과를 다시 적용한다.
  8. R8. 효과는 카드나 화면의 수명에 묶이지 않는다. 카드가 스크롤 밖으로 나가도 유지된다.
스코프에서 뺀 것 iOS·JVM·Web에서의 R2. 조사 결과 배포 방식을 포기해도 열리지 않는다. 세 플랫폼은 R6으로 처리한다.

화면·동작

항목값
제목화면 꺼짐 방지 (시스템 전역)
설명 (지원 안 함)이 플랫폼에서는 앱이 없는 동안의 화면 꺼짐을 막을 수 없습니다.
설명 (권한 없음)시스템 설정 변경 권한이 필요합니다. 켜면 권한 설정 화면이 열립니다.
설명 (허용됨)앱을 닫아도 화면이 꺼지지 않습니다. 현재 시스템 설정은 {시간}입니다.
컨트롤ToggleFeatureCard(enabled = supported). 지원하지 않으면 카드와 스위치가 잠긴다
켤 때설정값을 먼저 쓰고, 권한이 없으면 권한 설정 화면을 연다
테스트 태그feature:keepSystemScreenAwake

시간 표기는 큰 단위 하나로 줄인다(24일, 30분). 이 기능이 설정하는 값은 24일이 넘어서 초 단위까지 보여줄 이유가 없다.

}

// :data — 플랫폼이 실제로 할 수 있는 것
internal expect fun createSystemScreenAwakeDataSource(
    context: PlatformContext,

결정: 적용과 상태 읽기를 한 데이터 소스에 둔다 둘 다 화면 수명보다 오래 살아야 한다. 효과는 카드가 스크롤 밖으로 나가도 유지되어야 하고(R8), 권한 상태를 보는 폴링도 한 곳에서만 돌아야 한다. 그래서 SystemScreenAwakeDataSource 하나가 읽기와 쓰기를 모두 갖고, 리포지토리가 그 상태를 컨테이너 수명의 StateFlow로 공유한다. 카드마다 상태를 읽게 두면 폴링이 여러 벌 돌고, 카드가 사라질 때 효과도 흔들린다.
결정: 적용 규칙은 화면이 아니라 유스케이스에 둔다 "권한이 있을 때만, 설정을 따라 적용한다"와 "권한이 없으면 설정 화면을 연다"는 ApplySystemScreenAwakeUseCase·SetKeepSystemScreenAwakeUseCase에 있다. 예전에는 카드의 onCheckedChange와 Android actual의 LaunchedEffect에 나뉘어 있어서, 규칙을 읽으려면 화면 코드와 플랫폼 코드를 함께 봐야 했다. 지금은 Compose도 플랫폼도 없는 :domain 테스트로 검증한다.
결정: 컴포지션이 사라져도 효과를 풀지 않는다 앱 수명 내 화면 꺼짐 방지는 onDispose에서 효과를 푼다. 이 기능은 반대다. 앱이 없는 동안 화면을 켜 두는 것이 목적이라서, 되돌리는 시점은 사용자가 토글을 끌 때뿐이다.
결정: 권한이 없어도 설정값은 켜 둔다 토글을 켰는데 권한이 없으면 설정값을 true로 쓰고 권한 화면을 연다. 여기서 토글을 되돌리면 사용자는 왜 꺼졌는지 알 수 없고, 허용하고 돌아왔을 때 다시 켜야 한다. 값을 유지해 두면 권한이 들어오는 순간 R4가 저절로 성립한다.

규칙(언제 적용하고 언제 권한을 요구하는지)은 :domain 테스트가 가짜 리포지토리로 검증한다. 화면이 지원되는 플랫폼처럼 동작하는지도 :ui가 가짜 상태로 검증한다. 다만 실제로 Settings.System을 쓰고 권한 화면이 열리는 경로는 여전히 미검증이다. Android 기기에서만 돌고 Android에는 UI 테스트가 없다. 개발 기기에서 수동으로 확인한다.

한계

  • Android 외에는 동작하지 않는다. 세 플랫폼은 카드가 잠긴 채로 이유를 보여준다. 공통 한계 참고.
  • 마켓 배포와 양립하지 않는다. WRITE_SETTINGS는 심사를 통과하기 어렵다. 이 기능은 사이드로드 전제다.
  • 권한을 잃으면 되돌릴 수 없다. 사용자가 권한을 회수한 뒤 토글을 끄면 늘려 둔 값이 남는다. 저장해 둔 원래 값은 지우지 않으므로 권한이 돌아오면 복원된다.
  • 앱을 삭제하면 늘려 둔 값이 남는다. 삭제 시점에 실행되는 훅이 없다.
