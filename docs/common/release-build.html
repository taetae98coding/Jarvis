사용자 지시

모든 플랫폼 release build해서 배포 준비하자. 체크리스트 알려주고 전부 해결해줘.

2026-09-25 대화.

요구사항

지시를 받은 시점(0440c28)에 release 빌드를 네 플랫폼에서 돌려 본 결과가 체크리스트의 출발점이다. 산출물을 실제로 띄워 보다가 셋이 더 나왔다 — Android R8 설치본이 시작하자마자 죽었고(WorkManager 의 Room), iOS 는 120Hz iPhone 에서 시작하자마자 죽었고(CADisableMinimumFrameDurationOnPhone), Web 은 한글이 전부 □ 로 나왔다. 셋 다 release 전부터 있던 문제이거나 release 설정이 드러낸 문제다. Android 는 빌드는 됐지만 서명이 없었고(app-release-unsigned.apk), 데스크톱은 :desktopApp:proguardReleaseJars 에서 실패했고, iOS 는 TEAM_ID 가 비어 서명할 수 없었고, Web 만 그대로 됐다. 네 플랫폼 모두 앱 아이콘이 없었다.

  1. R1. release 산출물. 아래 명령이 각각 성공하고 산출물을 남긴다.
    플랫폼명령산출물
    Android./gradlew :androidApp:assembleRelease :androidApp:bundleReleaseandroidApp/build/outputs/apk/release/androidApp-release.apk, …/bundle/release/androidApp-release.aab
    iOSxcodebuild … -configuration Release archive 뒤 -exportArchivebuild/ios/Jarvis.xcarchive, build/ios/export/Jarvis.ipa
    JVM (macOS)./gradlew :desktopApp:packageReleaseDmgdesktopApp/build/compose/binaries/main-release/dmg/Jarvis-<버전>.dmg
    Web./gradlew :webApp:wasmJsBrowserDistributionwebApp/build/dist/wasmJs/productionExecutable/
  2. R2. 서명. Android release APK·AAB 는 release 키로 서명된다(apksigner verify 가 통과한다). iOS 아카이브는 Config.xcconfig 의 팀으로 서명된다. 서명 키와 비밀번호는 저장소에 들어가지 않는다.
  3. R3. 서명 키가 없는 머신. Android 서명 정보가 없으면 빌드는 실패하지 않고 미서명 산출물을 만들며, 그 사실을 빌드 로그에 경고로 남긴다.
  4. R4. 버전 원본 하나. gradle/libs.versions.toml 의 appVersion(MAJOR.MINOR.PATCH) 하나가 Android versionName·versionCode, 데스크톱 packageVersion, 앱 정보 카드의 APP_VERSION 을 정한다. 빌드 번호는 MAJOR×10000 + MINOR×100 + PATCH 다(1.0.0 → 10000). iOS 는 Gradle 이 Xcode 설정을 쓰지 못하므로 Config.xcconfig 의 MARKETING_VERSION·CURRENT_PROJECT_VERSION 이 같은 값인지 ./gradlew check 가 검사한다.
  5. R5. 앱 아이콘. 네 플랫폼 모두 같은 앱 아이콘을 갖는다. Android 런처 아이콘(적응형), iOS AppIcon 1024px, macOS .icns, Web favicon. 원본은 branding/ 의 SVG 둘이다.
  6. R6. 산출물이 뜬다. Android 는 release APK 를 실물 기기에 설치해 홈 화면이 그려지고, JVM 은 DMG 안의 Jarvis.app 을 띄워 창이 그려지고, Web 은 정적 서버로 번들을 띄워 브라우저에서 홈 화면이 그려지고, iOS 는 아카이브·내보내기가 성공한다.
  7. R7. 머신 독립. release 빌드에 필요한 Gradle 설정이 사용자 홈(~/.gradle/gradle.properties)에만 있으면 안 된다. 비밀이 아닌 설정은 저장소의 gradle.properties 에 있다.
  8. R8. 한글이 보인다. 네 플랫폼의 release 산출물에서 화면의 한글이 대체 문자(□) 없이 그려진다. Web 은 브라우저 폰트를 쓰지 못해 한글 폰트를 번들에 싣는다(Web).

결정: 아이콘은 SVG 원본에서 headless Chrome 으로 PNG 를 뽑아 커밋한다 이 머신에는 rsvg-convert·ImageMagick·Inkscape 가 없고 Python 에 Pillow 도 없다. 설치 없이 SVG 를 정확히 그리는 도구는 Chrome 뿐이라, --headless --screenshot --default-background-color=00000000 으로 1024px PNG 를 뽑고 sips 로 줄이고 iconutil 로 .icns 를 만든다. 빌드마다 생성하지 않고 결과를 커밋한다 — 빌드 머신에 Chrome 을 요구하지 않기 위해서다. Android 는 PNG 대신 같은 도형을 벡터 드로어블로 옮겼다(적응형 아이콘은 벡터가 모든 밀도를 덮는다). 다시 뽑는 스크립트는 branding/render-icons.sh 다.
결정: Android 서명 정보는 Gradle 사용자 속성에서 읽는다 jarvis.signing.storeFile·storePassword·keyAlias·keyPassword 를 ~/.gradle/gradle.properties 나 -P, 또는 ORG_GRADLE_PROJECT_jarvis.signing.* 환경 변수로 준다. 저장소 루트의 keystore.properties 는 버렸다 — local.properties 와 같이 워크트리마다 없어서, 워크트리로 일하는 이 저장소에서는 매번 복사해야 한다. 사용자 속성은 모든 워크트리가 함께 본다.

한계

  • 배포처에 올리는 일은 스코프 밖이다(위 경고). 올릴 때 필요한 것은 플랫폼 스펙에 적었다.
  • iOS·macOS 의 배포용 서명은 이 머신에 없는 인증서(Apple Distribution, Developer ID Application)가 필요하다. iOS, JVM 참고.
  • Android 의 시스템 전역 기능(WRITE_SETTINGS)은 여전히 사이드로드 전제다(공통 한계). Play 배포용 AAB 를 만들어도 심사 통과는 보장하지 않는다.
