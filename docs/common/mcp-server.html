Claude 에게 브라우저·기기 조작 맡기기 (MCP 서버)

데스크톱 앱이 MCP 서버 하나로 동작해서, Jarvis 가 띄운 Claude 가 앱 안의 브라우저 탭과 Android·iOS 기기(에뮬레이터·시뮬레이터·실물)를 직접 보고 누르고 입력한다. Claude 가 쓰는 브라우저·기기는 그 Claude 가 있는 패널(워크트리)에 탭으로 붙어서, 사용자가 원할 때 눌러 볼 수 있다.

사용자 지시

Jarvis가 JVM 환경에서는 하나의 MCP 서버로 동작하고, Browser조작과 Android/iOS 실기기 or 에뮬레이터 조작을 지원할 수 있어?? Claude에게 브라우저 조작/디바이스 조작을 시키도록 진행하고 싶어.

2026-09-25 대화. 첫 답에서 브라우저는 앱 밖 Chrome 을 CDP 로 조작하는 안을 권했다.

앱 안의 브라우저는 안돼? Orca는 해당 기능 제공하던데 Open source라서 참고 할 수 있을 것 같아.

2026-09-25 대화. Orca 는 Electron 이라 앱 안 브라우저가 Chromium 이고, webContents.debugger 로 CDP 를 직접 부른다(설치된 Orca.app 번들에서 Input.dispatchMouseEvent·Page.captureScreenshot 호출을 확인했다). 지금 브라우저 탭의 WKWebView 는 CDP 가 없어서 엔진을 Chromium 으로 바꾸는 안(JCEF)을 권했다.

JCEF로 진행하자. Android/iOS도 지원해줘. 그리고 해당 기능을 쓸 땐 해당 Worktree에 탭을 추가해서 사용자가 원할 때 볼 수 있도록 해줘 Android/iOS도 마찬가지야.

2026-09-25 대화. "Android/iOS도 지원" 은 조작 대상 기기로 읽었다 — 첫 답에서 iOS 는 화면만 1차로 두자고 권했던 것을 받지 않고 iOS 입력까지 넣으라는 뜻이다. MCP 서버를 Android·iOS 앱 타깃에 띄우라는 뜻으로 읽지 않았다(첫 지시가 "JVM 환경에서는 하나의 MCP 서버"). "해당 Worktree" 는 그 도구를 부른 Claude 탭이 있는 패널(워크트리 패널이면 그 패널)로, "탭을 추가해서 원할 때 볼 수 있도록" 은 탭을 붙이되 사용자가 보던 탭·포커스를 빼앗지 않는 것으로 읽었다(결정).

요구사항

서버와 연결

  1. R1. 데스크톱 앱(JVM, macOS)이 켜져 있는 동안 루프백(127.0.0.1:47891)에 MCP 서버 하나가 떠 있다. 전송은 MCP Streamable HTTP(POST /mcp, JSON 응답)다. 앱을 끄면 닫힌다. 포트가 이미 쓰이고 있으면 조용히 서버 없이 뜬다(호스트 에이전트와 같은 규칙).
  2. R2. Jarvis 가 새로 띄우는 Claude 탭의 세션은 따로 설정하지 않아도 이 서버에 붙는다. 세션을 만들 때 --mcp-config 로 서버 주소와, 그 탭을 가리키는 값(X-Jarvis-Session: <탭의 claudeSessionId> 헤더)을 넘긴다. 앱을 다시 켜도 포트와 값이 같아서 살아 있던 백그라운드 세션이 그대로 다시 붙는다.
  3. R3. 요청의 X-Jarvis-Session 으로 작업 공간에서 그 값을 가진 Claude 탭을 찾고, 그 탭이 있는 패널을 "호출한 패널", 그 탭이 있는 그룹을 "호출한 그룹" 이라 한다. 헤더가 없거나 그런 탭이 없으면(밖에서 등록한 Claude, 닫힌 탭) 호출한 패널이 없다.
  4. R4. 루프백 밖에서는 닿지 않는다. Origin 헤더가 붙은 요청(브라우저 안 웹 페이지가 보낸 요청, DNS rebinding)은 403 으로 거절한다. 브라우저 엔진은 원격 디버깅 포트를 열지 않는다 — CDP 는 엔진 안의 브라우저 객체에 직접 보낸다.

탭

  1. R5. Claude 가 브라우저를 새로 열면(browser_open) 호출한 그룹의 탭 줄 끝에 브라우저 탭이 붙는다. 선택하지 않는다 — 선택된 패널, 포커스된 그룹, 그룹마다 선택된 탭이 그대로다. 사용자가 그 탭을 누르면 Claude 가 조작하고 있는 그 페이지가 보인다(새로 부르지 않는다).
  2. R6. Claude 가 기기 도구를 쓰면 호출한 패널에 그 기기의 기기 탭이 있는지 본다. 없으면 호출한 그룹의 탭 줄 끝에 붙인다(선택하지 않는다, R5 와 같다). 있으면 그대로 둔다 — 같은 기기에 탭을 거듭 만들지 않는다. device_list 처럼 기기를 가리키지 않는 도구는 탭을 만들지 않는다. 다른 패널에 할당된 기기면 붙이지 않는다(기기 할당 R3).
  3. R7. 호출한 패널이 없으면 브라우저 도구는 "Jarvis 터미널의 Claude 탭에서만 브라우저를 쓸 수 있습니다" 오류를 주고, 기기 도구는 탭 없이 동작한다.
  4. R8. Claude 가 연 탭도 사용자가 연 탭과 똑같다. 닫기, 끌어 놓기, 저장·복원 규칙이 같다(웹 브라우저, 기기 화면). 사용자가 닫으면 그 탭을 가리키는 다음 도구 호출은 "탭이 닫혔습니다" 오류다.

브라우저

  1. R9. 브라우저 도구는 호출한 패널의 브라우저 탭만 다룬다. 사용자가 연 브라우저 탭도 포함한다. 탭은 tabId 로 가리키고, 빼면 이 세션이 마지막으로 연·쓴 탭, 그것도 없으면 그 패널의 첫 브라우저 탭이다. 하나도 없으면 오류로 browser_open 을 먼저 부르라고 알린다.
  2. R10. 가려진 브라우저 탭(선택되지 않았거나 다른 패널, 터미널 화면을 벗어난 뒤)도 페이지가 살아 있어서 Claude 가 보고 누를 수 있다. 이것은 웹 브라우저 R6 을 바꾼다.
  3. R11. 클릭·키 입력은 페이지에 신뢰된 입력(isTrusted = true)으로 들어간다. 스크립트로 만든 가짜 이벤트가 아니다.
  4. R12. 좌표는 CSS 픽셀이다. browser_screenshot 은 지금 보이는 뷰포트를 배율 1 로 찍어서 이미지의 픽셀이 곧 클릭 좌표다. browser_snapshot 은 눌러 볼 만한 요소마다 역할·이름·가운데 좌표를 준다.

기기

  1. R13. device_list 는 기기 목록과 같은 기기를 같은 식별자로 준다. 식별자는 다른 기기 도구에 그대로 넣는다. 한 기기는 한 패널만 조작한다(기기 할당).
  2. R14. Android(에뮬레이터·실물)는 화면 캡처, 탭·길게 누르기, 스와이프, 글자 입력(한글 등 ASCII 밖 글자 포함), 키(뒤로·홈·최근 앱·Enter·지우기·전원·볼륨), UI 트리, 앱 실행, 꺼진 AVD 켜기가 된다.
  3. R15. iOS 시뮬레이터도 R14 와 같은 도구가 된다(키는 홈·Enter·지우기·볼륨). 입력 경로(WebDriverAgent)는 처음 쓸 때 Jarvis 가 스스로 준비한다(소스를 받아 Xcode 로 빌드한다). 사용자는 Xcode 말고 따로 설치하지 않는다.
  4. R16. 실물 iOS 기기도 R15 와 같다. 다만 기기에 앱을 올리려면 사용자의 Apple 개발 팀으로 서명해야 해서, Xcode 에 개발 팀 계정이 없거나 기기에서 개발자를 신뢰하지 않았으면 무엇을 해야 하는지 적은 오류를 준다.
  5. R17. 좌표는 device_screenshot 이 준 이미지의 픽셀이다. 이미지는 긴 변 1280 px 을 넘지 않게 줄여서 준다(iOS 는 포인트 크기). 기기 탭이 가려져 있어도, 아무 화면도 그 기기를 보고 있지 않아도 캡처·입력이 된다.
  6. R18. Claude 의 기기 조작은 그 기기를 보고 있는 모든 화면(기기 탭, 기기 목록의 화면)에 그대로 보인다. 같은 기기를 보는 곳이 여럿이어도 기기 쪽 에이전트는 하나다(영상 스트림 R5).

도구 결과

  1. R19. 도구가 실패하면 MCP 도구 결과의 isError = true 와 한 줄짜리 이유를 준다. 서버가 죽거나 다른 도구에 영향을 주지 않는다.
  2. R20. 한 도구 호출은 30초 안에 끝난다. 넘으면 오류다. 예외는 WebDriverAgent 를 처음 준비할 때(내려받기·빌드)이고, 그때는 180초다.
스코프에서 뺀 것
  • Android·iOS·Web 앱 타깃에 MCP 서버를 띄우는 것. 지시가 "JVM 환경에서는 하나의 MCP 서버" 다. 이 타깃들은 바뀌지 않는다.
  • 이미 살아 있는 백그라운드 Claude 세션을 서버에 붙이는 것. 세션의 MCP 설정은 만들 때만 줄 수 있다. 이 기능 전에 만든 Claude 탭은 닫고 새로 열어야 도구가 생긴다(한계).
  • Claude Code 전역 설정(~/.claude.json)에 서버를 등록하는 것. 사용자의 설정 파일을 앱이 고치지 않는다. 밖에서 쓰고 싶으면 사용자가 claude mcp add 로 직접 등록한다(그때는 R7 대로 브라우저 도구가 없다).
  • 기기 탭에서 사람이 iOS 시뮬레이터·실물 iOS 에 제스처를 보내는 것. 입력 경로가 생기지만 지시는 Claude 의 조작이다. 기기 화면 R7 은 그대로다.
  • 실물 iOS 기기의 화면을 기기 탭에 흘리는 것. 도구의 캡처(R16)는 되지만 기기 탭은 기기 목록 R13 대로 목록에서 누를 수 없는 채다. Claude 가 실물 iOS 를 쓰면 기기 탭은 붙지만 "[기기 화면을 볼 수 없습니다]" 만 보인다(한계).
  • 브라우저 파일 받기·올리기, 새 창(target="_blank")을 따로 된 탭으로 여는 것, 여러 탭을 동시에 조작하는 것 말고 탭 사이 끌어 놓기. 웹 브라우저가 빼 둔 것을 그대로 뺀다.
  • 멀티터치·핀치, 기기 오디오, 기기 파일 올리기·설치(adb install). 지시에 없다.

화면·동작

새 화면은 없다. 사용자에게 보이는 변화는 Claude 가 붙인 탭뿐이다.

항목값
Claude 가 연 브라우저 탭호출한 그룹의 탭 줄 끝. 선택되지 않는다. 이름은 페이지 제목(가려져 있어도 엔진이 알려 준다), 없으면 "웹 N"
Claude 가 쓴 기기 탭호출한 그룹의 탭 줄 끝. 선택되지 않는다. 이름은 기기 이름
서버 주소http://127.0.0.1:47891/mcp. MCP 서버 이름 jarvis
Claude 탭에 넘기는 설정{"mcpServers":{"jarvis":{"type":"http","url":"http://127.0.0.1:47891/mcp","headers":{"X-Jarvis-Session":"<claudeSessionId>"}}}}
테스트 태그바뀌지 않는다. 붙은 탭은 기존 태그(terminal:browser:<tabId>, terminal:device:<tabId>)를 쓴다

도구

인자 이름은 camelCase 다. tabId? 는 빼도 되는 인자다(R9). 이미지 결과는 MCP image 콘텐츠(JPEG 품질 0.85, base64 — PNG 는 1280px 한 장이 1~2MB 라 무겁다)와 크기를 적은 text 콘텐츠 둘이다.

공통 구현

모듈

도구는 두 기능(터미널의 탭·브라우저, emulator 의 기기)을 가로지른다. 기능은 서로를 의존하지 않으므로(모듈 구조 R3) 이음새를 :core:automation 에 두고 각 기능이 구현을 Koin 에 등록한다. 기기 탭의 DeviceScreens 와 같은 방식이다.

모듈패키지내용
:core:automation…automation이음새 인터페이스와 값 타입만. AgentTabs, BrowserAutomation, DeviceAutomation, AutomationImage, AutomationDevice, DeviceKey, AutomationException. commonMain 만 있고 플랫폼 코드가 없다
:core:browser…browserJVM: Chromium(JCEF) 엔진, 탭 id 마다 살아 있는 브라우저, CDP 클라이언트, BrowserAutomation 구현. 다른 타깃은 빈 모듈. :feature:terminal:ui 가 브라우저 창을 그리려고, Koin 이 BrowserAutomation 을 꺼내려고 쓴다(웹 브라우저)
:feature:mcp:domain…domain.mcp도구 목록(이름·설명·인자 스키마)과 호출을 이음새에 나눠 주는 McpToolbox. 플랫폼·직렬화에 의존하지 않는다
:feature:mcp:data…data.mcpJVM: HTTP 서버, JSON-RPC 2.0 ↔ McpToolbox, startMcpServer(). 다른 타깃은 no-op
:feature:terminal:domain·data기존TerminalWorkspace.appendTab(선택하지 않고 붙이기), findClaudeTab. AgentTabs 구현(WorkspaceAgentTabs). Claude 세션 시작 명령에 --mcp-config
:feature:emulator:data기존DeviceAutomation 구현. JVM 만(adb·scrcpy 제어 소켓·simctl·WebDriverAgent). 다른 타깃은 등록하지 않는다

:feature:mcp:domain 이 :core:automation 을 의존하는 것은 모듈 구조 R5(domain 의 의존은 coroutines·koin 뿐)의 예외다. :core:automation 은 인터페이스와 데이터 클래스만 있고 플랫폼·Compose 를 끌어오지 않는다. :feature:mcp 에는 화면이 없어서 ui 모듈이 없다.

프로토콜

MCP 2025-06-18 의 Streamable HTTP 중 서버가 꼭 해야 하는 부분만 한다. 스트림(SSE)은 열지 않는다.

요청응답
POST /mcp initializeprotocolVersion(클라이언트가 보낸 것이 아는 버전이면 그것, 아니면 2025-06-18), capabilities.tools, serverInfo {name: "jarvis"}. Mcp-Session-Id 헤더는 주지 않는다 — 서버에 연결별 상태가 없다
POST /mcp 알림·응답(id 없음)202 Accepted, 본문 없음
POST /mcp tools/list도구 표 전체. 페이지를 나누지 않는다
POST /mcp tools/call{content: [...], isError}
POST /mcp ping{}
POST /mcp 모르는 메서드JSON-RPC 오류 -32601
GET /mcp405. 서버가 먼저 보낼 알림이 없다
Origin 헤더가 있는 요청403(R4)
결정: MCP 는 손으로 짠다 공식 Kotlin SDK(io.modelcontextprotocol:kotlin-sdk)는 Ktor 서버·클라이언트를 끌고 오고, 여기서 쓰는 것은 요청 네 가지(initialize·tools/list·tools/call·ping)의 JSON 응답뿐이다. 이미 있는 호스트 에이전트처럼 JDK HttpServer 와 kotlinx-serialization-json 으로 짜면 의존성이 늘지 않는다. SDK 가 해 주는 SSE 스트림·재개·세션은 이 서버에 필요가 없다(서버가 먼저 보낼 것이 없다). 프로토콜 버전이 바뀌어 요청 모양이 달라지면 이 표를 먼저 고친다.
결정: 호출한 Claude 를 헤더로 가른다 후보는 셋이었다. (1) 탭마다 다른 경로(/mcp/<id>) — 헤더와 같지만 주소가 로그에 남고 서버 이름이 탭마다 달라 보인다. (2) MCP roots 로 작업 디렉터리를 받아 패널 폴더와 맞추기 — 같은 워크트리에 Claude 탭이 여럿이면 가를 수 없고, 폴더가 없는 패널은 찾을 수 없다. (3) 채택: 세션을 만들 때 --mcp-config 의 headers 에 탭의 claudeSessionId 를 넣는다. 탭에 저장된 값이라 앱을 다시 켜도, 탭을 다른 그룹으로 옮겨도 같은 탭을 가리킨다.
결정: 붙인 탭은 선택하지 않는다 지시의 "사용자가 원할 때 볼 수 있도록" 을 따른다. 기존 addTab 은 붙인 탭을 고르고 그 그룹·패널에 포커스를 준다. Claude 가 페이지를 열 때마다 사용자가 보던 Claude 창이 브라우저로 바뀌면 원할 때 보는 것이 아니다. 그래서 선택·포커스·선택된 패널을 건드리지 않는 appendTab 을 새로 둔다. 붙는 자리는 호출한 그룹이다 — 패널의 포커스된 그룹에 붙이면 사용자가 다른 그룹을 보고 있을 때 Claude 와 먼 곳에 생긴다.

한계

  • 이 기능 전에 만든 Claude 탭(이미 살아 있는 백그라운드 세션)에는 도구가 없다. 탭을 닫고 새 Claude 탭을 연다.
  • 앱이 꺼져 있으면 Claude 의 도구 호출이 연결 실패로 끝난다. 앱을 켜면 다음 호출부터 된다.
  • Claude 가 브라우저를 조작하는 동안 사용자가 같은 페이지를 누르면 두 입력이 섞인다. 막지 않는다.
  • 브라우저 탭마다 Chromium 렌더러가 하나씩 살아 있다. 탭을 닫기 전까지 메모리를 쥔다(R10 의 대가).
  • 기기 탭은 Claude 가 쓴 기기마다 하나씩 쌓인다. Claude 가 기기를 다 쓴 뒤에도 닫지 않는다 — 사용자가 닫는다.
  • 플랫폼마다의 한계는 JVM 문서에 있다.
