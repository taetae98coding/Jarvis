화면 이동 (Navigation3)

홈 · 기기 목록 · 기기 화면 사이의 이동을 NavDisplay와 백스택이 맡는다. 라우트는 그 화면을 가진 기능 모듈이 Koin 에 등록하고, 백스택은 앱 셸의 컴포지션이 들고 저장한다.

사용자 지시

Koin 적용해서 DI 사용하도록 해줘. 그리고 Compose에서 제공하는 Retain 개념과 ViewModel 개념 Navigation3 개념 적용해서 Koin이랑도 연동까지 구현해줘.

2026-09-22 대화. 같은 지시에서 의존성 주입, ViewModel, 재생성을 넘기는 상태 스펙이 함께 나왔다.

이 스펙은 기기 목록·화면·제스처가 임시로 두었던 자체 라우트를 걷어낸다. 그때의 판단은 이렇게 적혀 있었다.

내비게이션 라이브러리를 쓰지 않는 이유는 경로가 이 둘뿐이고 딥링크도 백스택 복원도 필요 없기 때문이다. 경로가 늘면 그때 라이브러리를 들인다.

ui/.../emulator/EmulatorRoute.kt, 커밋 6f079c2.

요구사항

  1. R1. 화면은 셋이다. 앱 셸이 가진 Home(기능 그리드)과 에뮬레이터 기능이 가진 EmulatorRoute.Devices·EmulatorRoute.Screen(deviceId). 이동은 백스택에 키를 넣고 빼는 것으로만 일어난다. (이후 터미널·페어링 화면이 더해졌고, 2026-09-26 홈 적응형 배치로 화면 꺼짐 방지 둘·화면 테마·프로파일링·화면 회전의 기능 화면(ScreenAwakeRoute.App·System, ThemeModeRoute, ProfilingRoute, DeviceRotationRoute)이 같은 방식으로 더해졌다.)
  2. R2. 라우트 키는 NavKey이고 @Serializable이다. 화면에 필요한 값은 키에 직렬화 가능한 형태로만 담는다.
  3. R3. 백스택은 rememberNavBackStack으로 저장·복원된다. 복원 경로가 있는 플랫폼에서는 앱을 다시 띄웠을 때 마지막 화면으로 돌아온다.
  4. R4. 각 라우트의 @Composable 본문은 그 기능의 Koin 모듈에 navigation<T>로 선언하고, NavDisplay는 koinEntryProvider()가 모아 준 entryProvider만 받는다. 화면을 하나 더할 때 앱 셸은 고치지 않는다.
  5. R5. 엔트리마다 ViewModelStore와 SaveableStateHolder가 따로 붙는다. 엔트리가 백스택에서 빠지면 둘 다 비워진다.
  6. R6. 뒤로 아이콘 버튼(contentDescription "뒤로")은 백스택을 한 칸 줄인다. 홈에서는 뒤로 갈 곳이 없다.
  7. R7. 이동 후에도 앱 수명 효과(화면 꺼짐 방지)는 끊기지 않는다. NavDisplay는 그 효과보다 안쪽에 있다.
  8. R8. 사용자에게 보이는 화면 구성과 전환 결과는 바뀌지 않는다. 카드를 누르면 목록, 기기를 누르면 화면, 뒤로 두 번 누르면 그리드다.
스코프에서 뺀 것
  • 딥링크. navigation3-runtime에 DeepLinkMatcher가 있지만 앱을 밖에서 열 창구(Android intent-filter, 커스텀 스킴, URL 경로)를 만들지 않았다. 지금은 열 이유가 없다.
  • 여러 창(Scene) 전략. SinglePaneSceneStrategy 기본값만 쓴다. 넓은 창에서 목록·화면을 나란히 두는 TwoPaneScene은 화면이 셋뿐인 지금 이득이 없다.
  • 전환 애니메이션 지정. NavDisplay의 기본 전환을 쓴다.
  • 브라우저 히스토리 연동. Web 참고.

공통 구현

라우트

// :app:ui — 셸이 가진 유일한 라우트
@Serializable
internal data object HomeRoute : NavKey

// :feature:emulator:ui — 이 기능이 가진 화면 둘. 앱 셸은 이 타입을 모른다.
@Serializable
internal sealed interface EmulatorRoute : NavKey {
    @Serializable data object Devices : EmulatorRoute

    // 기기 상태가 아니라 식별자만 나른다. 이유는 view-model.html 의 결정에 있다.
    @Serializable data class Screen(val deviceId: String) : EmulatorRoute
}

백스택

rememberNavBackStack은 PolymorphicSerializer(NavKey::class)로 백스택을 저장한다. NavKey는 sealed 가 아닌 인터페이스라 구현을 직접 등록해 줘야 하고, 안 하면 다음 메시지로 죽는다.

You must pass a SavedStateConfiguration.serializersModule configured to handle NavKey open polymorphism. Define it with: polymorphic(NavKey::class) { ... }

androidx.navigation3:navigation3-runtime 1.1.7 의 rememberNavBackStack.

등록 목록을 앱 셸에 두면 화면을 더할 때마다 셸을 고쳐야 한다. 그래서 :core:ui 가 NavKeySerializers 를 정의하고, 기능이 자기 라우트를 Koin 에 등록하고, 셸이 getAll 로 모은다(모듈 구조의 결정).

// :feature:emulator:ui — emulatorUiModule 안
navKeySerializers<EmulatorRoute> {
    subclass(EmulatorRoute.Devices::class, EmulatorRoute.Devices.serializer())
    subclass(EmulatorRoute.Screen::class, EmulatorRoute.Screen.serializer())
}

// :app:ui — 셸은 자기 것만 알고 나머지는 모아서 채운다
val registrations = currentKoinScope().getAll<NavKeySerializers>()

SavedStateConfiguration {
    serializersModule = SerializersModule {
        polymorphic(NavKey::class) {
            subclass(HomeRoute::class, HomeRoute.serializer())

            registrations.forEach { it.register(this) }
        }
    }
}

NavDisplay

NavDisplay(
    backStack = backStack,
    onBack = navigator::back,
    entryDecorators = listOf(
        // NavDisplay 의 기본값과 같다. 목록을 넘기는 순간 기본값이 사라지므로 함께 적는다.
        rememberSaveableStateHolderNavEntryDecorator(),
        // 엔트리마다 ViewModelStore 를 만들고, 백스택에서 빠질 때 비운다.
        rememberViewModelStoreNavEntryDecorator(),
    ),
    entryProvider = koinEntryProvider(),
)

ViewModel 데코레이터는 별도 아티팩트(lifecycle-viewmodel-navigation3)에 있어서 NavDisplay의 기본값에 들어갈 수 없고, 그것이 화면 수명 ViewModel의 전제라 직접 넘긴다. 목록을 직접 주면 기본값이 사라지므로 rememberSaveableStateHolderNavEntryDecorator()도 함께 적는다. Scene 설정 데코레이터는 이 버전에서 internal 이라 목록에 넣을 수 없고, NavDisplay가 안에서 알아서 붙인다.

Koin ↔ Navigation3

koin-compose-navigation3이 두 조각을 준다. 모듈 쪽의 navigation<T : NavKey> DSL 과 화면 쪽의 koinEntryProvider()다. 전자는 EntryProviderInstaller 타입 정의를 등록하고, 후자는 현재 Koin 스코프에서 그 정의를 getAll로 모아 entryProvider를 만든다.

// :feature:emulator:ui — emulatorUiModule
navigation<EmulatorRoute.Devices> {
    val navigator = LocalNavigator.current

    EmulatorListScreen(
        viewModel = koinViewModel(),
        onSelect = { device -> navigator.goTo(EmulatorRoute.Screen(device.id)) },
        onBack = navigator::back,
    )
}

navigation<EmulatorRoute.Screen> { route ->
    EmulatorStreamScreen(viewModel = koinViewModel { parametersOf(route.deviceId) }, …)
}
결정: 라우트 정의는 Koin 에, 백스택은 컴포지션에 둔다 백스택도 Koin single로 둘 수 있다. NavBackStack은 스냅샷 상태 리스트라 컴포지션 밖에서도 만들어진다. 버렸다. 그러면 저장·복원(R3)을 우리가 다시 구현해야 하고, 화면 이동이 전역 가변 상태가 된다. 반대로 라우트 본문을 Koin 에 두면 얻는 것이 분명하다 — 화면은 그 기능 모듈 안에서만 선언되고 NavDisplay를 부르는 앱 셸은 라우트 목록을 모른다. 두 세계를 잇는 값이 내비게이터 하나뿐이라, 그것만 LocalNavigator로 내려보낸다.
결정: 내비게이터를 CompositionLocal 로 내려보낸다 라우트 본문은 Koin 모듈이 선언할 때 백스택을 알 수 없다(그때는 컴포지션이 없다). 선택지는 셋이었다. (1) 백스택을 Koin 에 둔다 — 위 결정에서 버렸다. (2) navigation 정의에 파라미터로 내비게이터를 넘긴다 — koinEntryProvider()가 정의를 getAll로 꺼내므로 파라미터를 끼울 자리가 없다. (3) staticCompositionLocalOf로 내려보낸다 — 채택. 값이 앱 수명 동안 바뀌지 않아 static이 맞고, 제공하는 곳이 JarvisApp() 한 곳이다. Navigator와 LocalNavigator는 기능이 서로를 모른 채 이동할 수 있게 :core:ui에 둔다.

한계

  • NavKey 구현을 SerializersModule에 등록하는 일이 수동이다. 라우트를 추가하고 subclass() 한 줄을 잊으면 컴파일은 통과하고 그 화면으로 이동할 때 런타임에 죽는다. 기능이 navKeySerializers 블록을 아예 잊으면 그 기능의 모든 화면이 같은 이유로 죽는다.
  • 라우트 정의가 Koin 에 있으므로 어떤 화면이 있는지는 런타임 목록이다. 존재하지 않는 키로 이동하면 NavDisplay가 그 시점에 예외를 던진다. when 으로 갈랐던 예전 코드에서는 컴파일러가 빠진 분기를 잡아 줬다.
  • 기기 화면에서 기기가 목록에서 사라져도 백스택은 그대로다. 화면은 제목 없는 "가져오는 중"에 머문다.
  • 브라우저 뒤로와 iOS 가장자리 스와이프는 앱 백스택과 이어지지 않는다. 플랫폼 문서의 해당 섹션에 이유와 우회 후보를 적었다.
  • 메타데이터 컴파일에 KLIB loader: The same 'unique_name=savedstate_commonMain' found in more than one library 류의 경고가 새로 생긴다. Navigation3 가 androidx.savedstate·androidx.navigationevent를, 같이 쓰는 JetBrains 쪽 아티팩트가 org.jetbrains.androidx.* 의 같은 라이브러리를 끌고 와서다. 두 벌이 클래스패스에 함께 있지만 컴파일·테스트·실행에는 문제가 없었다. 한쪽을 exclude 하면 어느 쪽이 skiko 타깃의 실제 구현인지에 따라 링크가 깨질 수 있어 건드리지 않았다. JetBrains 가 navigation3-runtime 도 퍼블리시하면 사라질 종류의 경고다.
