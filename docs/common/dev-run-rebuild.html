요구사항

리포트를 판독한 결과, 코드 결함이 아니라 돌고 있는 앱의 jar 를 Gradle 이 자리에서 덮어쓴 것이었다. :desktopApp:run 은 각 모듈의 build/libs/*-jvm.jar 를 그대로 classpath 에 올리고, JVM 은 jar 를 연 채 클래스를 처음 쓰는 순간에 읽는다. 같은 체크아웃에서 빌드가 다시 돌면(워크트리 작업을 main 에 머지한 뒤의 빌드, 다른 세션의 jvmTest) Gradle 의 Jar 태스크가 기존 파일을 같은 inode 에 잘라 다시 쓰고, 열어 둔 JVM 은 아직 읽지 않은 클래스를 ClassNotFoundException 으로 잃는다. 판독 근거와 재현은 JVM 스펙에 있다. 그래서 요구사항은 "빌드가 돌고 있는 앱을 깨뜨리지 않는다" 다. 리포트에 함께 온 Exception in thread "AppKit Thread" 줄은 jar 와 무관한 브라우저 탭의 포커스 재귀(StackOverflowError)였고, 그쪽은 터미널에서 웹 브라우저의 JVM 스펙에서 다룬다.

  1. R1. 개발용으로 띄운 앱(:desktopApp:run)이 돌고 있는 동안 같은 체크아웃에서 어떤 Gradle 빌드가 모듈 jar 를 다시 만들어도, 돌고 있던 앱은 아직 읽지 않은 클래스를 NoClassDefFoundError·ClassNotFoundException 없이 계속 읽는다.
  2. R2. 모든 하위 프로젝트의 Jar 태스크는 산출물을 다시 쓸 때 기존 파일을 먼저 지워 새 inode 에 쓴다. 다시 빌드한 뒤 jar 의 inode 가 바뀐다.
  3. R3. 새로 띄운 앱은 새 jar 를 쓴다. 돌고 있던 앱에 새 코드가 들어가는 것은 요구하지 않는다.
스코프에서 뺀 것 JCEF 를 띄운 뒤 데스크톱 앱이 SIGTERM 을 무시해 :desktopApp:run 을 끊어도 창이 남는 문제. 옛 인스턴스가 남아 있는 동안 다시 빌드하면 이 기능이 그 인스턴스를 보호하지만, 남는 것 자체는 고치지 않는다.

공통 구현

파일
루트 build.gradle.kts
동작
subprojects { tasks.withType<Jar>().configureEach { doFirst { archiveFile.get().asFile.delete() } } }. 태스크가 실제로 돌 때(UP-TO-DATE 가 아닐 때)만 doFirst 가 돌아 옛 파일을 unlink 하고, Gradle 은 새 inode 에 쓴다. 열어 둔 옛 파일은 마지막 fd 가 닫힐 때까지 그대로 읽힌다
공급
expect 없음. Gradle 설정만이다
결정: Jar 태스크가 쓰기 전에 옛 파일을 지운다. :desktopApp:run 이 classpath 를 launch 마다 build/run/<시각>/ 으로 복사해 그것으로 띄우는 방법도 되지만, 매번 프로젝트 jar 를 복사하고 옛 디렉터리를 치워야 하며 run 한 경로만 보호한다. 옛 파일을 지우는 쪽은 한 줄이고, 어떤 태스크가 어떤 이유로 jar 를 다시 만들어도 돌고 있는 모든 JVM(앱, 테스트)을 보호한다. 앱이 시작할 때 모든 클래스를 미리 읽는 방법은 JCEF·FFmpeg 까지 수백 MB 라 버렸다. "앱을 끄고 빌드하라" 는 안내는 빌드를 다른 세션이 돌리므로 지킬 수 없다.

플랫폼별 판정

플랫폼판정어떻게문서
Android구현문제가 생기지 않는다. 설치본은 APK 를 기기로 복사한 것이라 빌드 산출물을 열어 두지 않는다android.html
iOS구현문제가 생기지 않는다. Xcode 가 번들을 시뮬레이터·기기에 복사한다ios.html
JVM구현 미검증루트 build.gradle.kts 의 Jar doFirst. 자동 테스트는 없고 inode 비교와 재현 jar 로 확인했다jvm.html
Web구현문제가 생기지 않는다. 개발 서버가 번들을 메모리에서 내주고 다시 빌드하면 페이지를 새로 고친다web.html

한계

  • 돌고 있는 앱에 새 코드가 들어가지는 않는다. 새 코드는 앱을 다시 띄워야 한다(R3).
  • jar 가 아닌 산출물을 자리에서 바꾸는 태스크는 보호하지 않는다. 지금 :desktopApp:run 의 classpath 는 jar 뿐이고 compose.application.resources.dir 은 비어 있다.
