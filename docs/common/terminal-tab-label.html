탭 종류 표시와 이름 바꾸기

탭 제목 앞에 종류(터미널·Claude·브라우저·Android·iOS) 아이콘을 두어 한눈에 가르고, 탭 제목을 두 번 눌러 그 자리에서 이름을 바꾼다.

사용자 지시

탭에 terminal, browser, claude, android, ios 분리할 수 있도록 indicator 같은 것 추가하고, 탭도 이름 수정할 수 있도록 구현해줘.

2026-09-25 대화. "탭" 은 그룹의 탭 줄 한 칸(분할 그룹)으로, "indicator" 는 탭 안에서 종류를 알려 주는 표시(아이콘과 색)로 읽었다. android·ios 는 기기 탭(터미널에서 기기 화면)을 기기 플랫폼으로 나눈 것이다. 패널 이름은 이미 바꿀 수 있으므로(패널 R2) "탭도" 는 탭 줄의 탭을 가리킨다.

요구사항

종류 표시

  1. R1. 탭 줄의 모든 탭은 제목 왼쪽에 종류 아이콘을 가진다. 종류는 터미널 · Claude · 브라우저 · Android · iOS 다섯 가지이고 아이콘 모양과 색이 서로 다르다. 플랫폼을 모르는 기기 탭(R3)만 여섯째 모양(일반 기기)이다.
  2. R2. 종류는 탭의 program 으로 정한다. 셸 → 터미널, Claude → Claude, 브라우저 → 브라우저, 기기 → 그 기기의 플랫폼(Android 에뮬레이터·Android 실물 기기 → Android, iOS 시뮬레이터 → iOS). Claude 세션이 끝나 셸이 남아도 탭의 종류는 Claude 그대로다(program 이 바뀌지 않는다).
  3. R3. 기기 탭의 플랫폼은 새 탭 메뉴에서 기기를 고를 때 탭에 저장한다(기기 이름과 같다, 기기 화면). 앱을 다시 켜도 같다. 이 기능 전에 저장된 기기 탭은 플랫폼을 몰라 일반 기기 아이콘이다.
  4. R4. 새 탭(+) 메뉴의 기기 항목 아이콘도 R1 의 Android · iOS 아이콘이다. 메뉴의 "터미널 / Claude (YOLO) / 웹 브라우저" 항목 아이콘은 R1 의 같은 종류 아이콘과 같은 모양이다.
  5. R5. 아이콘은 스크린 리더에 종류 이름("터미널", "Claude", "브라우저", "Android", "iOS", "기기")으로 읽힌다.

이름 바꾸기

  1. R6. 탭 제목을 두 번 누르면(마우스 더블클릭, 터치 더블탭) 제목 자리가 이름 입력칸으로 바뀐다. 첫 번째 누름은 지금처럼 곧바로 탭을 고른다 — 두 번째 누름을 기다리느라 선택이 늦지 않는다. 입력칸에는 지금 보이는 제목이 전체 선택된 채로 들어 있다.
  2. R7. Enter 또는 입력칸이 포커스를 잃으면 확정, Esc 는 취소다. 앞뒤 공백을 뗀 값이 그 탭의 이름이 된다. 빈 값으로 확정하면 사용자가 정한 이름이 지워지고 자동 제목으로 돌아간다. 입력칸의 값을 고치지 않고 확정하면 아무것도 바뀌지 않는다(자동 제목이 이름으로 굳지 않는다).
  3. R8. 탭 제목은 사용자가 정한 이름, 없으면 자동 제목이다. 자동 제목은 분할 그룹 R12 그대로(창이 OSC 로 정한 제목·페이지 제목·기기 이름, 없으면 "셸 N" 등)다. 사용자가 정한 이름은 셸이 OSC 로 제목을 바꾸거나 페이지 제목이 바뀌어도 그대로다. 끌기 유령에도 같은 제목이 보인다.
  4. R9. 이름은 탭에 붙어 저장되고 앱을 다시 켜도 남는다. 탭을 다른 그룹으로 끌어 놓아도 이름이 따라간다.
  5. R10. 입력칸이 떠 있는 동안 그 탭은 끌 수 없다. 입력칸 안에서 끌어 글자를 고르는 것이 탭 끌기로 읽히지 않는다. 확정·취소하면 다시 끌 수 있다.
스코프에서 뺀 것
  • 종류로 탭을 거르거나 묶기, 종류마다 탭 줄을 따로 두기. 지시의 "분리" 는 눈으로 가르는 것으로 읽었다.
  • 사용자가 종류 색을 바꾸기.
  • 오른쪽 클릭 메뉴의 "이름 바꾸기". 더블클릭 하나로 마우스·터치 둘 다 된다.

공통 구현

도메인
TerminalTab.name: String? — 사용자가 정한 이름. null 이면 자동 제목.
TerminalTab.devicePlatform: DevicePlatform? — 기기 탭만. DevicePlatform { Android, IOS } 는 terminal 도메인에 둔다.
TerminalTab.kind: TerminalTabKind — Terminal · Claude · Browser · Android · IOS · Device(R2, Device 는 플랫폼을 모르는 기기 탭).
TerminalWorkspace.renameTab(tabId, name) — 앞뒤 공백을 떼고 비면 null(R7). 같은 값이면 자신을 돌려준다.
TerminalWorkspace.addTab(…, devicePlatform)
이음새
core/ui 의 DeviceChoice.platform: DeviceChoicePlatform(Android · IOS). emulator 기능이 EmulatorPlatform 에서 채우고, 터미널 UI 가 terminal 도메인의 DevicePlatform 으로 옮긴다. 기능끼리 의존하지 않으므로 열거형이 둘이다(기기 화면)

결정: 첫 누름에 바로 고르고, 두 번째 누름을 직접 잰다 combinedClickable(onDoubleClick)·detectTapGestures(onDoubleTap) 는 더블클릭인지 가리려고 onClick 을 더블탭 시간(ViewConfiguration.doubleTapTimeoutMillis, 기본 300ms)만큼 미룬다. 탭 고르기는 가장 잦은 동작이라 매번 늦어지면 안 된다. 그래서 clickable 의 누름마다 곧바로 고르고, 앞 누름과의 간격이 doubleTapTimeoutMillis 안이면 입력칸을 연다. 간격은 같은 제목의 pointerInput 이 Initial 단계에서 본 누름의 uptimeMillis 로 잰다 — 벽시계로 재면 테스트의 가상 시계와 어긋난다. 탭을 두 번 누르면 첫 누름에 이미 골라져 있으므로 결과가 같다. 버린 후보: 길게 누르기 — 터치에서 길게 누르기는 탭 끌기가 쓴다(탭 끌어 놓기). ✎ 버튼 — 탭 폭 120dp 에 ✕ 와 종류 아이콘까지 있어 버튼 하나 더 둘 자리가 없다. 오른쪽 클릭 메뉴 — 터치에서 안 된다.
결정: 종류는 program 과 저장된 플랫폼에서 계산하고 따로 저장하지 않는다 kind 를 따로 저장하면 program 과 어긋날 수 있다. 기기 플랫폼만은 탭 밖(기기 목록)에서 오고, 목록은 메뉴가 열릴 때만 세므로(기기 화면) 고를 때 탭에 적는다. 기기 이름을 적는 것과 같은 이유다. 플랫폼을 deviceId 모양(시뮬레이터 UDID 등)으로 짐작하는 방법은 id 형식이 emulator 기능의 내부라 버렸다.
결정: 종류 색은 테마 색이 아니라 고정 색이다 M3 색 역할은 뜻(주·보조·오류)을 나타내지 브랜드를 나타내지 않아 다섯 종류에 맞는 역할이 없다. Claude·Android 는 사람들이 이미 아는 색(Claude 주황, Android 초록)이 있어 그 색에 가깝게 두고, 라이트·다크의 surfaceVariant·primaryContainer 위에서 모두 보이는 중간 밝기로 골랐다. 터미널은 가장 흔한 탭이라 글자색 그대로 두어 다른 종류가 눈에 띄게 한다.

한계

  • 이 기능 전에 저장된 기기 탭은 Android 인지 iOS 인지 몰라 일반 기기 아이콘이다(R3). 그 탭을 닫고 다시 열면 플랫폼이 붙는다.
  • 입력칸이 떠 있어도 화면 단축키(⌘T·⌘W·⌘D 등)는 화면이 먼저 가로챈다(분할 그룹 R11). ⌘W 를 누르면 편집 중인 탭이 닫힌다. ⌘A·⌘C·⌘V 처럼 화면이 쓰지 않는 조합은 입력칸으로 간다.
  • 두 번째 누름이 첫 누름과 다른 탭이면 입력칸이 열리지 않는다. 간격 재기는 탭마다 따로다.
