새 패널 제목·폴더

"새 패널" 을 누르면 제목과 폴더를 받는 창이 뜨고, 그 폴더에서 터미널이나 Claude 를 연 패널을 만든다. 둘 다 비워 두면 지금처럼 "패널 N" 이 홈 디렉터리에서 열린다.

사용자 지시

패널 추가할 때 제목 입력할 수 있도록 해줘(선택으로 하고 미입력 시 기본값) 그리고 폴더 지정할 수 있도록 해줘. 해당 폴더에서 claude나 터미널 열 수 있도록

2026-09-24 대화. "기본값" 은 지금의 "패널 N"(패널 R2)으로 읽었다. "해당 폴더에서 claude나 터미널 열 수 있도록" 은 패널을 만들 때 첫 탭을 터미널로 열지 Claude 로 열지 고르고, 그 탭이 지정한 폴더에서 시작하는 것으로 읽었다. 폴더는 제목과 달리 "선택" 이라는 말이 없지만, 비워 두면 지금처럼 홈에서 시작하는 것으로 둔다 — 폴더를 꼭 넣어야 패널을 만들 수 있게 하면 지금 되는 일이 막힌다.

요구사항

  1. R1. 패널 목록 아래 "새 패널" 버튼을 누르면 곧바로 패널을 만들지 않고 "새 패널" 창이 뜬다. 창에는 제목 입력란, 폴더 입력란, 그리고 "취소"·"터미널" 버튼이 있다. Claude 를 실행할 수 있는 타깃(Claude 실행)에서는 "Claude (YOLO)" 버튼도 있다. 창이 뜨면 제목 입력란이 포커스를 받는다.
  2. R2. 제목은 넣지 않아도 된다. 앞뒤 공백을 떼고, 비어 있으면 "패널 N"(N 은 지금 패널 수 + 1)이다. 제목 입력란은 비어 있는 동안 그 기본 제목을 흐리게 보여 준다.
  3. R3. 폴더도 넣지 않아도 된다. 경로를 직접 입력할 수 있고, 폴더 선택 창이 있는 타깃에서는 "찾아보기" 버튼으로 고른 폴더의 절대 경로가 입력란에 채워진다. 고르다 취소하면 입력란은 그대로다. 앞뒤 공백을 떼고, 비어 있으면 폴더가 없는 패널이다. ~ 또는 ~/ 로 시작하는 경로는 그 셸의 홈 디렉터리 기준으로 읽는다.
  4. R4. "터미널" 을 누르면 그 제목·폴더를 가진 패널에 셸 탭 하나, "Claude (YOLO)" 를 누르면 Claude 탭 하나(새 sessionId, 패널 R11)를 넣어 목록 끝에 붙이고 선택한다. 첫 탭은 그 폴더에서 시작한다. 창은 닫힌다.
  5. R5. 제목·폴더 입력란에서 Enter 는 "터미널" 과 같다.
  6. R6. "취소", Esc, 창 바깥 누르기는 아무것도 만들지 않고 창을 닫는다. 다음에 창을 열면 입력란은 비어 있다.
  7. R7. 패널의 폴더는 패널과 함께 저장되고 앱을 다시 켜도 그대로다(패널 R9). 폴더가 있는 패널은 목록 줄에서 이름 아래에 폴더 경로가 한 줄로 보이고, 넘치면 앞쪽을 줄인다(폴더 이름이 보이게).
  8. R8. 패널 안에서 새로 여는 탭(그룹의 +, 빈 패널의 +, 분할)은 그 그룹에서 선택돼 있던 탭의 작업 디렉터리에서 시작하고, 그것을 모르면(빈 패널 포함) 패널의 폴더, 그것도 없으면 홈에서 시작한다(패널 R8 을 넓힌다).
  9. R9. 폴더가 없거나 디렉터리가 아니면 탭은 홈에서 시작한다. 창에서 미리 막지 않는다(결정).
스코프에서 뺀 것
  • 만든 뒤 패널 폴더 바꾸기. 이름 바꾸기(패널 R3)처럼 붙일 수 있지만 지시는 "추가할 때" 다. 이미 열린 탭의 작업 디렉터리는 폴더를 바꿔도 따라가지 않으므로 뜻도 모호하다.
  • 처음 켤 때의 "패널 1". 창 없이 지금처럼 만든다(폴더 없음).
  • 최근 폴더 목록, 폴더 즐겨찾기. 지시에 없다.

공통 구현

TerminalPanelDto(id, name, directory: String? = null, root, focusedGroupId)
도메인 규칙
TerminalWorkspace.addPanel(name: String? = null, directory: String? = null, program = Shell, claudeSessionId: String? = null) — R2·R3 의 공백 떼기와 기본값, R4 의 첫 탭. 첫 탭의 directory 는 패널 폴더다. 기본 제목은 nextPanelName 이고 창의 placeholder 도 이것을 쓴다.
TerminalWorkspace.startDirectory(groupId: Long?): String? — R8. 그룹(null 이면 포커스된 그룹)에서 선택된 탭의 디렉터리, 없으면 선택된 패널의 폴더. ViewModel 에 있던 directoryOf 를 도메인으로 옮긴다.
저장
TerminalPanelDto.directory. 없는 키는 null 로 읽으므로 이전 파일도 그대로 읽힌다
홈 펼치기
internal fun expandHome(path: String, home: String): String — :feature:terminal:data commonMain. 셸을 띄우는 쪽(플랫폼 startDirectory)이 부른다(R3). 홈이 플랫폼마다 달라 도메인에 두지 않는다
상태
TerminalViewModel.addPanel(name: String, directory: String, program: TerminalProgram) — Claude 면 여기서 sessionId 를 만든다. 창이 떠 있는지와 입력 중인 글자는 화면 안의 remember 다
UI

공급
internal expect val directoryPicker: DirectoryPicker? — :feature:terminal:ui. null 이면 이 타깃에 폴더 선택 창이 없어 "찾아보기" 를 숨긴다.
internal fun interface DirectoryPicker { suspend fun pick(initial: String?): String? } — 고른 폴더의 절대 경로, 취소면 null. 창을 여는 명령이라 suspend 다
결정: 폴더가 있는지 창에서 미리 확인하지 않는다 확인하려면 UI 가 파일 시스템을 한 번 묻는 플랫폼 조회가 하나 더 생긴다. 셸을 띄우는 쪽은 이미 "없으면 홈" 으로 떨어지고(패널 R14), 저장된 폴더가 나중에 지워져도 같은 규칙으로 되살아나야 하므로 그 규칙 하나로 충분하다. 잘못 친 경로는 홈에서 뜬 셸의 프롬프트로 곧바로 드러난다. 한계에 적는다.
결정: 첫 탭 종류는 확인 버튼 두 개로 고른다 라디오·세그먼트로 종류를 고른 뒤 "만들기" 를 누르게 하면 누르는 횟수가 하나 늘고, Claude 를 못 쓰는 타깃에서는 선택지가 하나뿐인 컨트롤이 남는다. 그룹의 새 탭(+) 메뉴가 "터미널 / Claude (YOLO)" 로 바로 여는 것과 같은 모양이다. 기본(Enter)은 모든 타깃에 있는 터미널이다.

플랫폼별 판정

플랫폼판정어떻게문서
Android우회 미검증제목·폴더 경로 입력은 구현. 폴더 선택 창은 SAF 가 파일 경로가 아니라 content:// URI 를 줘서 셸이 들어갈 수 없다 — "찾아보기" 없이 경로를 직접 입력한다. Claude 는 불가라 버튼이 없다. ~ 는 filesDirandroid.html
iOS불가터미널 자체가 불가라 화면에 들어갈 수 없다. directoryPicker 는 nullios.html
JVM구현"찾아보기" 는 java.awt.FileDialog + apple.awt.fileDialogForDirectories → macOS NSOpenPanel(폴더만). ~ 는 user.homejvm.html
Web불가터미널 자체가 불가라 화면에 들어갈 수 없다. directoryPicker 는 nullweb.html

한계

  • 없는 경로나 오타는 경고 없이 홈에서 열린다(R9).
  • 폴더는 만들 때 한 번 정한다. 바꾸려면 새 패널을 만든다.
  • Android 에는 폴더 선택 창이 없다. 셸이 들어갈 수 있는 경로(앱의 filesDir 아래 등)를 직접 친다(Android).
