새 패널 제목·폴더

"새 패널" 을 누르면 제목과 폴더를 받는 창이 뜨고, "확인" 이 그 제목·폴더를 가진 패널을 그 폴더에서 연 Claude 탭 하나로 만든다. 다른 탭은 새 탭(+)으로 그 폴더에서 연다. 둘 다 비워 두면 "패널 N" 이고 폴더는 홈이다.

사용자 지시

패널 추가할 때 제목 입력할 수 있도록 해줘(선택으로 하고 미입력 시 기본값) 그리고 폴더 지정할 수 있도록 해줘. 해당 폴더에서 claude나 터미널 열 수 있도록

2026-09-24 대화. "기본값" 은 지금의 "패널 N"(패널 R2)으로 읽었다. "해당 폴더에서 claude나 터미널 열 수 있도록" 은 패널을 만들 때 첫 탭을 터미널로 열지 Claude 로 열지 고르고, 그 탭이 지정한 폴더에서 시작하는 것으로 읽었다. 폴더는 제목과 달리 "선택" 이라는 말이 없지만, 비워 두면 지금처럼 홈에서 시작하는 것으로 둔다 — 폴더를 꼭 넣어야 패널을 만들 수 있게 하면 지금 되는 일이 막힌다.

2026-09-25 대화. 빈 패널(그룹이 없는 패널)은 이미 있었다 — 마지막 탭을 닫으면 남는 상태(패널)다. 이 지시는 그 상태로 "시작" 도 할 수 있게 하라는 것으로 읽었다: 창의 "터미널"·"Claude (YOLO)" 두 버튼이 "확인" 하나가 되고, 만든 패널은 탭이 없다. 첫 탭은 빈 패널의 새 탭(+) 메뉴에서 연다. 앞 지시의 "해당 폴더에서 claude나 터미널 열 수 있도록" 은 그 + 가 패널 폴더에서 여는 것(R8)으로 계속 지킨다. "워크트리도 동일하게" 는 패널에서 git 워크트리 추가의 창에 그대로 적용한다.

처음 시작할 때 tab이 없는게 아니라 claude로 시작하도록 해줘.

2026-09-25 대화. "처음 시작할 때" 는 창의 "확인" 으로 만든 패널이 처음 뜰 때로 읽었다 — 탭이 없는 채로 시작하는 곳은 앞 지시로 빈 채 만들어지는 새 패널·워크트리 패널뿐이고, 앱을 처음 켤 때의 "패널 1" 은 이미 셸 탭 하나로 시작한다(스코프에서 뺀 것). 창은 앞 지시대로 "취소"·"확인" 만 두고, "확인" 이 만드는 패널이 패널 폴더에서 연 Claude 탭 하나를 갖는다. 워크트리 패널도 같다. 마지막 탭을 닫아 빈 패널이 되는 것은 그대로다.

요구사항

  1. R1. 패널 목록 아래 "새 패널" 버튼을 누르면 곧바로 패널을 만들지 않고 "새 패널" 창이 뜬다. 창에는 제목 입력란, 폴더 입력란, 그리고 "취소"·"확인" 버튼만 있다. 창이 뜨면 제목 입력란이 포커스를 받는다.
  2. R2. 제목은 넣지 않아도 된다. 앞뒤 공백을 떼고, 비어 있으면 "패널 N"(N 은 지금 패널 수 + 1)이다. 제목 입력란은 비어 있는 동안 그 기본 제목을 흐리게 보여 준다.
  3. R3. 폴더도 넣지 않아도 된다. 경로를 직접 입력할 수 있고, 폴더 선택 창이 있는 타깃에서는 "찾아보기" 버튼으로 고른 폴더의 절대 경로가 입력란에 채워진다. 고르다 취소하면 입력란은 그대로다. 앞뒤 공백을 떼고, 비어 있으면 폴더가 없는 패널이다. ~ 또는 ~/ 로 시작하는 경로는 그 셸의 홈 디렉터리 기준으로 읽는다.
  4. R4. "확인" 을 누르면 그 제목·폴더를 가진 패널을 목록 끝에 붙이고 선택한다. 창은 닫힌다. 패널은 그룹 하나에 Claude(YOLO) 탭 하나로 시작하고, 그 탭은 새 Claude 세션으로 R8 대로 패널 폴더에서 뜬다 — 그룹의 + 메뉴에서 "Claude (YOLO)" 를 고른 것과 같다. 다른 탭(터미널·웹 브라우저·기기)은 + 메뉴에서 연다.
  5. R4b. Claude 를 띄울 수 없는 타깃(isClaudeSupported 가 false)에서는 R4 의 Claude 탭 없이 빈 패널(그룹·탭 없음)로 시작한다. 오른쪽에 빈 패널 안내와 새 탭(+)이 뜨고(패널), 첫 탭은 그 + 메뉴에서 연다.
  6. R5. 제목·폴더 입력란에서 Enter 는 "확인" 과 같다.
  7. R6. "취소", Esc, 창 바깥 누르기는 아무것도 만들지 않고 창을 닫는다. 다음에 창을 열면 입력란은 비어 있다.
  8. R7. 패널의 폴더는 패널과 함께 저장되고 앱을 다시 켜도 그대로다(패널 R9). 폴더가 있는 패널은 목록 줄에서 이름 아래에 폴더 경로가 한 줄로 보이고, 넘치면 앞쪽을 줄인다(폴더 이름이 보이게).
  9. R8. 패널 안에서 새로 여는 탭(그룹의 +, 빈 패널의 +, 분할)은 그 그룹에서 선택돼 있던 탭의 작업 디렉터리에서 시작하고, 그것을 모르면(빈 패널 포함) 패널의 폴더, 그것도 없으면 홈에서 시작한다(패널 R8 을 넓힌다).
  10. R9. 폴더가 없거나 디렉터리가 아니면 탭은 홈에서 시작한다. 창에서 미리 막지 않는다(결정).
스코프에서 뺀 것
  • 만든 뒤 패널 폴더 바꾸기. 이름 바꾸기(패널 R3)처럼 붙일 수 있지만 지시는 "추가할 때" 다. 이미 열린 탭의 작업 디렉터리는 폴더를 바꿔도 따라가지 않으므로 뜻도 모호하다.
  • 처음 켤 때의 "패널 1". 창 없이 지금처럼 셸 탭 하나로 만든다(폴더 없음). 빈 패널·Claude 로 시작 지시는 "만들 때" 의 창에 대한 것이다. Claude 로 바꾸지 않는 이유는 결정에 있다.
  • 최근 폴더 목록, 폴더 즐겨찾기. 지시에 없다.

도메인 규칙
TerminalWorkspace.addPanel(name: String? = null, directory: String? = null, claudeSessionId: String? = null) — R2·R3 의 공백 떼기와 기본값. claudeSessionId 가 있으면 R4 대로 그 세션의 Claude 탭 하나를 가진 그룹 하나로, 탭의 directory 는 패널 폴더다. 없으면 R4b 의 빈 패널(root = null, focusedGroupId = null)이다. 빈 패널의 첫 탭은 addTab 이 만들고(패널), 그 directory 는 startDirectory 가 패널 폴더로 채운다. 처음 켤 때의 initial() 은 addPanel().addTab() 으로 셸 탭 하나를 넣는다. 기본 제목은 nextPanelName 이고 창의 placeholder 도 이것을 쓴다.
TerminalWorkspace.startDirectory(groupId: Long?): String? — R8. 그룹(null 이면 포커스된 그룹)에서 선택된 탭의 디렉터리, 없으면 선택된 패널의 폴더. ViewModel 에 있던 directoryOf 를 도메인으로 옮긴다.

결정: 처음 켤 때의 "패널 1" 은 셸 탭 그대로다 initial() 은 저장 파일이 없거나 그룹이 하나도 없을 때 data 계층이 부르고(TerminalWorkspaceSerializer.defaultValue, toDomain), 읽을 때마다 다시 만든다. Claude 탭은 무작위 sessionId 가 있어야 해서, 저장되기 전까지 읽을 때마다 다른 sessionId 가 나오고 화면이 띄운 세션과 저장된 탭이 어긋난다. 고정 sessionId 는 저장을 지운 뒤 예전 백그라운드 세션에 다시 붙는다. 지시가 가리키는 것도 탭 없이 시작하는 새 패널이라 바꾸지 않는다.
결정: 폴더가 있는지 창에서 미리 확인하지 않는다 확인하려면 UI 가 파일 시스템을 한 번 묻는 플랫폼 조회가 하나 더 생긴다. 셸을 띄우는 쪽은 이미 "없으면 홈" 으로 떨어지고(패널 R14), 저장된 폴더가 나중에 지워져도 같은 규칙으로 되살아나야 하므로 그 규칙 하나로 충분하다. 잘못 친 경로는 홈에서 뜬 셸의 프롬프트로 곧바로 드러난다. 한계에 적는다.
결정: 창은 종류를 묻지 않고 "확인" 이 Claude 탭으로 연다 처음(2026-09-24)에는 "터미널"·"Claude (YOLO)" 두 확인 버튼으로 첫 탭 종류를 골랐다. 빈 패널 지시(2026-09-25)로 버튼은 "확인" 하나가 됐고 패널은 탭 없이 시작했다. 그 뒤 Claude 로 시작 지시(같은 날)로 "확인" 은 Claude 탭 하나를 연다. 창은 여전히 "취소"·"확인" 뿐이고 Claude 를 쓸 수 있는 타깃인지도 모른다 — 그것은 ViewModel 이 claudeSessionId 를 넘길지로 가린다(R4b). 버린 후보: 창에 "터미널"·"Claude" 두 버튼을 되살리는 것 — 빈 패널 지시의 "취소/확인만" 과 어긋난다. ViewModel 이 addPanel 뒤에 addTab 을 따로 부르는 것 — 워크트리 패널은 use case 가 만들어 같은 규칙을 두 곳에 적어야 한다.

한계

  • 없는 경로나 오타는 경고 없이 홈에서 열린다(R9).
  • 폴더는 만들 때 한 번 정한다. 바꾸려면 새 패널을 만든다.
  • Android 에는 폴더 선택 창이 없다. 셸이 들어갈 수 있는 경로(앱의 filesDir 아래 등)를 직접 친다(Android).
