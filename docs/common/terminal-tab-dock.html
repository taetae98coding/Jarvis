탭 끌어 놓기 분할

터미널 상단 막대의 동작 버튼을 없애고, 새 탭은 탭 줄 끝의 + 로 그 패널에 붙인다. 창을 좌우·상하로 나누는 것은 탭을 끌어다 보이는 창의 어느 변에 놓느냐로 정한다.

사용자 지시

terminal에서 actions에 버튼 다 제거해줘.
그리고 패널에서 탭 옆에 + 버튼을 둬서 해당 패널에 탭을 추가하겠다는 느낌의 UI/UX를 구성해줘.
그리고 상하/좌우 탭 구분은 탭을 dragAndDrop 방식으로 지정할 수 있도록 해줘.

2026-09-24 대화. "actions" 는 터미널 상단 JarvisTopBar 의 오른쪽 동작 버튼 줄(좌우 분할 · 상하 분할 · 새 탭 · 닫기)로 읽었다. "탭 옆에 + 버튼" 은 탭 줄에서 마지막 탭 바로 오른쪽에 붙는 버튼으로 읽었다. "상하/좌우 탭 구분을 dragAndDrop 으로" 는 탭을 끌어다 지금 보이는 창 위에 놓으면 그 창이 나뉘고 끌어온 탭이 그 자리에 들어가는 것, 놓은 변(왼쪽·오른쪽·위·아래)이 좌우·상하를 정하는 것으로 읽었다. VS Code 가 편집기 탭을 다른 그룹 영역의 가장자리에 놓는 방식이다.

이 지시로 터미널 R5·R6·R7·R10 의 버튼과 Claude 실행 R1 의 + 자리가 바뀌었다. 두 문서는 그 자리에 이 문서를 가리킨다. 단축키는 지시에 없어 그대로 둔다.

뒤따른 분할 그룹 지시로 놓는 대상이 창에서 그룹으로, 옮겨지는 것이 탭의 분할 트리에서 탭 하나로 바뀌었고 가운데 영역(그 그룹에 넣기)이 생겼다. 아래 R4–R9 는 그에 맞춰 고쳤고, 충돌하면 그 문서의 R7–R9 가 우선한다. + 버튼(R2·R3)은 그룹마다 하나다.

왜 탭이 없을 때 탭 추가 버튼과 탭이 없을 때 탭 추가 버튼이 달라? 탭 있을 때 탭 추가버튼으로 통일해줘.

2026-09-25 대화. 앞의 "탭이 없을 때" 는 "탭이 있을 때" 의 오타로 읽었다. 빈 패널의 + 는 같은 컴포저블이었지만, 탭 줄 높이를 탭에 맞추는 IntrinsicSize.Min 줄에 탭이 없어서 아이콘 크기(small)까지 줄어든 작은 사각형으로 보였다. 이 지시로 R2 에 "빈 패널의 + 도 모양·크기가 같다" 가 붙었다.

요구사항

상단 막대와 새 탭

  1. R1. 터미널 상단 막대에는 뒤로 버튼과 제목 "터미널" 만 있다. 좌우 분할·상하 분할·새 탭·닫기 아이콘 버튼이 없다.
  2. R2. 그룹의 탭 줄에서 마지막 탭 바로 오른쪽에 새 탭(+) 버튼이 있다. 누르면 그 그룹의 탭 줄 끝에 탭이 붙고 선택된다(분할 그룹 R2). Claude 를 실행할 수 있는 타깃에서는 Claude 실행 R1 의 "터미널 / Claude (YOLO)" 메뉴가 이 버튼 아래로 뜨고, 아니면 곧바로 셸 탭이 열린다(R6). 패널에 그룹이 하나도 없어도 + 버튼은 남고, 그 + 는 탭이 있는 줄의 + 와 모양·크기와 세로 자리(탭 줄의 위쪽, 아래 내용과의 간격)가 같다.
  3. R3. 새 탭은 그 그룹 안에서 열린다. 다른 패널을 골라도 그 패널의 그룹마다 + 가 있고, 누르면 그 그룹에 붙는다. 탭은 만든 패널을 벗어나지 않는다(패널 R5).

탭 끌어 놓기

  1. R4. 탭 줄의 탭을 끌어서 어떤 그룹의 변에 놓으면 그 그룹이 나뉘고, 끌어온 탭 하나짜리 새 그룹이 놓은 변 쪽에 생긴다(분할 그룹 R7). 왼쪽·오른쪽 변은 좌우 분할(SideBySide), 위·아래 변은 상하 분할(Stacked)이다. 왼쪽·위에 놓으면 새 그룹이 앞(first), 오른쪽·아래에 놓으면 뒤(second)다. 비율은 0.5 다. 가운데에 놓으면 나누지 않고 그 그룹의 탭 줄 끝에 들어간다.
  2. R5. 끌어온 탭은 원래 그룹에서 빠진다. 그 그룹이 비면 사라지고 형제가 자리를 채운다. 옮겨진 탭의 셸·Claude 세션은 끊기지 않고 화면과 스크롤백이 그대로다.
  3. R6. 놓은 뒤 끌어온 탭이 선택되고, 놓인 그룹(변이면 새 그룹, 가운데면 그 그룹)이 포커스를 받는다.
  4. R7. 놓을 자리는 그룹 영역의 네 변에서 안쪽으로 25% 띠가 각각 그 변이고, 그 안쪽이 가운데다. 띠가 겹치는 모서리는 더 가까운 변이다(분할 그룹 R9).
  5. R8. 끄는 동안 포인터를 따라 끌던 탭의 이름이 적힌 칩이 움직인다. 포인터가 그룹 위에 있으면 놓일 자리가 강조색으로 덮여 결과가 미리 보인다 — 변이면 그 절반, 가운데면 그룹 전체. 그룹 밖이면 강조가 없다.
  6. R9. 그룹 밖에 놓거나, 자기 그룹의 가운데에 놓거나, 탭이 하나뿐인 그룹의 탭을 자기 그룹의 변에 놓으면 아무 일도 일어나지 않는다(결과가 지금과 같다). 그런 자리에서는 강조도 없다. 탭이 둘 이상인 그룹의 탭을 자기 그룹의 변에 놓으면 그 탭이 새 그룹으로 떨어져 나간다.
  7. R10. 마우스는 탭을 누른 채 터치 슬롭만큼 움직이면 끌기가 시작된다. 터치는 탭을 길게 누른 뒤 움직여야 시작된다 — 그냥 옆으로 밀면 탭 줄이 스크롤된다. 끌기가 시작되지 않고 뗀 것은 탭 선택(누름)이다.
  8. R11. 놓아서 바뀐 배치는 다른 변경과 같이 저장된다(패널 R9).
  9. R12. ⌘D(좌우 분할) · ⌘⇧D(상하 분할) · ⌘T(새 탭) · ⌘W(포커스된 창 닫기)와 나머지 단축키(터미널 R12)는 그대로다.
스코프에서 뺀 것
  • 탭 순서 바꾸기(탭 줄 안에서 끌어 놓기), 탭을 다른 패널로 옮기기(패널 목록에 놓기), 창 하나만 떼어 다른 탭으로 옮기기. 지시는 "상하/좌우 탭 구분" 이다.
  • 창을 창 위에 놓아 자리를 바꾸기. 놓는 것은 탭이고, 놓이는 것은 창이다.
  • 새 창을 여는 다른 진입점(빈 창 위의 + 등). 빈 패널은 패널 R7 의 안내 글과 탭 줄의 + 로 충분하다.
  • 가운데 영역에 놓았을 때의 별도 동작. VS Code 의 가운데는 "그 그룹으로 옮기기" 인데 이 앱에는 그룹이 없다. 네 삼각형이 창 전체를 덮는다(R7).

공통 구현

도메인
enum class DockEdge { Left, Right, Top, Bottom, Center } — splitDirection(Left·Right → SideBySide, Top·Bottom → Stacked, Center → null), placesFirst(Left·Top).
TerminalWorkspace.dockTab(tabId, groupId, edge) — 탭을 원래 그룹에서 빼고(비면 그룹을 지운다), 변이면 대상 그룹을 Split(direction, first, second) 로 바꿔 한쪽에 그 탭 하나짜리 새 Group 을 넣고, 가운데면 대상 그룹의 tabs 끝에 붙인다(R4–R6). R9 의 경우는 그대로 돌려준다. 사라지는 탭이 없으므로 TerminalWorkspaceChange.removedTabs 가 비어 세션이 멈추지 않는다(R5).
상태
TerminalViewModel.dockTab(tabId, groupId, edge). 끄는 중인 탭·포인터 위치·그룹의 경계는 화면에서만 쓰는 값이라 ViewModel 에 두지 않는다
UI
TerminalScreen — 상단 막대에서 동작 버튼을 뺀다(R1). TerminalTabRow 끝에 NewTabButton(R2). 빈 패널도 같은 NewTabButton 을 쓴다. 탭 줄은 IntrinsicSize.Min 이라 버튼이 fillMaxHeight 로 탭 높이를 따라가는데, 탭이 없으면 줄 높이를 정할 것이 버튼뿐이다. 그때 aspectRatio(1f, matchHeightConstraintsFirst = true) 는 intrinsic 높이를 콘텐츠 너비(아이콘 small)로 정해 버튼이 아이콘 크기로 줄어든다. 그래서 TerminalNewTabButton 은 heightIn(min = TerminalTabDefaults.height()) 로 탭 높이를 최소로 둔다. height() 는 rememberTextMeasurer 로 잰 제목 한 줄(아이콘 small 보다 작으면 아이콘)에 위아래 spacing.s 를 더한 값이다. 화면 루트를 Box 로 감싸 끌기 칩을 맨 위에 그린다.
TerminalTabDrag.kt — TerminalTabDragState(remember): 끌고 있는 탭 id·이름, 화면 좌표의 포인터 위치, 창 id → LayoutCoordinates. 그룹은 자기 탭 id 목록과 함께 등록되고 target() 이 R7·R9 대로 대상 그룹과 자리를 계산한다(자기 그룹의 가운데, 탭 하나뿐인 자기 그룹의 변은 건너뛴다). Modifier.terminalTabDragSource(...) 가 R10 의 제스처를 pointerInput 으로 만든다: 첫 포인터가 PointerType.Mouse 면 viewConfiguration.touchSlop 만큼 움직인 뒤, 아니면 awaitLongPressOrCancellation 을 지나야 시작하고, 그 뒤 drag() 가 끝날 때까지 이동을 소비한다. 마우스에 awaitTouchSlopOrCancellation 을 쓰지 않는 이유는 그 함수가 마우스에는 터치 슬롭의 1/144(0.125dp)만 주어, 누르는 동안의 1px 떨림에도 끌기가 시작돼 탭 선택(클릭)이 사라지기 때문이다.
PaneTree 의 잎(그룹)은 onGloballyPositioned 로 좌표를 등록하고, 대상이면 TerminalDropPreview 상자를 겹친다(R8).
공급
해당 없음. 플랫폼 코드가 없다
결정: 끌기는 Compose 의 dragAndDropSource/dragAndDropTarget 이 아니라 pointerInput 제스처로 만든다 Compose Multiplatform 1.12.1 의 Modifier.dragAndDropSource 는 플랫폼의 시스템 끌어 놓기를 부른다. 데스크톱은 AwtDragAndDropManager 가 java.awt.dnd.DropTarget 을 창에 붙이고 Swing TransferHandler(ComposeTransferHandler)로 네이티브 드래그 세션을 시작한다. Android 는 View.startDragAndDrop, iOS 는 UIDragInteraction 이다. 이 API 는 앱·창 사이에 데이터(Transferable, ClipData)를 옮기려고 있는 것이라 (1) 옮길 데이터가 없는데 DragAndDropTransferData 를 만들어야 하고, (2) 드래그 중의 그림자는 플랫폼이 그려 데스크톱과 Android 의 모양이 다르며, (3) 네이티브 드래그 세션이 도는 동안 Compose 는 포인터 이벤트를 받지 못해 미리 보기 상자를 우리가 그릴 수 없고, (4) skiko 헤드리스 UI 테스트(runComposeUiTest)에는 AWT 창이 없어 자동으로 확인할 수 없다. 탭은 이 화면 안에서만 움직이므로 시스템 끌어 놓기가 필요 없다.
pointerInput 으로 만들면 네 플랫폼이 같은 코드와 같은 모양이고, performMouseInput 으로 테스트한다. 버린 다른 후보: Modifier.draggable 은 한 축만 따라가 변을 고를 수 없다. detectDragGestures 는 터치에서도 슬롭만 넘으면 시작해 탭 줄의 가로 스크롤을 빼앗는다 — 마우스에만 그 규칙을 쓰고 터치는 detectDragGesturesAfterLongPress 와 같은 길게 누르기로 시작한다(R10). 포인터 종류는 첫 PointerInputChange.type 으로 안다.
결정: 놓는 것은 탭 하나이고 대상은 그룹이다 처음(패널 → 탭 → 분할 트리)에는 탭의 분할 트리를 통째로 옮겼고 대상은 잎(창)이었다. 분할 그룹 뒤로는 탭이 그룹의 원소라 옮기는 단위가 탭 하나고, 대상은 잎인 그룹이다. 변은 split() 이 포커스된 그룹을 Split 으로 바꾸는 것과 같은 규칙(replaceGroup)을 쓰고, 가운데는 addTab 과 같은 자리에 붙인다.
결정: 결과가 지금과 같은 자리는 놓을 수 없는 자리다 처음에는 선택된 탭(보이는 창의 주인)만 놓을 수 없었다. 그룹 뒤로는 규칙이 "놓아도 배치가 바뀌지 않는 자리" 로 일반화됐다: 자기 그룹의 가운데, 탭이 하나뿐인 자기 그룹의 변. 그런 자리에서 강조를 띄우면 놓았을 때 아무 일도 없어 어긋나므로 강조도 없다. 끌기 시작 때 탭을 선택으로 바꾸지 않는 것은 그대로다 — 누르자마자 선택하면 그룹의 보이는 창이 바뀌어 끌던 손 아래의 화면이 흔들린다.

한계

  • 그룹을 통째로 닫는 버튼은 없다. 탭의 ✕ 로 하나씩 닫으면 마지막에 그룹이 사라진다(분할 그룹).
  • 탭 줄이 스크롤될 만큼 탭이 많으면, 끄는 동안 탭 줄은 스크롤되지 않는다. 대상은 창이므로 탭 줄을 스크롤할 필요가 없다.
  • 끌어 놓기는 같은 패널 안에서만 일어난다. 다른 패널의 그룹은 보이지 않아 놓을 수 없다.
