패널에서 git 워크트리 추가·지우기

폴더가 git 저장소 안에 있는 패널은 목록 줄에 + 가 붙고, 누르면 브랜치 이름과 기준 브랜치를 받아 git worktree add 로 워크트리를 만든 뒤 그 폴더에서 연 Claude 탭 하나를 가진 패널을 원래 패널 아래에 들여써서 붙인다. 워크트리 패널 줄에는 기준 브랜치와 지금 체크아웃한 브랜치가 함께 보인다. 워크트리 패널도 다른 패널처럼 새 탭(+)·좌우·상하 분할을 가진다. 워크트리 패널의 ✕ 는 창을 띄워 워크트리·브랜치와 폴더를 함께 지울지 고르게 한다.

사용자 지시

패널로 지정한 곳에 git을 지원하면 패널에 + 버튼도 같이 추가해서 + 버튼 누를 시 새로운 워크트리 만들도록 해줘. 워크트리 만들면 마치 패널로 하듯 오른쪽에 탭과 좌우분할 등이 노출되어야해. 그리고 워크트리는 main worktree 패널 하위에 속하도록 UI/UX 제공해줘.

용어

git 을 지원하는 패널
폴더(새 패널 제목·폴더의 directory)가 git 작업 트리 안에 있는 패널. 폴더가 없는 패널, git 저장소가 아닌 폴더, git 을 실행할 수 없는 타깃의 패널은 지원하지 않는다
main 패널
+ 를 누른 패널. 워크트리 패널의 부모다. 지시의 "main worktree 패널" 이다. 폴더가 저장소의 main 워크트리인지 다른 워크트리인지는 가리지 않는다
워크트리 패널
+ 로 만든 패널. parentId 로 main 패널을 가리키고, 폴더는 새 워크트리의 최상위 폴더다
main 워크트리
git 용어. 저장소의 .git 디렉터리를 직접 가진 작업 트리(git rev-parse --git-common-dir 의 부모). 새 워크트리 폴더의 기본 위치를 정할 때만 쓴다
현재 브랜치
워크트리가 지금 체크아웃한 브랜치(git branch --show-current). HEAD 가 떨어져 있으면(detached) 없다. 폴더마다 관측하는 상태라 셸에서 git switch 하면 따라 바뀐다
기준 브랜치(base branch)
새 브랜치를 만드는 시작점. 지시의 "base branch". 브랜치 이름뿐 아니라 git 이 받는 커밋 표현(origin/main, 태그, SHA)이면 된다. 기본값은 + 를 누른 패널의 현재 브랜치다

요구사항

  1. R1. git 을 지원하는 패널의 목록 줄에는 이름 바꾸기(✎) 앞에 + ("워크트리 추가") 버튼이 있다. 지원하지 않는 패널에는 없다. 화면이 열려 있는 동안 폴더가 git 저장소가 되거나 아니게 되면(예: 셸에서 git init) 일정 간격 안에 버튼이 따라 나타나거나 사라진다.
  2. R2. + 를 누르면 "새 워크트리" 창이 뜬다. 창에는 브랜치 입력란, 기준 브랜치 입력란, 폴더 입력란, "취소"·"확인" 버튼만 있다. 창이 뜨면 브랜치 입력란이 포커스를 받는다.
  3. R2b. 기준 브랜치의 기본값은 + 를 누른 패널의 현재 브랜치다 — main 패널에서 누르면 main 패널의 브랜치, 워크트리 패널에서 누르면 그 워크트리의 브랜치. 그 패널의 HEAD 가 떨어져 있어 현재 브랜치가 없으면 비어 있다. 사용자가 고칠 수 있고, 앞뒤 공백을 떼고 비어 있으면 기본값을 쓴다. 기본값도 비어 있으면 + 를 누른 패널 폴더의 지금 HEAD 가 시작점이다.
  4. R3. 브랜치는 비울 수 없다. 앞뒤 공백을 떼고 비어 있으면 "확인" 이 비활성이고 Enter 도 아무 일도 하지 않는다.
  5. R4. 폴더의 기본값은 main 워크트리 옆의 <main 워크트리 폴더 이름>-worktrees/<브랜치> 다. 브랜치를 치는 동안 기본값이 따라 바뀌고, 폴더 입력란을 한 번 직접 고치면 더 따라가지 않는다. 앞뒤 공백을 떼고 비어 있으면 기본값을 쓴다. ~·~/ 는 홈 기준이다(새 패널 R3).
  6. R5. "확인" 을 누르면 main 패널의 폴더가 속한 저장소에 git worktree add 로 워크트리를 만든다. 브랜치가 저장소에 없으면 기준 브랜치(없으면 지금 HEAD)에서 그 이름의 새 브랜치를 만들어 체크아웃하고(-b <브랜치> <폴더> [<기준>]), 있으면 기준 브랜치와 무관하게 그 브랜치를 체크아웃한다. 기준 브랜치가 저장소에 없는 이름이면 git 이 거부하고 그 문구가 창에 보인다(R6). 브랜치·기준 브랜치·폴더 입력란에서 Enter 는 "확인" 과 같다.
  7. R6. 만드는 동안 창은 남고 버튼과 입력란은 비활성이다. git 이 실패하면(이미 다른 워크트리가 체크아웃한 브랜치, 이미 있는 폴더, 권한 없음 등) 창은 남고 git 의 오류 문구가 창 안에 보이며 고쳐서 다시 누를 수 있다. 성공하면 창이 닫힌다.
  8. R7. 성공하면 그 워크트리 폴더를 폴더로, 브랜치 이름을 제목으로 하는 패널이 생겨 선택된다. 패널은 만든 브랜치와 창에 넣은 기준 브랜치(비었으면 없음)를 기억한다. 패널은 그 워크트리 폴더에서 뜬 새 Claude(YOLO) 세션 탭 하나로 시작하고, Claude 를 띄울 수 없는 타깃에서는 빈 패널이다(새 패널 R4·R4b·R8). 워크트리 패널은 다른 패널과 같은 것이다 — 탭을 열면 탭 줄·분할 창이 뜨고 새 탭, 좌우·상하 분할, 끌어 놓기, 이름 바꾸기, 닫기가 그대로 된다(패널·그룹·끌어 놓기).
  9. R8. 워크트리 패널은 목록에서 main 패널 바로 아래에, main 패널의 다른 워크트리 패널들 뒤에 들여써서 놓이고 이름 앞에 브랜치 아이콘이 붙는다. 한 단계만 있다 — 워크트리 패널에도 + 가 있고(폴더가 git 저장소이므로) 누르면 같은 main 패널 아래에 형제로 생긴다.
  10. R8b. 워크트리 패널 줄에는 이름 아래, 폴더 위에 브랜치 줄 <기준 브랜치> → <현재 브랜치> 가 있다. 현재 브랜치는 그 폴더의 워크트리에서 관측한 값이고, 관측할 수 없으면(폴더가 지워짐, HEAD 가 떨어짐, git 이 없는 타깃) 만들 때의 브랜치다. 기준 브랜치를 기억하지 않는 패널(비워서 만들었거나 이전 버전이 저장한 파일)은 → 없이 현재 브랜치만 보인다. 현재 브랜치를 관측도 기억도 못 하면 브랜치 줄이 없다. 이름을 바꿔도 브랜치 줄은 그대로다.
  11. R9. 부모 관계와 브랜치·기준 브랜치는 패널과 함께 저장되어 앱을 다시 켜도 그대로다(패널 R9). 저장 파일의 부모가 없어졌으면 최상위 패널로 읽는다.
  12. R10. 워크트리 패널이 아닌 패널(main 패널 포함)의 ✕ 는 창 없이 곧바로 닫는다. main 패널을 닫으면 그 아래 워크트리 패널도 함께 닫히고, 이때 디스크의 워크트리·브랜치·폴더는 모두 남는다(사라진 Claude 탭의 세션은 패널 R12 대로 멈춘다). 닫아서 패널이 하나도 남지 않게 되는 닫기는 하지 않고 그 줄에 ✕ 가 없다.
  13. R11. 워크트리 폴더가 나중에 지워졌으면 다른 패널과 같이 탭은 홈에서 시작한다(새 패널 R9). 패널은 남고 + 는 사라진다(R1).
  14. R12. 워크트리 패널의 ✕ 를 누르면 "워크트리 닫기" 창이 뜬다. 창에는 패널의 현재 브랜치(R8b 의 관측 값, 없으면 줄 없음)와 워크트리 폴더, 체크박스 "워크트리·브랜치 지우기"·"폴더도 지우기", "취소"·"확인" 버튼이 있다. 두 체크박스는 창이 뜰 때마다 켜져 있다. 그 폴더의 워크트리를 관측할 수 없거나(폴더가 지워짐, git 이 없는 타깃) 관측한 워크트리가 main 워크트리면 지울 워크트리가 없으므로 창 없이 패널만 닫는다(R10 과 같다).
  15. R13. "워크트리·브랜치 지우기" 를 끄면 "폴더도 지우기" 는 꺼진 채로 보이고 누를 수 없다. 다시 켜면 "폴더도 지우기" 는 끄기 전 값으로 돌아온다.
  16. R14. "확인" 은 고른 것을 지운 뒤 패널을 닫는다(선택·탭 정리는 R10 의 닫기와 같다).
    • 둘 다 켬: git worktree remove 로 워크트리 폴더와 저장소의 워크트리 기록을 지우고, 그 워크트리가 체크아웃하고 있던 브랜치를 지운다.
    • "워크트리·브랜치 지우기" 만: 저장소의 워크트리 기록과 브랜치를 지우고 폴더는 남긴다. 남은 폴더는 파일이 그대로인 보통 폴더다(.git 파일이 없어 git 저장소가 아니다).
    • 둘 다 끔: 패널만 닫는다. 디스크는 그대로다.
    지우는 브랜치는 "확인" 을 누른 순간 그 워크트리가 체크아웃하고 있는 브랜치다 — 패널이 기억한 만들 때의 브랜치가 아니다(셸에서 git switch 했으면 바뀐 브랜치). HEAD 가 떨어져 있으면 브랜치는 지우지 않고 워크트리만 지운다. 브랜치는 병합 여부와 무관하게 지운다.
  17. R15. 폴더에 커밋하지 않은 변경이나 추적하지 않는 파일이 있으면 폴더를 지우지 않는다 — git 이 거부하고 그 문구가 창에 보이며 워크트리·브랜치·패널은 그대로다. "폴더도 지우기" 를 끄고 다시 누르면 파일을 남긴 채 워크트리·브랜치만 지운다.
  18. R16. 지우는 동안 창은 남고 체크박스와 버튼은 비활성이며 진행 표시가 돈다. git 이 실패하면 창은 남고 git 의 오류 문구가 창 안에 보이며 패널은 닫히지 않는다. 고쳐서 다시 누를 수 있다. 성공하면 창이 닫히고 패널이 닫힌다.
스코프에서 뺀 것
  • 변경이 있는 워크트리 폴더의 강제 삭제(git worktree remove --force). 커밋하지 않은 변경은 git 에도 남지 않아 되돌릴 수 없다. 기본값이 켜진 체크박스 하나로 날아가면 안 된다(R15). 셸에서 한다.
  • main 패널을 닫을 때 그 아래 워크트리들을 함께 지우기. 지시는 "worktree x" 다(R10).
  • 저장소에 이미 있는 워크트리를 목록에 불러오기(git worktree list). 지시는 "+ 로 새로 만들기" 다. 기존 워크트리는 "새 패널" 에서 그 폴더를 골라 연다.
  • 두 단계 이상의 중첩. 워크트리의 워크트리는 git 에서도 같은 저장소의 형제라 한 단계로 충분하다(R8).
  • 워크트리 패널 목록 접기·펼치기. 지시에 없다.
  • 기준 브랜치의 자동 완성·목록(git branch --list). 지시는 "설정할 수 있도록" 이다. 입력란 하나로 받고 틀리면 git 의 오류를 보인다(R5).
  • 이미 있는 브랜치를 기준 브랜치로 옮겨 붙이기(rebase). 기준 브랜치는 새 브랜치의 시작점일 뿐이고, 있는 브랜치는 그대로 체크아웃한다(R5).
  • 최상위(main) 패널 줄의 현재 브랜치 표시. 지시는 "워크트리 만들면" 이다. 관측 값은 있으므로(GitWorktree.branch) 필요해지면 줄만 더한다.

공급
internal expect fun createGitDataSource(): GitDataSource — :feature:terminal:data. GitDataSource 는 GitWorktreeRepository 와 같은 두 함수를 가진 internal 인터페이스이고, git 을 쓸 수 없는 타깃은 UnsupportedGitDataSource(늘 null, 늘 실패)다.
결정: git 저장소인지는 폴링으로 본다 파일 시스템 변경 알림(JVM WatchService)을 .git 에 걸 수도 있지만, 폴더가 저장소가 되는 일은 드물고 걸어야 할 곳이 패널마다 다르며 macOS 의 WatchService 는 JDK 안에서 폴링으로 구현돼 있다. 대신 observeByPolling(GitWorktreePollInterval) 로 수집하는 동안만 다시 읽고, 읽기는 먼저 .git 을 위로 찾아(프로세스 없이) 없으면 곧바로 null, 있을 때만 git rev-parse 한 번이다. 간격과 버린 후보는 JVM 스펙에 있다.
결정: 워크트리 패널은 평평한 panels 목록에 parentId 로 둔다 TerminalPanel.children 트리로 바꾸면 탭·그룹 id 로 패널을 찾는 모든 규칙(findPanel, replaceGroup)과 저장 형식이 바뀐다. parentId 하나면 기존 규칙은 그대로이고, 목록은 "최상위 → 그 자식들" 로 그리기만 하면 된다. 한 단계만 허용하므로(R8) 자식의 자식을 걷는 코드도 없다.
결정: 브랜치가 이미 있으면 그 브랜치를 체크아웃한다 늘 -b 로 새 브랜치만 만들면 "이미 있는 브랜치" 오류를 사용자가 셸로 돌아가 풀어야 한다. git rev-parse --verify refs/heads/<브랜치> 로 있는지 보고 있으면 git worktree add <path> <branch>, 없으면 git worktree add -b <branch> <path> [<기준>] 다. 있는 브랜치에는 기준 브랜치를 쓰지 않는다 — 시작점은 새 브랜치에만 뜻이 있고, 있는 브랜치를 옮겨 붙이는 것은 rebase 라 스코프 밖이다. 그래도 패널은 창에 넣은 기준 브랜치를 기억한다(사용자가 그렇게 말했으므로). 다른 워크트리가 이미 체크아웃한 브랜치는 git 이 거부하고 그 문구를 창에 보인다(R6).
결정: 기준 브랜치는 저장하고, 현재 브랜치는 관측한다 git 은 브랜치가 어디서 갈라졌는지 기억하지 않는다(--track 은 원격 브랜치에만, 로컬 기준에는 업스트림도 남지 않는다). 그래서 기준 브랜치는 만들 때 패널에 적어 둔다(TerminalPanel.baseBranch). 반대로 현재 브랜치는 셸에서 git switch 하면 바뀌는 상태라 저장한 값을 보이면 금방 틀린다 — 저장소 판정 폴링이 이미 폴더마다 돌고 있으므로 거기에 git branch --show-current 한 번을 더해 GitWorktree.branch 로 관측한다. 만들 때의 브랜치(TerminalPanel.branch)는 관측할 수 없을 때(폴더 삭제, detached, git 없는 타깃)의 대체값이다. git rev-parse --abbrev-ref HEAD 를 한 프로세스에 합치는 길은 버렸다 — 커밋이 없는 새 저장소(unborn)에서 rev-parse 전체가 128 로 끝나 저장소 판정까지 깨진다.
결정: 기준 브랜치의 기본값은 + 를 누른 패널의 현재 브랜치다 지시 "+눌렀을 때 워크트리가 기본 base branch" 다. main 패널에서 누르면 main 패널이 체크아웃한 브랜치, 워크트리 패널에서 누르면 그 워크트리의 브랜치가 들어간다 — 작업 브랜치 위에 이어서 파생 브랜치를 만드는 흐름이 그대로 된다. 이전 동작(+ 를 누른 패널 폴더의 지금 HEAD)과 기본값이 같으므로 창을 바꾸지 않고 누르면 결과가 같다. 저장소 폴더 대신 main 워크트리의 기본 브랜치(origin/HEAD)를 기본값으로 두는 후보는 버렸다 — 지시와 다르고, 원격이 없는 저장소에서는 값이 없다.
결정: 워크트리 패널의 ✕ 만 묻고, 변경이 있는 폴더는 지우지 않는다 패널은 화면의 배치이고 워크트리는 디스크의 작업이다. 워크트리 패널의 ✕ 는 창에서 지울 것을 고르게 하고(R12), main 패널의 ✕ 는 묻지 않고 패널만 닫는다 — 지시는 "worktree x" 이고, 워크트리 여러 개를 한 번에 지우는 것은 한 번 더 확인해야 할 만큼 크다. 체크박스 기본값이 켜짐이라 창에서 "확인" 만 눌러도 지워지므로, 되돌릴 수 없는 것만 막는다: 커밋하지 않은 변경은 git 에도 남지 않으니 --force 를 쓰지 않아 git 이 거부하게 둔다(R15). 브랜치는 병합하지 않았어도 -D 로 지운다 — 커밋은 git reflog 에 남아 되살릴 수 있고, -d 로 두면 워크트리에서 커밋한 브랜치는 거의 늘 병합 전이라 지우기가 매번 실패한다.
결정: 폴더를 남길 때는 .git 파일을 지우고 git worktree prune 한다 git worktree remove 는 폴더를 늘 지운다(폴더를 남기는 옵션이 없다). 연결된 워크트리의 .git 은 저장소의 .git/worktrees/<이름> 을 가리키는 한 줄짜리 파일이라, 이것을 지우면 그 폴더는 보통 폴더가 되고 저장소 쪽 기록은 가리키는 곳이 없어져 git worktree prune 이 걷어낸다. 그 뒤 브랜치는 어느 워크트리도 체크아웃하지 않아 지울 수 있다. .git/worktrees/<이름> 을 직접 지우는 길은 버렸다 — git 의 내부 구조에 기대고, prune 이 같은 일을 공식으로 한다. prune 은 다른 이미 죽은 워크트리 기록(폴더가 사라진 것)도 함께 걷는다 — 어차피 쓸 수 없는 기록이고, git worktree lock 한 것은 건드리지 않는다.

한계

  • + 는 폴링 간격(JVM 스펙) 뒤에 나타나거나 사라진다. git init 직후에는 잠깐 없다.
  • 워크트리 패널의 폴더는 만들 때 한 번 정한다. 워크트리를 옮기면(git worktree move) 패널은 옛 경로를 갖고 탭이 홈에서 열린다(R11).
  • main 패널을 닫으면 그 아래 워크트리는 모두 디스크에 남는다. 지우려면 워크트리 패널을 하나씩 ✕ 로 닫는다.
  • 변경이 있는 워크트리 폴더는 앱에서 지울 수 없다(R15). 커밋·정리하거나 셸에서 git worktree remove --force 한다.
  • 워크트리를 뗀 뒤 브랜치 지우기가 실패하면(드물다: 권한, 잠긴 ref) 워크트리는 이미 지워졌는데 패널이 남는다. 다시 "확인" 하면 워크트리가 없다는 오류가 나므로, "워크트리·브랜치 지우기" 를 끄고 닫은 뒤 브랜치는 셸에서 지운다.
  • 창은 열 때 관측한 워크트리로 브랜치·폴더를 보이지만, 실제로 지우는 브랜치는 "확인" 하는 순간 다시 읽은 값이다(R14). 창을 연 채 셸에서 브랜치를 바꾸면 보이는 글자와 지워지는 브랜치가 다를 수 있다.
  • 기준 브랜치는 만들 때 적어 둔 글자다. 그 뒤 기준 브랜치가 지워지거나 이름이 바뀌어도 브랜치 줄은 그대로다. 현재 브랜치는 폴링 간격 뒤에 따라온다.
  • 이미 있는 브랜치를 골라 만들면 기준 브랜치는 git 에 넘기지 않고 패널에만 남는다(결정 참고).
  • Android 에는 git 이 없어 + 가 없다(Android).
