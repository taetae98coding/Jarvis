패널에서 git 워크트리 추가

폴더가 git 저장소 안에 있는 패널은 목록 줄에 + 가 붙고, 누르면 브랜치 이름을 받아 git worktree add 로 워크트리를 만든 뒤 그 폴더를 가진 패널을 원래 패널 아래에 들여써서 붙인다. 워크트리 패널도 다른 패널처럼 탭·좌우·상하 분할을 가진다.

사용자 지시

패널로 지정한 곳에 git을 지원하면 패널에 + 버튼도 같이 추가해서 + 버튼 누를 시 새로운 워크트리 만들도록 해줘. 워크트리 만들면 마치 패널로 하듯 오른쪽에 탭과 좌우분할 등이 노출되어야해. 그리고 워크트리는 main worktree 패널 하위에 속하도록 UI/UX 제공해줘.

2026-09-25 대화.

용어

git 을 지원하는 패널
폴더(새 패널 제목·폴더의 directory)가 git 작업 트리 안에 있는 패널. 폴더가 없는 패널, git 저장소가 아닌 폴더, git 을 실행할 수 없는 타깃의 패널은 지원하지 않는다
main 패널
+ 를 누른 패널. 워크트리 패널의 부모다. 지시의 "main worktree 패널" 이다. 폴더가 저장소의 main 워크트리인지 다른 워크트리인지는 가리지 않는다
워크트리 패널
+ 로 만든 패널. parentId 로 main 패널을 가리키고, 폴더는 새 워크트리의 최상위 폴더다
main 워크트리
git 용어. 저장소의 .git 디렉터리를 직접 가진 작업 트리(git rev-parse --git-common-dir 의 부모). 새 워크트리 폴더의 기본 위치를 정할 때만 쓴다

요구사항

  1. R1. git 을 지원하는 패널의 목록 줄에는 이름 바꾸기(✎) 앞에 + ("워크트리 추가") 버튼이 있다. 지원하지 않는 패널에는 없다. 화면이 열려 있는 동안 폴더가 git 저장소가 되거나 아니게 되면(예: 셸에서 git init) 일정 간격 안에 버튼이 따라 나타나거나 사라진다.
  2. R2. + 를 누르면 "새 워크트리" 창이 뜬다. 창에는 브랜치 입력란, 폴더 입력란, "취소"·"터미널" 버튼이 있고 Claude 를 실행할 수 있는 타깃(Claude 실행)에서는 "Claude (YOLO)" 버튼도 있다. 창이 뜨면 브랜치 입력란이 포커스를 받는다.
  3. R3. 브랜치는 비울 수 없다. 앞뒤 공백을 떼고 비어 있으면 "터미널"·"Claude (YOLO)" 가 비활성이고 Enter 도 아무 일도 하지 않는다.
  4. R4. 폴더의 기본값은 main 워크트리 옆의 <main 워크트리 폴더 이름>-worktrees/<브랜치> 다. 브랜치를 치는 동안 기본값이 따라 바뀌고, 폴더 입력란을 한 번 직접 고치면 더 따라가지 않는다. 앞뒤 공백을 떼고 비어 있으면 기본값을 쓴다. ~·~/ 는 홈 기준이다(새 패널 R3).
  5. R5. "터미널" 또는 "Claude (YOLO)" 를 누르면 main 패널의 폴더가 속한 저장소에 git worktree add 로 워크트리를 만든다. 브랜치가 저장소에 없으면 지금 HEAD 에서 그 이름의 새 브랜치를 만들어 체크아웃하고(-b), 있으면 그 브랜치를 체크아웃한다. 브랜치·폴더 입력란에서 Enter 는 "터미널" 과 같다.
  6. R6. 만드는 동안 창은 남고 버튼과 입력란은 비활성이다. git 이 실패하면(이미 다른 워크트리가 체크아웃한 브랜치, 이미 있는 폴더, 권한 없음 등) 창은 남고 git 의 오류 문구가 창 안에 보이며 고쳐서 다시 누를 수 있다. 성공하면 창이 닫힌다.
  7. R7. 성공하면 그 워크트리 폴더를 폴더로, 브랜치 이름을 제목으로 하는 패널이 생겨 선택되고, 첫 탭(셸 또는 Claude, 새 sessionId)이 그 폴더에서 시작한다. 워크트리 패널은 다른 패널과 같은 것이다 — 오른쪽에 탭 줄·분할 창이 뜨고 새 탭, 좌우·상하 분할, 끌어 놓기, 이름 바꾸기, 닫기가 그대로 된다(패널·그룹·끌어 놓기).
  8. R8. 워크트리 패널은 목록에서 main 패널 바로 아래에, main 패널의 다른 워크트리 패널들 뒤에 들여써서 놓이고 이름 앞에 브랜치 아이콘이 붙는다. 한 단계만 있다 — 워크트리 패널에도 + 가 있고(폴더가 git 저장소이므로) 누르면 같은 main 패널 아래에 형제로 생긴다.
  9. R9. 부모 관계는 패널과 함께 저장되어 앱을 다시 켜도 그대로다(패널 R9). 저장 파일의 부모가 없어졌으면 최상위 패널로 읽는다.
  10. R10. 워크트리 패널을 닫으면 패널만 닫힌다. 디스크의 워크트리와 브랜치는 남는다. main 패널을 닫으면 그 아래 워크트리 패널도 함께 닫힌다(사라진 Claude 탭의 세션은 패널 R12 대로 멈춘다). 닫아서 패널이 하나도 남지 않게 되는 닫기는 하지 않고 그 줄에 ✕ 가 없다.
  11. R11. 워크트리 폴더가 나중에 지워졌으면 다른 패널과 같이 탭은 홈에서 시작한다(새 패널 R9). 패널은 남고 + 는 사라진다(R1).
스코프에서 뺀 것
  • 워크트리·브랜치 삭제(git worktree remove, git branch -d). 패널을 닫는 것은 되돌릴 수 있어야 하는데 작업 트리 삭제는 커밋하지 않은 변경을 날린다. 셸에서 한다.
  • 저장소에 이미 있는 워크트리를 목록에 불러오기(git worktree list). 지시는 "+ 로 새로 만들기" 다. 기존 워크트리는 "새 패널" 에서 그 폴더를 골라 연다.
  • 두 단계 이상의 중첩. 워크트리의 워크트리는 git 에서도 같은 저장소의 형제라 한 단계로 충분하다(R8).
  • 브랜치 시작점 고르기(origin/main 등). 지금 HEAD 에서만 만든다. 다른 시작점은 셸에서 git worktree add 를 직접 친다.
  • 워크트리 패널 목록 접기·펼치기. 지시에 없다.

공급
internal expect fun createGitDataSource(): GitDataSource — :feature:terminal:data. GitDataSource 는 GitWorktreeRepository 와 같은 두 함수를 가진 internal 인터페이스이고, git 을 쓸 수 없는 타깃은 UnsupportedGitDataSource(늘 null, 늘 실패)다.
결정: git 저장소인지는 폴링으로 본다 파일 시스템 변경 알림(JVM WatchService)을 .git 에 걸 수도 있지만, 폴더가 저장소가 되는 일은 드물고 걸어야 할 곳이 패널마다 다르며 macOS 의 WatchService 는 JDK 안에서 폴링으로 구현돼 있다. 대신 observeByPolling(GitWorktreePollInterval) 로 수집하는 동안만 다시 읽고, 읽기는 먼저 .git 을 위로 찾아(프로세스 없이) 없으면 곧바로 null, 있을 때만 git rev-parse 한 번이다. 간격과 버린 후보는 JVM 스펙에 있다.
결정: 워크트리 패널은 평평한 panels 목록에 parentId 로 둔다 TerminalPanel.children 트리로 바꾸면 탭·그룹 id 로 패널을 찾는 모든 규칙(findPanel, replaceGroup)과 저장 형식이 바뀐다. parentId 하나면 기존 규칙은 그대로이고, 목록은 "최상위 → 그 자식들" 로 그리기만 하면 된다. 한 단계만 허용하므로(R8) 자식의 자식을 걷는 코드도 없다.
결정: 브랜치가 이미 있으면 그 브랜치를 체크아웃한다 늘 -b 로 새 브랜치만 만들면 "이미 있는 브랜치" 오류를 사용자가 셸로 돌아가 풀어야 한다. git rev-parse --verify refs/heads/<브랜치> 로 있는지 보고 있으면 git worktree add <path> <branch>, 없으면 git worktree add -b <branch> <path> 다. 다른 워크트리가 이미 체크아웃한 브랜치는 git 이 거부하고 그 문구를 창에 보인다(R6).
결정: 패널 닫기는 워크트리를 지우지 않는다 패널은 화면의 배치이고 워크트리는 디스크의 작업이다. 닫기 하나로 커밋하지 않은 변경이 사라지면 되돌릴 수 없다. 삭제는 셸에서 git worktree remove 로 한다(스코프에서 뺀 것).

한계

  • + 는 폴링 간격(JVM 스펙) 뒤에 나타나거나 사라진다. git init 직후에는 잠깐 없다.
  • 워크트리 패널의 폴더는 만들 때 한 번 정한다. 워크트리를 옮기면(git worktree move) 패널은 옛 경로를 갖고 탭이 홈에서 열린다(R11).
  • 패널을 닫아도 워크트리는 남는다. 정리는 셸에서 git worktree remove 로 한다.
  • 새 브랜치의 시작점은 main 패널 폴더의 지금 HEAD 다. 다른 시작점은 셸에서 만든다.
  • Android 에는 git 이 없어 + 가 없다(Android).
