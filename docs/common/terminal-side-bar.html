터미널 오른쪽 사이드 바 (파일·Git)

터미널 화면 오른쪽 끝에 접었다 펼 수 있는 사이드 바가 있다. "파일" 구획은 선택된 패널 폴더의 파일 트리를 보이고, 파일을 누르면 그 내용을 읽기 전용 파일 탭으로 연다. "Git" 구획은 위에 스테이지된 변경과 스테이지되지 않은 변경을 보이며 항목마다 stage·unstage 하고, 아래에 커밋 그래프(선 그림·ref·메시지)를 보인다.

사용자 지시

터미널에서 오른쪽 사이드 바 만들자.
- 오른쪽 사이드 바는 접었다가 펼치기 기능을 제공해야해.

해당 사이드바에서는 일단 2가지 기능을 제공해.

1. 파일 목록보기.
- 파일 목록을 볼 수 있고 클릭 시 새 탭으로 열어서 내용을 확인할 수 있어야해.

2. git 작업하기.
- git 패널 상단에서는 stage, unstage 항목들이 노출되어야해.
- git 패널에서는 하단에 커밋 상태랑 메시지 같은 그래프를 볼 수 있어야해.

용어

사이드 바
터미널 화면에서 탭 영역 오른쪽에 붙은 세로 영역. 오른쪽 끝의 레일(아이콘 버튼 세로 줄)과 그 왼쪽의 내용으로 되어 있다. 접으면 내용만 사라지고 레일은 남는다
구획
내용에 보이는 것. "파일" 과 "Git" 둘 중 하나다. 지시의 "git 패널" 은 Git 구획이다(왼쪽 목록의 "패널" 과 다르다)
기준 폴더
사이드 바가 보이는 폴더. 선택된 패널의 폴더(새 패널 제목·폴더의 directory), 없으면 포커스된 탭의 작업 디렉터리다
파일 탭
파일 하나의 내용을 읽기 전용으로 보이는 탭(TerminalProgram.File). 셸을 열지 않는다
스테이지된 변경
git status 의 index 쪽(porcelain 의 X 글자) 변경. 다음 커밋에 들어간다
변경
작업 트리 쪽(porcelain 의 Y 글자) 변경과 추적하지 않는 파일. 아직 index 에 없다
커밋 그래프
git log --graph 가 그리는 선 그림과 커밋 줄. 지시의 "커밋 상태랑 메시지 같은 그래프" 다

요구사항

사이드 바

  1. R1. 터미널 화면에서 탭 영역 오른쪽 끝에 사이드 바가 있다. 레일은 위에서부터 접기·펼치기 버튼, "파일" 아이콘, "Git" 아이콘을 가진다.
  2. R2. 펼친 상태에서 접기 버튼을 누르면 내용이 사라지고 레일만 남으며, 탭 영역이 그만큼 넓어진다. 접힌 상태에서 펼치기 버튼을 누르면 마지막으로 보던 구획으로 다시 펼쳐진다. 접고 펼쳐도 탭과 셸은 그대로다.
  3. R3. 레일의 구획 아이콘을 누르면 그 구획으로 펼쳐진다. 이미 그 구획이 펼쳐져 있으면 접힌다. 펼쳐진 구획의 아이콘은 선택된 모양이다.
  4. R4. 터미널 화면을 처음 열면 사이드 바는 "파일" 구획으로 펼쳐져 있다. 접힘·구획은 화면에 있는 동안 유지되고 저장하지 않는다.
  5. R5. 기준 폴더는 선택된 패널의 폴더이고, 패널에 폴더가 없으면 포커스된 탭의 작업 디렉터리다. 패널을 바꾸면 따라 바뀐다. 둘 다 없으면 두 구획 모두 "폴더가 없는 패널입니다" 를 보인다.
  6. R6. 접혀 있는 동안, 또는 보이지 않는 구획은 디스크·git 을 읽지 않는다.

파일

  1. R7. "파일" 구획은 맨 위에 기준 폴더 경로를, 그 아래에 기준 폴더 바로 아래 항목을 폴더 먼저, 그 안에서 이름(대소문자 무시) 순으로 보인다. .git 은 보이지 않고, 다른 점(.)으로 시작하는 항목은 보인다. 기준 폴더가 없거나 읽을 수 없으면 "폴더를 읽을 수 없습니다" 다.
  2. R8. 폴더 줄을 누르면 그 폴더가 펼쳐져 아래 항목이 한 단계 들여써 같은 순서로 보이고, 다시 누르면 접힌다. 펼친 폴더는 기준 폴더를 바꿨다 돌아와도 펼쳐져 있다(화면에 있는 동안).
  3. R8a. 접힌 폴더를 펼칠 때, 그 폴더의 항목이 폴더 하나뿐이면(파일이 없고 폴더가 하나) 그 폴더도 함께 펼친다. 이것을 항목이 폴더 하나가 아닌 폴더(비었거나, 파일이 있거나, 둘 이상이거나, 읽을 수 없는 폴더)에 닿을 때까지 이어간다. a → b → c → d 에서 a 를 누르면 d 의 항목까지 보인다. 이어 펼치기는 FileTreeChainMaxDepth(32) 단계에서 멈춘다. 접을 때는 누른 폴더만 접히고, 안쪽 폴더는 펼친 채로 남아 다시 펼치면 그대로 보인다.
  4. R9. 파일 줄을 누르면 선택된 패널의 포커스된 그룹 탭 줄 끝에 그 파일의 파일 탭이 새로 열리고 선택된다. 패널에 그룹이 없으면 그룹을 만든다. 그 패널에 같은 파일의 파일 탭이 이미 있으면 새로 열지 않고 그 탭을 고른다.
  5. R10. 파일 탭의 종류 아이콘은 "파일" 이고 자동 제목은 파일 이름이다. 이름 바꾸기·닫기·끌어 놓기·분할은 다른 탭과 같다.
  6. R11. 파일 탭은 파일 내용을 UTF-8 로 읽어 고정폭 글자로, 줄 번호와 함께, 줄바꿈 없이 가로·세로 스크롤로 보인다. 글자를 골라 복사할 수 있고 고칠 수는 없다. 파일이 FileViewerMaxBytes(512 KiB)보다 크면 그만큼만 보이고 위에 "앞 512 KiB 만 보입니다" 가 붙는다. 앞 8 KiB 안에 NUL 바이트가 있으면 내용 대신 "텍스트가 아닌 파일이라 보일 수 없습니다", 파일이 없거나 읽을 수 없으면 "파일을 읽을 수 없습니다" 다.
  7. R12. 파일 탭은 경로와 함께 저장돼 앱을 다시 켜면 같은 파일로 되살아난다. 셸을 띄우지 않는다.
  8. R13. 목록과 파일 탭 내용은 디스크가 바뀌면(셸에서 파일을 만들고 지우고 고치면) 플랫폼 스펙의 간격 안에 따라간다.

Git

  1. R14. "Git" 구획은 기준 폴더가 git 작업 트리 안에 있으면 위 절반에 현재 브랜치(detached 면 "HEAD (detached)")와 "스테이지된 변경 (n)"·"변경 (n)" 두 목록을, 아래 절반에 "커밋 그래프" 를 보인다. 위·아래는 각각 따로 스크롤된다. 작업 트리 밖이거나 git 을 쓸 수 없는 플랫폼이면 "git 저장소가 아닙니다" 만 보인다.
  2. R15. 변경 항목 줄은 상태 글자, 파일 이름, 저장소 최상위 기준 상위 폴더를 보인다. 상태 글자는 M 수정, A 추가, D 삭제, R 이름 바꿈, C 복사, T 종류 바뀜, U 충돌, ? 추적 안 함이다. 한 파일이 index 와 작업 트리 양쪽에서 바뀌었으면(MM) 두 목록에 모두 나온다. 충돌 파일은 "변경" 에만 나온다. 목록은 경로 순이다. 목록이 비어 있으면 머리만 보인다.
  3. R16. "변경" 항목의 + ("stage")를 누르면 그 파일을 stage 하고, "스테이지된 변경" 항목의 − ("unstage")를 누르면 unstage 한다. 이름 바꿈의 unstage 는 옛 경로까지 함께 되돌린다. 목록 머리의 "모두 stage"·"모두 unstage" 는 그 목록 전체다. 명령이 끝나면 폴링 간격을 기다리지 않고 두 목록과 그래프를 다시 읽는다. 실패하면 git 의 오류 문구가 구획 위에 남고, 다음 명령이 성공하면 사라진다.
  4. R17. 변경 항목 줄을 버튼 밖에서 누르면 R9 처럼 그 파일(저장소 최상위 + 경로)의 파일 탭을 연다.
  5. R18. 커밋 그래프는 로컬 브랜치·원격 브랜치·태그·HEAD 에서 닿는 커밋을 최근 GitGraphMaxCommits(200)개까지 날짜순으로 보인다. 줄마다 왼쪽에 git log --graph 의 선 그림이 칸마다 색을 달리해 고정폭으로 있다. 커밋마다 두 줄이다 — 첫 줄에 그 커밋을 가리키는 ref(HEAD·브랜치·태그)와 메시지 제목, 둘째 줄에 짧은 해시·작성자·날짜(yyyy-MM-dd HH:mm). 둘째 줄의 이음선도 git 이 그려 그래프가 끊기지 않는다. 가로로 넘치면 줄 전체가 가로 스크롤된다. HEAD 가 가리키는 커밋의 제목은 굵다. 커밋이 없는 저장소는 "커밋이 없습니다" 다.
  6. R19. 두 목록과 그래프는 셸에서 git 을 쓰거나 파일을 고치면 플랫폼 스펙의 간격 안에 따라간다.
스코프에서 뺀 것 지시에 없는 것: 커밋 만들기, diff 보기, 줄 단위(hunk) stage, 브랜치 전환, 파일 편집·만들기·지우기·이름 바꾸기, 사이드 바 폭 조절, 접힘·구획·펼친 폴더 저장. 지시가 "일단 2가지" 라고 해서 나중 기능으로 둔다. 커밋은 셸이나 Claude 탭에서 하면 그래프가 따라온다(R19).

결정: 그래프는 git log --graph 의 글자 그림을 그대로 쓴다. 부모 목록(%P)으로 레인을 직접 배치해 선으로 그리는 방법을 버렸다. 병합·교차 배치 알고리즘을 새로 짜야 하고 git 과 모양이 달라진다. git 의 그림은 셸에서 보던 것과 같고, 칸마다 색을 입히면 레인이 구분된다. 형식은 %x1f 로 구분한 필드 뒤에 %n%x1e 를 붙여 커밋마다 둘째 줄을 만든다. git 은 여러 줄 형식의 이음선을 스스로 그리므로, 둘째 줄에 작성자·날짜를 놓아도 선이 끊기지 않는다. 둘 다 없는 줄은 선만 있는 줄이다.
결정: 기준 폴더는 패널 폴더가 먼저다. 포커스된 탭의 작업 디렉터리를 먼저 쓰면 셸에서 cd 할 때마다 트리가 통째로 바뀌고 펼친 폴더가 흩어진다. 패널 폴더는 사용자가 정한 작업 대상이다. 폴더 없이 만든 패널만 탭의 디렉터리로 채운다.
결정: 같은 파일은 패널 안에서 탭 하나. 누를 때마다 새 탭이면 같은 파일 탭이 쌓인다. 다른 패널에 있는 같은 파일 탭은 고르지 않는다 — 탭은 만든 패널에 속하고 패널을 건너뛰면 사용자가 보던 패널이 바뀐다.
결정: 이어 펼치기는 누른 순간의 디스크를 한 번 읽어 펼친 폴더 집합에 넣는다. TerminalSideBarViewModel.toggle 은 누른 폴더를 곧바로 펼치고, 이어서 ObserveDirectoryUseCase(path).first() 로 한 단계씩 읽어 폴더 하나뿐인 동안 그 경로를 더한다. 트리를 그릴 때마다 "폴더 하나뿐이면 펼친 것으로 친다" 로 계산하는 방법을 버렸다. 그러면 사용자가 안쪽 폴더를 접을 수 없고, 셸에서 파일을 하나 만들었다 지우면 펼침이 저절로 바뀐다. 폴더 심볼릭 링크는 따라가므로(a/link → a) 단계 상한을 둬 끝없이 펼치지 않는다. 플랫폼 API 를 새로 쓰지 않아 네 플랫폼이 같다.
결정: 펼친 폴더·접힘은 저장하지 않는다. 지시에 없고, 저장하면 작업 공간 파일 형식이 화면 상태로 늘어난다. 화면에 있는 동안만 유지한다.

한계

  • 파일 탭은 앞 512 KiB 만 보이고 UTF-8 이 아닌 인코딩은 글자가 깨진다(잘못된 바이트는 U+FFFD).
  • 그래프는 최근 200개 커밋까지다. 그보다 오래된 커밋은 셸에서 본다.
  • stage·unstage 는 파일 단위다. 줄 단위는 셸에서 git add -p 한다.
  • 기준 폴더가 저장소의 하위 폴더여도 Git 구획은 저장소 전체의 변경을 보인다(git 의 porcelain 경로는 최상위 기준이다).
  • 큰 저장소는 폴링마다 git status 가 느릴 수 있다. Git 구획이 보이는 동안만 돈다(R6).
  • Android 는 git 을 쓸 수 없고, 앱 샌드박스 밖 폴더는 읽을 수 없다(Android).
