패널 줄의 Claude 상태 표시

Claude 탭이 있는 패널(main 워크트리 패널과 그 아래 워크트리 패널 모두)은 목록 줄의 이름 옆에 그 패널의 Claude 가 지금 "작업 중" 인지, 차례를 끝내고 "응답 대기" 중인지, 끝난 것을 사용자가 "확인함" 인지, 걸어 둔 백그라운드 작업으로 "모니터링 중" 인지를 네 가지 표시 중 하나로 보인다.

사용자 지시

main worktree, 및 하위 worktree 옆에 status도 추가해서 해당 worktree에 하위 claude가 작업을 진행중인지 작업을 마쳐서 응답을 기다리는지 작업 마친 것을 사용자가 확인했는지 claude가 모니터링 진행중인지 4가지 상태 indicator로 표시해줘.

2026-09-25 대화. "main worktree, 및 하위 worktree" 는 워크트리의 최상위 패널 줄과 그 아래 들여쓴 워크트리 패널 줄로, "하위 claude" 는 그 패널의 Claude 탭이 붙어 있는 백그라운드 세션(패널 R11)으로 읽었다. "모니터링" 은 Claude 가 차례를 끝낸 뒤에도 스스로 걸어 둔 백그라운드 작업(Monitor, 백그라운드 명령, 예약된 깨우기)이 돌고 있는 상태로 읽었다.

용어

차례
사용자 입력 하나를 받아 Claude 가 도구를 부르고 답을 쓰는 한 바퀴. 답을 다 쓰고 입력을 기다리면 차례가 끝난 것이다.
백그라운드 작업
Claude 가 차례 안에서 걸어 두고 차례가 끝난 뒤에도 도는 것: Monitor, run_in_background 명령, 서브에이전트, ScheduleWakeup·/loop 의 예약된 깨우기, 세션 cron. 끝나거나 때가 되면 Claude 를 다시 깨운다.
본다
앱 창이 포커스를 가진 동안 그 탭이 터미널 화면에 보인다 — 선택된 패널에서, 그 탭이 속한 그룹의 선택된 탭이다.

뒤따른 버튼을 아래 줄로 지시로 표시는 이름 옆이 아니라 이름 아래 버튼 줄의 왼쪽 끝에 있다. R1 의 "이름 칸 오른쪽(+ ✎ ✕ 아이콘 앞)" 은 그 문서의 R6 으로 읽는다.

터미널 환경에서 claude 상태를 보여주잖아. 특히 워크트리에서 상태 보여줄 때 1개만 보여주는 것 같아. 하나의 워크트리에서 여러 claude를 사용하는 경우 상태 모두 보여주도록 해줘. (Row로 여러개 하면 될 것 같은데 검토해줘)

2026-09-25 대화, 뒤따른 지시. 이 지시로 R1 의 "표시 하나" 와 R4 의 "가장 앞선 상태 하나" 를 Claude 탭마다 하나씩으로 고쳤다(아래 R1·R4). 워크트리 패널만이 아니라 모든 패널 줄에 같이 적용한다 — 줄마다 규칙이 다르면 같은 목록 안에서 읽는 법이 둘이 된다. "Row" 는 검토 결과 한 줄로 두되 넘치면 다음 줄로 넘기는 흐름 배치로 했다(결정).

요구사항

  1. R1. 패널 목록의 줄마다, 그 패널에 Claude 탭이 하나 이상 있고 그중 하나라도 상태를 알 수 있으면 이름 칸 오른쪽(+ ✎ ✕ 아이콘 앞)에 상태를 아는 Claude 탭마다 상태 표시가 하나씩 있다. 상태를 알 수 없는 탭은 표시가 없다. Claude 탭이 없거나 어느 탭의 상태도 알 수 없으면 표시가 없다. main 워크트리 패널은 자기 탭만 센다 — 아래 워크트리 패널의 Claude 는 그 줄에 따로 보인다. 워크트리가 아닌 패널도 같은 규칙을 따른다.
  2. R2. Claude 탭 하나의 상태는 다음 넷 중 하나다.
    • 작업 중 — Claude 가 차례를 진행하고 있다.
    • 모니터링 중 — 차례는 끝났지만 백그라운드 작업이 남아 있어 Claude 가 스스로 다시 깨어날 수 있다. 사용자에게 묻고 멈춘 차례(입력이 필요함)는 백그라운드 작업이 있어도 모니터링이 아니다.
    • 응답 대기 — 차례가 끝났고(답을 마침, 질문함, 세션이 멈춤) 모니터링 중이 아니며, 끝난 뒤 사용자가 그 탭을 아직 보지 않았다.
    • 확인함 — 응답 대기와 같은 끝난 상태를 사용자가 끝난 뒤에 봤다.
    백그라운드 세션을 찾지 못한 탭(아직 한 번도 열리지 않음, 세션이 지워짐)은 상태를 알 수 없다.
  3. R3. 끝난 상태의 Claude 탭을 한 번이라도 보면 확인함이 된다. 보고 있는 동안 차례가 끝나도 곧바로 확인함이다. Claude 가 다시 일하고(사용자의 답 또는 백그라운드 작업이 깨움) 다시 끝나면 새 결과이므로 다시 응답 대기다. 앱 창이 포커스를 잃은 동안에는 보이는 탭도 보지 않은 것으로 친다.
  4. R4. 한 패널에 Claude 탭이 여럿이면 표시도 여럿이고, 순서는 패널 안 탭의 순서(분할 그룹이 있으면 왼쪽·위 그룹부터, 그룹 안에서는 탭 줄 순서)다. 상태가 바뀌어도 표시의 자리는 바뀌지 않는다 — 같은 자리가 같은 Claude 다. 줄의 폭에 다 들어가지 않으면 다음 줄로 넘어가고, 어떤 표시도 가려지지 않는다.
  5. R5. 상태는 Claude 쪽에서 바뀐 뒤 ClaudeActivityPollInterval(1초) 안에 줄에 반영된다. 터미널 화면이 떠 있는 동안에만 조회한다(상태 조회).
  6. R6. 확인한 기록은 탭과 함께 저장되어(패널 R9) 앱을 다시 켜도 확인함은 확인함이다. 탭을 닫으면 기록도 사라진다.
  7. R7. Claude 를 띄울 수 없는 타깃(Claude R6)에서는 어떤 줄에도 표시가 없다.
  8. R8. 표시를 누르면 그 패널이 선택되고 그 표시의 Claude 탭이 그 그룹에서 선택·포커스된다. 그래서 끝난 탭의 표시를 누르면 곧바로 확인함이 된다(R3).
스코프에서 뺀 것
  • 탭 줄(탭 이름 옆)의 상태 표시. 지시가 패널("worktree 옆") 줄이다.
  • Claude 가 묻는 내용(needs)·요약(detail) 글자, 알림·소리. 지시가 네 가지 표시다. 뒤따른 지시로 턴이 끝날 때의 알림은 Claude 턴 알림이 맡고, 요약은 그 알림 본문에만 쓴다.
  • "확인함" 으로 손으로 바꾸기(보지 않고 읽음 처리). 보면 바뀐다(R3).
  • 앱 안에서 직접 띄운 Claude(kind: interactive, 백그라운드 세션을 만들지 못했을 때의 대체 실행 — Claude 실행)의 상태. Claude Code 가 그 세션의 차례·백그라운드 작업을 기록하지 않는다. 그 탭은 상태를 알 수 없다.

공통 구현

도메인
sealed interface ClaudeActivity { Working; Monitoring; Finished(at: Long, needsInput, summary) } — 백그라운드 세션이 지금 하는 일. at 은 그 끝난 상태를 Claude Code 가 마지막으로 기록한 시각(epoch ms)이고 "새 결과인지" 를 가리는 열쇠다. needsInput·summary 는 Claude 턴 알림만 쓴다.
enum class ClaudeStatus { AwaitingReply, Working, Monitoring, Checked } — 표시 하나가 보이는 넷.
ClaudeActivity.status(checkedAt: Long?) — Finished(at) 는 checkedAt ≥ at 이면 Checked, 아니면 AwaitingReply.
TerminalTab.claudeCheckedAt: Long? — 사용자가 본 마지막 끝난 상태의 at(R6).
data class ClaudeTabStatus(tabId: Long, status: ClaudeStatus), TerminalPanel.claudeStatuses(activities): List<ClaudeTabStatus> — R1·R4. 상태를 아는 Claude 탭마다 하나, 패널 탭 순서. TerminalWorkspace.checkVisibleClaudeTabs(activities) — 보이는 Claude 탭 중 끝난 것의 claudeCheckedAt 을 그 at 으로 올린다. 바꿀 것이 없으면 같은 인스턴스다(R3).
ClaudeActivityRepository.observeActivities(sessionIds: Set<String>): Flow<Map<String, ClaudeActivity>> — 창 sessionId(TerminalTab.claudeSessionId)마다의 활동. 모르는 세션은 맵에 없다. cold. ObserveClaudeActivitiesUseCase.

UI

결정: 상태는 Claude Code 가 세션마다 쓰는 기록에서 읽고, "확인함" 만 앱이 기록한다 작업 중·끝남·백그라운드 작업은 Claude Code 의 백그라운드 서비스가 이미 세션마다 기록한다(플랫폼 스펙). 앱이 터미널 출력을 읽어 짐작하는 방법은 보이지 않는 창은 열지 않으므로(패널) 쓸 수 없고, Claude 훅(Stop·UserPromptSubmit)으로 앱에 알리는 방법은 사용자 설정 파일을 고쳐야 하고 앱이 꺼진 동안의 변화를 놓친다. 둘 다 버렸다. "사용자가 확인했는지" 는 Claude Code 어디에도 기록이 없다(2.1.282 의 세션 기록·claude agents --json 에 읽음 표시가 없다). 사용자가 결과를 보는 곳이 이 앱의 창이므로 앱이 본 시각을 기록한다. 시각 대신 Claude 가 기록한 끝난 시각(at)을 저장해서, 시계가 어긋나도 "이 결과를 봤다" 가 정확하다.
결정: 확인 기록은 탭에 둔다 탭은 이미 다시 열 때 필요한 것(프로그램·작업 디렉터리·sessionId)을 들고 저장된다. 따로 파일을 두면 탭이 닫힐 때 지우는 규칙이 하나 더 는다. 탭에 두면 탭과 함께 저장되고 함께 사라진다(R6). 쓰기는 끝난 결과를 처음 볼 때 한 번이라 저장이 잦아지지 않는다.
결정: 한 패널의 Claude 들을 하나로 합치지 않고 탭마다 보인다 처음에는 가장 급한 상태 하나(응답 대기 → 작업 중 → 모니터링 중 → 확인함)만 보였다. 한 워크트리에서 Claude 를 여럿 돌리면 하나가 작업 중인 동안 다른 하나가 끝났는지·몇 개가 남았는지 알 수 없어서 뒤따른 지시로 바꿨다. 순서는 급한 순이 아니라 탭 순서다 — 급한 순으로 늘어놓으면 상태가 바뀔 때마다 표시가 자리를 바꿔 어느 표시가 어느 Claude 인지 따라갈 수 없다. 배치 후보는 셋이었다. (1) 한 줄 Row + 넘치면 가로 스크롤 — 목록 폭 200dp 에 버튼 셋이 있으면 표시가 둘~셋만 보이고 나머지는 스크롤해야 보여서 "모두 보여 달라" 에 어긋난다. 버렸다. (2) 셋까지 보이고 나머지는 "+N" — 가려진 Claude 가 무슨 상태인지 모른다. 버렸다. (3) 채택: 버튼 앞 칸을 FlowRow 로 두어 넘치면 다음 줄로 넘긴다. Claude 가 둘~셋인 흔한 경우는 지금처럼 한 줄이고, 더 많으면 줄이 늘 뿐 다 보인다.
결정: 사용자에게 묻는 차례는 백그라운드 작업이 있어도 응답 대기다 Claude Code 는 차례를 끝낸 문장을 읽어 "입력이 필요함(blocked)" 인지 가린다. 그때는 사용자가 답해야 일이 나아가므로, 모니터가 돌고 있어도 응답 대기로 보인다.

한계

  • 상태의 뜻은 Claude Code 가 차례를 끝낸 문장을 읽어 가른 결과를 따른다. 답이 물음표로 끝나면 질문(입력이 필요함)으로 보는 식이라, Claude 가 끝냈다고 보는 것과 사용자가 보기에 끝난 것이 다를 수 있다.
  • Claude Code 가 끝난 세션의 기록을 결과와 무관하게 다시 쓰면(at 이 바뀌면) 새 결과로 보고 다시 응답 대기가 된다.
  • 창이 앞에 있기만 하면 본 것으로 친다. 사용자가 실제로 화면을 읽었는지는 알 수 없다.
  • 기록 형식은 Claude Code 2.1.282 에서 확인한 것이다. 버전이 바뀌어 형식이 달라지면 상태를 알 수 없게 되어 표시가 사라진다(플랫폼 스펙).
