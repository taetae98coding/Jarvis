기준 브랜치 자동 완성

"새 워크트리" 창의 기준 브랜치 입력란 아래에 저장소의 로컬 브랜치와 원격 추적 브랜치를 후보로 펴고, 줄마다 local 인지 어느 원격(origin)인지 라벨을 붙여, 누르면 입력란이 그 이름이 된다.

사용자 지시

base branch 입력할 때 자동완성 기능 제공해줘.
- local/origin 둘 다 조회되면 좋겠어.
- origin/local 구분해서 표시해줘.

2026-09-25 대화. "base branch 입력" 은 워크트리 R2b 의 기준 브랜치 입력란이다. 이 지시로 워크트리 스펙이 스코프에서 뺐던 "기준 브랜치의 자동 완성·목록" 이 들어온다.

요구사항

  1. R1. 후보는 + 를 누른 패널의 워크트리가 속한 저장소의 로컬 브랜치(refs/heads)와 원격 추적 브랜치(refs/remotes) 전부다. 원격의 기본 브랜치를 가리키는 심볼릭 ref(origin/HEAD)는 뺀다. 같은 저장소의 어느 워크트리 패널에서 + 를 눌러도 후보는 같다.
  2. R2. 후보 줄은 왼쪽에 git 에 넘길 이름(로컬 main, 원격 origin/main), 오른쪽에 구분 라벨을 가진다. 로컬은 local, 원격은 그 원격의 이름(origin, upstream 등)이다. 두 라벨은 색이 달라 글자를 읽지 않아도 구분된다.
  3. R3. 로컬 후보가 먼저, 원격 후보가 뒤다. 각 무리 안에서는 끝 커밋의 커밋 시각이 최근인 것이 먼저다.
  4. R4. 창이 뜬 뒤 사용자가 기준 브랜치 입력란의 글자를 고치기 전에는 모든 후보를 보인다. 고친 뒤에는 앞뒤 공백을 뗀 입력이 이름에 대소문자 없이 들어 있는 후보만 보이고, 입력이 비면 다시 모든 후보다. 실패로 다시 뜬 창(워크트리 R6)도 새 창이라 고치기 전에는 모든 후보다.
  5. R5. 목록은 한 번에 최대 50줄이다. 넘치는 후보는 입력으로 좁혀야 보인다.
  6. R6. 기준 브랜치 입력란이 포커스를 받으면 목록이 펴지고, 글자를 고칠 때마다 다시 펴진다. 보일 후보가 없으면(브랜치가 없는 저장소, 입력과 맞는 것이 없음, 아직 읽지 못함, git 을 쓸 수 없음) 펴지지 않는다.
  7. R7. 후보를 누르면 입력란이 그 이름이 되고, 커서가 끝으로 가고, 목록이 닫힌다. 목록 바깥을 누르거나 입력란이 포커스를 잃어도 닫힌다.
  8. R8. 자동 완성은 입력을 제한하지 않는다. 후보에 없는 글자(태그, SHA, 아직 fetch 하지 않은 이름)도 그대로 넣을 수 있고, 목록이 펴져 있어도 Enter 는 "확인" 이다(워크트리 R5). 만들기·실패·기본값 규칙은 워크트리 스펙 그대로다.
  9. R9. 원격 후보는 이 컴퓨터가 마지막으로 받아 둔 원격 추적 브랜치다. 창은 원격에 접속하지 않는다(fetch 하지 않는다).
  10. R10. 후보는 창이 떠 있는 동안만 읽는다. 떠 있는 동안 셸에서 브랜치를 만들거나 지우거나 fetch 하면 폴링 간격 뒤에 목록이 따라온다. 창이 닫히면 읽기를 멈춘다.
스코프에서 뺀 것
  • 창을 열 때 git fetch. 네트워크·인증을 기다리며 창이 늦어지고, 인증을 묻지 못해 실패하면(GIT_TERMINAL_PROMPT=0) 목록이 비는 이유를 설명할 곳이 없다. 받아 둔 것만 보인다(R9).
  • 태그·커밋 후보. 지시는 "local/origin" 이다. 태그는 입력란에 직접 넣으면 된다(R8).
  • 화살표 키로 후보 고르기. 목록은 포커스를 가져가지 않는 팝업이라 키 입력은 입력란에 남는다. 마우스로 누른다.
  • 브랜치 입력란(새 브랜치 이름)의 자동 완성. 지시는 base branch 다.

공통 구현

도메인
feature/terminal/domain/.../GitBranch.kt: data class GitBranch(val name: String, val remote: String? = null) — name 은 git 에 넘길 이름(원격이면 origin/main 처럼 원격 이름을 붙인 것), remote 는 원격 이름이고 로컬이면 null. GitWorktreeRepository.observeBranches(directory): Flow<List<GitBranch>> — directory 가 속한 저장소의 후보를 R1·R3 순서로 준다. 저장소가 아니거나 git 을 쓸 수 없으면 빈 목록. cold 이고 수집하는 동안만 다시 읽는다. ObserveGitBranchesUseCase 가 그대로 넘긴다

UI
NewWorktreeDialog(branches = …). TerminalPanelList 가 창을 띄우는 두 곳(+ 와 실패로 다시 뜬 창)에서 gitBranches(worktree.mainPath).collectAsStateWithLifecycle() 로 모아 넘긴다. 거르기(R4·R5)는 baseBranchSuggestions(branches, query, edited) 순수 함수
결정: 원격 후보의 이름은 원격 이름을 붙인 채로 넣는다 origin/main 을 누르면 입력란에 origin/main 이 들어가 git worktree add -b <브랜치> <폴더> origin/main 이 된다. 라벨만 보이고 이름은 main 으로 보이게 하는 길은 버렸다 — 로컬 main 과 원격 main 이 같은 글자로 두 줄 보이고, 누른 뒤 입력란의 글자와 목록의 글자가 달라진다.
결정: 로컬 먼저, 그 안에서 최근 커밋 순 지시의 "구분해서 표시" 는 라벨(R2)로 하고, 순서도 로컬·원격을 나눠 같은 무리가 붙어 보이게 한다. 이름순은 버렸다 — 브랜치가 많은 저장소에서 지금 작업 중인 브랜치가 목록 끝에 묻힌다. 최근 커밋 순이면 main·방금 쓴 브랜치가 위에 온다.
결정: 고치기 전에는 거르지 않는다 입력란은 + 를 누른 패널의 현재 브랜치로 시작한다(워크트리 R2b). 그 글자로 바로 거르면 포커스를 줄 때 그 이름을 담은 것만 보여 다른 브랜치를 고르려면 먼저 지워야 한다. 사용자가 한 글자라도 고친 뒤부터 거른다(R4).

검증

테스트확인하는 것소스셋
GitBranchParserTestR1·R3. for-each-ref 출력에서 로컬·원격을 가르고 로컬을 앞에 두되 무리 안의 순서는 그대로, origin/HEAD 같은 심볼릭 ref 는 빼고, / 가 든 원격 이름은 가장 긴 원격으로 가른다:feature:terminal:data jvmTest
GitDataSourceTestR1·R3·R9. 임시 저장소에 bare 원격을 붙여 올린 뒤 observeBranches 가 로컬을 앞에, origin/… 를 뒤에 주고 origin/HEAD 가 없으며, 워크트리 폴더에서 불러도 같은 목록, 원격에 새로 생긴 브랜치는 fetch 한 뒤에야 보이고, 저장소가 아닌 폴더는 빈 목록같음
JarvisAppTerminalWorktreeTestR2·R4·R6·R7. 기준 브랜치 입력란을 누르면 모든 후보가 라벨 local·origin 과 함께 펴지고, 글자를 고치면 걸러지고, 맞는 것이 없으면 목록이 없고, 후보를 누르면 입력란이 그 이름이 되고 목록이 닫히며 "확인" 이 그 이름으로 만든다:app:ui skikoTest

R9(fetch 하지 않음)는 GitDataSourceTest.remoteBranchesAreWhatWasLastFetched 가 본다 — 다른 복제본이 원격에 올린 브랜치는 이 저장소에서 fetch 하기 전에는 후보에 없고, fetch 한 뒤에 생긴다. R3 의 커밋 시각 순서는 git 의 --sort=-committerdate 에 맡기고, 파서가 무리 안의 순서를 바꾸지 않는 것만 GitBranchParserTest 가 본다(임시 저장소의 커밋은 같은 초에 생겨 시각으로 줄 세울 수 없다). R5(50줄)는 baseBranchSuggestions 의 take(NewWorktreeBaseSuggestionMaxCount) 하나이고, :feature:terminal:ui 에 테스트 소스셋이 없어 자동 테스트가 없다.

한계

  • 원격 후보는 마지막 fetch 시점의 것이다. 원격에 새로 생긴 브랜치는 셸에서 git fetch 한 뒤 폴링 간격 안에 보인다.
  • 브랜치가 50개를 넘는 저장소는 입력으로 좁혀야 나머지가 보인다(R5).
  • 키보드만으로는 후보를 고를 수 없다(스코프 밖). 이름을 끝까지 치면 된다.
