배터리 상태

홈의 "배터리" 카드가 이 앱이 돌고 있는 기기의 배터리 잔량, 충전 상태, 전원 종류, 저전력 모드를 보이고, 플랫폼이 알려 줄 때마다 바로 고친다.

사용자 지시

Android/iOS/JVM(Macos) 3개 플랫폼 구현하면 좋을 기능들 그리고 현제 스토어 도구나 생산성에서 순위 높은 앱들 찾아서 기능 추가해줘.

2026-09-26 대화.

지시를 받고 2026-09-26 에 스토어 순위를 봤다. Google Play 도구 상위의 올인원 유틸리티(Quick Tools 등)는 손전등·QR 과 함께 배터리 정보를 넣었고, Mac App Store 유틸리티 차트의 AlDente 류와 개발자 도구 차트의 Device Monitor² 는 배터리·시스템 상태를 보여 주는 앱이다. 세 플랫폼 모두 배터리 상태를 공개 API 나 명령으로 읽을 수 있고, 이미 있는 프로파일링 카드와 같이 "이 기기의 상태" 를 보는 카드라 골랐다.

요구사항

  1. R1. 홈 기능 그리드에 "배터리" 카드가 있고, 맨 끝(터미널 카드 다음)에 놓인다. 앞에 두면 뒤 카드들이 첫 화면 밖으로 밀려 나기 때문이다.
  2. R2. 배터리가 있으면 잔량을 정수 퍼센트(87%)와 막대로 보인다. 전원 없이 20%(Battery.LowBatteryPercent) 이하이면 막대를 오류 색으로 그린다.
  3. R3. 충전 상태를 "충전 중" · "방전 중" · "완충" · "전원 연결됨 (충전 안 함)" 중 하나로 보인다.
  4. R4. 플랫폼이 알려 주면 전원 종류("전원 어댑터" · "USB" · "무선 충전" · "도크" · "배터리"), 온도(31.5°C), 건강("좋음" · "과열" · …), 저전력 모드("켜짐" · "꺼짐") 줄을 더한다. 알려 주지 않는 항목은 줄을 그리지 않는다.
  5. R5. 배터리가 없는 기기(데스크톱 Mac 등)는 "배터리 없음", 플랫폼이 알려 주지 않거나 읽기에 실패하면 "측정 불가", 첫 값이 오기 전에는 "확인 중" 을 한 줄로 보인다. 앱이 죽거나 카드가 숨지 않는다.
  6. R6. 값은 상태 조회 규칙을 따른다. 플랫폼이 변경을 알려 주면(Android·iOS·Web) 그 신호마다 다시 읽고, 알려 주지 않는 JVM 만 BatteryPollInterval(5초)마다 읽는다. 카드가 보이지 않으면 등록을 풀거나 폴링을 멈춘다.
  7. R7. 같은 값이 다시 와도 화면을 다시 그리지 않는다(Android 는 전압만 바뀌어도 방송이 온다).
스코프에서 뺀 것
  • 충전 한도 설정(AlDente 의 핵심 기능). macOS 는 SMC 에 쓰는 권한 있는 헬퍼가, Android·iOS 는 시스템 권한이 필요하다.
  • 남은 시간 예측, 사이클 수, 설계 용량 대비 최대 용량. 플랫폼마다 있는 곳이 달라 한 줄로 맞출 수 없고, iOS 는 공개 API 가 없다.
  • 연결된 기기(에뮬레이터·실물 기기)의 배터리. 이 카드는 Jarvis 가 떠 있는 기기만 본다.
  • 경고 알림. 보여 주기만 한다.

UI

결정: 공급은 표본기가 아니라 Flow 다 프로파일링은 모든 플랫폼이 폴링이라 sample() 하나로 맞췄다. 배터리는 세 플랫폼이 변경 알림을 주고 JVM 만 폴링이라, 플랫폼마다 observeOnSignals·observeByPolling 중 맞는 것을 고르도록 Flow 를 그대로 내게 했다.
결정: 없는 기기와 모르는 기기를 나눈다 데스크톱 Mac 은 pmset 이 "배터리 없음" 을 분명히 알려 준다. 반면 iOS 시뮬레이터·Safari 는 그저 모른다. 둘을 한 문구로 합치면 노트북에서 읽기가 실패했을 때도 "배터리 없음" 이 되어 틀린 말을 하므로 나눴다.

한계

  • JVM 은 5초 간격이라 전원을 꽂고 뽑은 것이 최대 5초 늦게 보인다(jvm.html).
  • Web 은 배터리 없는 PC 에서도 Chromium 이 "충전 중, 100%" 를 돌려주도록 표준이 정했다. 그래서 "배터리 없음" 대신 "완충" 으로 보인다(web.html).
  • 항목마다 있는 플랫폼이 다르다. 같은 카드라도 Android 는 여섯 줄, Web 은 세 줄이다.
