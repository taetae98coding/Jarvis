개발자 도구 모음

사용자 지시

Android/iOS/JVM(Macos) 3개 플랫폼 구현하면 좋을 기능들 그리고 현제 스토어 도구나 생산성에서 순위 높은 앱들 찾아서 기능 추가해줘.

2026-09-26 대화(/goal).
왜 이 기능인가 2026-09-26 Mac App Store 개발자 도구 차트(apps.apple.com/us/mac/charts/6026)의 상위권에 RocketSim("30+ iOS Developer Utilities"), Hex Fiend, System Color Picker·ColorSlurp 같은 작은 변환 도구가 여럿 올라 있고, 같은 일을 한 앱에 모은 DevUtils·DevToys 가 개발자 사이에서 널리 쓰인다. Jarvis 는 개발자 머신과 기기를 다루는 앱이라, 브라우저를 열어 온라인 변환기에 토큰·로그를 붙여 넣지 않고 앱 안에서 끝내는 것이 가장 맞는 보탬이다. 변환은 순수 Kotlin 이라 Android·iOS·macOS·Web 네 곳에서 같은 결과를 낸다.

요구사항

  1. R1. 홈 그리드에 "개발자 도구" 카드가 있고, 누르면 개발자 도구 화면으로 간다. 화면의 뒤로 버튼은 홈으로 돌아간다.
  2. R2. 화면 위쪽의 칩 일곱 개(타임스탬프, Base64, URL, JSON, UUID, 해시, 색)로 도구를 고른다. 고른 칩 하나만 선택 상태다.
  3. R3. 타임스탬프: 정수를 넣으면 절댓값이 100,000,000,000 이상이면 밀리초, 아니면 초로 보고 UTC ISO-8601 과 초·밀리초를 보인다. ISO-8601 문자열을 넣으면 초·밀리초와 정규화한 ISO-8601 을 보인다. "지금" 버튼은 입력을 현재 Unix 초로 바꾼다. 둘 다 아니면 오류다.
  4. R4. Base64: 입력의 UTF-8 인코드 결과와 디코드 결과를 함께 보인다. "URL-safe" 스위치를 켜면 -·_ 알파벳을 쓴다. 디코드는 공백을 무시하고 패딩이 없어도 받으며, Base64 가 아니거나 UTF-8 이 아니면 그 줄만 오류다.
  5. R5. URL: RFC 3986 비예약 문자(A–Z a–z 0–9 - _ . ~)만 두고 나머지를 UTF-8 바이트의 %XX(대문자)로 바꾼 인코드 결과와, %XX 를 푼 디코드 결과를 함께 보인다. 잘못된 % 나 UTF-8 이 아닌 바이트는 디코드 줄만 오류다.
  6. R6. JSON: 두 칸 들여쓰기로 정렬한 결과와 공백을 뺀 한 줄 결과를 함께 보인다. 문법에 맞지 않으면 두 줄 모두 오류이고, 오류는 1부터 센 줄·칸과 까닭을 보인다.
  7. R7. UUID: "생성" 버튼이 무작위 UUID v4 를 개수(1·5·10)만큼 만든다. "대문자" 스위치가 켜져 있으면 대문자로 보인다. 화면을 처음 열면 하나를 만들어 둔다.
  8. R8. 해시: 입력의 UTF-8 바이트로 SHA-256·SHA-1·MD5 를 소문자 16진수로 보인다. 빈 입력도 해시한다.
  9. R9. 색: #RGB·#RRGGBB(# 생략 가능), rgb(r, g, b) 또는 r, g, b, hsl(h, s%, l%) 를 받아 HEX·RGB·HSL 세 표기와 그 색의 견본을 보인다. 범위를 벗어난 값은 오류다.
  10. R10. 결과 줄마다 복사 버튼이 있고, 누르면 그 줄의 값이 시스템 클립보드에 들어간다. 오류 줄에는 복사 버튼이 없다.
  11. R11. 마지막에 고른 도구와 도구마다의 입력이 앱을 껐다 켜도 남는다.
  12. R12. 입력이 비어 있으면 결과 줄이 없다(해시와 UUID 는 예외 — R7·R8).
스코프에서 뺀 것
  • 현지 시간대 표시. 공통 코드에서 시간대를 얻으려면 kotlinx-datetime 을 새로 들여야 한다. 지금은 UTC 만 보이고, 들일 때 TimestampConverter 한 곳에 줄을 더한다.
  • 화면의 색을 집어 오는 스포이트. Android·iOS 는 다른 앱 화면을 읽을 권한이 없어 세 플랫폼 공통으로 만들 수 없다.
  • 파일 해시와 16진 편집(Hex Fiend). 파일 선택기가 플랫폼마다 달라 이 기능의 범위를 넘는다.
  • URL 디코드의 + → 공백. application/x-www-form-urlencoded 규칙이지 RFC 3986 이 아니라서 + 는 그대로 둔다.

상태
고른 도구와 입력은 저장소의 Flow 를 stateIn(viewModelScope, WhileSubscribed(), read…()) 로 받는다. 결과는 (도구, 입력, URL-safe) 를 combine 해 변환기에 넘긴 값이다. URL-safe·UUID 개수·대문자·생성한 UUID·도구별 방금 친 입력은 저장하지 않는 화면 상태라 ViewModel 의 MutableStateFlow 다.
expect
없음. 클립보드는 Compose 의 LocalClipboardManager 가 플랫폼 구현을 준다.
결정: 변환을 domain 의 순수 Kotlin 으로 직접 짠다 domain 은 kotlinx-coroutines-core·koin-core 만 쓴다(모듈 구조). 그래서 JSON 은 kotlinx-serialization-json 대신 토크나이저 + 재귀 하강 파서를, 해시는 플랫폼 MessageDigest·CommonCrypto·crypto.subtle 대신 FIPS 180-4·RFC 1321 을 그대로 옮긴 구현을 쓴다. 해시를 플랫폼 API 로 하면 네 개의 actual 이 생기고 Web 의 crypto.subtle 은 비동기이며 MD5 가 없다. Base64 와 UUID 는 stdlib(kotlin.io.encoding.Base64, kotlin.uuid.Uuid)가 네 타깃에 같은 구현을 준다. JSON 파서는 숫자를 원문 그대로 옮겨 정밀도를 잃지 않고, 중첩이 512 단계를 넘으면 스택이 넘치기 전에 오류로 멈춘다.
결정: 입력 칸은 화면이 들고, 저장소는 뒤따라 적는다 입력 칸이 저장소 Flow 를 곧장 보여 주면, 저장이 신호로 돌아오기 전에 친 글자가 옛 값에 덮여 커서가 튄다(JVM Preferences 의 변경 알림은 다른 스레드에서 늦게 온다). 그래서 입력 칸은 TextFieldState 를 도구마다 한 번 저장된 값으로 채워 스스로 들고, 바뀔 때마다 SetDevToolInputUseCase 로 적는다. 결과는 ViewModel 이 도구마다 마지막으로 받은 입력(아직 없으면 저장값)으로 계산한다. 저장이 늦거나 실패해도 결과가 입력을 곧바로 따라간다. "지금" 버튼도 입력 칸에 직접 쓰고 같은 길로 저장한다.
결정: 복사는 LocalClipboardManager.setText Compose Multiplatform 1.12.1 의 LocalClipboard 는 공통 코드에서 글자 ClipEntry 를 만들 수 없다(터미널 선택 복사와 같은 사정, 터미널 선택). 폐기 예정인 LocalClipboardManager 를 쓰고, ClipEntry 에 공통 팩토리가 생기면 두 곳을 함께 옮긴다. 색 견본은 파싱한 채널로 Color(red, green, blue) 를 만든다. 사용자가 넣은 값이라 테마 토큰이 될 수 없고, 리터럴 규칙이 막는 Color(0x…) 상수가 아니다.

한계

  • 시간은 UTC 로만 보인다(스코프에서 뺀 것).
  • Web 은 HTTPS·localhost 가 아니면 복사가 조용히 실패한다(web.html).
  • 입력은 저장소 한 칸에 통째로 들어간다. 수 MB 의 JSON 을 붙여 넣으면 Android SharedPreferences·Web localStorage(보통 5 MB) 한도에 걸려 저장이 실패할 수 있다. 그때도 변환 결과는 보인다.
