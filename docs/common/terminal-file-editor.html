파일 탭 편집·꾸며 보기·빠른 스크롤

사이드 바의 파일 트리와 파일 탭 오른쪽에 끌어서 옮기는 빠른 스크롤 막대를 두고, 파일 탭에서 "편집" 을 눌러 내용을 고쳐 저장하며, 코드 파일은 문법 색으로, 마크다운 파일은 렌더링한 미리보기로 보인다.

사용자 지시

파일 매니저에서 FastScroller 추가하고 edit 할 수 있는 기능 추가해줘. 그리고 md, kt, swift 같은 파일들 예쁘게 보도록 구현할 수 있어?

2026-09-25 대화.

용어

파일 매니저
사이드 바의 "파일" 구획(트리)과 거기서 연 파일 탭을 함께 가리킨다
빠른 스크롤 막대
지시의 "FastScroller". 목록 오른쪽 끝의 세로 막대와 그 안의 손잡이. 손잡이를 끌면 목록이 그 비율의 자리로 곧장 옮겨 간다
읽기 보기
파일 탭의 기존 화면(사이드 바 R11, diff·줄 코멘트 포함). 마크다운 파일에서는 "원문" 이라고 부른다
편집 보기
"편집" 을 눌러 들어가는, 파일 전체를 고칠 수 있는 글 입력 칸
미리보기
마크다운 파일을 제목·목록·표·코드 블록 등으로 그린 화면
문법 색
확장자로 고른 언어의 키워드·문자열·주석·숫자 등에 다른 색을 칠하는 것

요구사항

빠른 스크롤 막대

  1. S1. 파일 트리, 파일 탭의 읽기 보기·편집 보기·미리보기는 내용이 보이는 높이보다 길면 오른쪽 끝에 빠른 스크롤 막대를 보인다. 내용이 다 보이면 막대가 없다.
  2. S2. 손잡이 높이는 (보이는 높이 ÷ 전체 높이) × 막대 높이이고 FastScrollerMinThumb(32dp) 보다 작지 않다. 손잡이 위치는 스크롤한 비율이다. 목록을 휠·드래그로 스크롤하면 손잡이가 따라간다.
  3. S3. 손잡이를 끌면 끈 만큼의 비율로 내용이 곧장 옮겨 간다. 손잡이 밖의 막대를 누르면 손잡이 가운데가 누른 자리로 가게 옮기고, 떼지 않고 끌면 이어서 끈다.
  4. S4. 막대는 평소 옅게(onSurfaceVariant 38%) 보이고, 마우스를 올리거나 끄는 동안 짙게(70%)·넓게 보인다. 막대는 내용 위에 겹쳐 그려서 내용 폭을 줄이지 않는다.

편집

  1. E1. 작업 트리 파일 탭(커밋 파일 탭이 아닌 것)의 내용이 텍스트이고 잘리지 않았으면(truncated 가 아니면) 탭 위 도구 줄에 "편집" 버튼이 있다. 바이너리·읽을 수 없음·512 KiB 로 잘린 파일, 커밋 파일 탭에는 없다.
  2. E2. "편집" 을 누르면 편집 보기로 바뀐다. 파일 전체가 고정폭 글자(codeTextStyle)로, 왼쪽에 줄 번호와 함께, 줄바꿈 없이 가로·세로로 스크롤되는 입력 칸에 들어가고 커서가 그 칸에 간다. 문법 색(H1)을 입력 칸에도 칠한다. diff 표시·요약과 줄 코멘트는 편집 보기에서 보이지 않는다.
  3. E3. 도구 줄의 "저장" 또는 ⌘S·Ctrl+S 가 입력 칸의 글자 전체를 UTF-8 로 그 파일에 덮어쓴다. 바뀐 것이 없으면 "저장" 은 누를 수 없고 단축키는 아무 일도 하지 않는다. 저장하는 동안 "저장 중…" 이고, 끝나면 편집 보기에 남은 채 "수정됨" 표시가 사라진다.
  4. E4. 저장이 실패하면 입력 칸의 글자를 그대로 두고 도구 줄에 "저장하지 못했습니다: <오류>" 를 보인다. 다음 편집·저장에서 문구가 사라진다.
  5. E5. 저장하지 않은 변경이 있으면 도구 줄에 "수정됨" 이 보인다. "닫기" 또는 Esc 는 변경이 없으면 곧장 읽기 보기로 돌아가고, 있으면 "저장하지 않은 변경을 버릴까요?" 창을 띄운다. 창의 "버리기" 는 변경을 버리고 읽기 보기로, "계속 편집" 은 창만 닫는다.
  6. E6. 편집 보기에 있는 동안 디스크의 파일이 바뀌면(R13 의 간격 안), 저장하지 않은 변경이 없으면 입력 칸을 새 내용으로 바꾸고, 있으면 입력 칸을 두고 "디스크의 파일이 바뀌었습니다 — 저장하면 덮어씁니다" 를 보인다. 저장한 직후 돌아온 자기 저장 결과는 바뀐 것으로 치지 않는다.
  7. E7. 편집 중인 글자와 편집 보기 여부는 탭마다 따로이고, 같은 그룹의 다른 탭을 골랐다 돌아오거나 터미널 화면을 떠났다 돌아와도 남는다. 탭을 닫으면 버린다. 앱을 끄면 저장하지 않은 변경은 남지 않는다.
  8. E8. 저장이 끝나면 읽기 보기는 폴링 간격을 기다리지 않고 곧장 저장한 내용을 다시 읽는다.

문법 색

  1. H1. 파일 탭의 읽기 보기와 편집 보기는 파일 이름으로 고른 언어(아래 표)의 토큰을 색으로 가른다: 키워드, 타입(대문자로 시작하는 이름), 함수 호출, 문자열, 숫자, 주석, 애노테이션(@·전처리기·셸 변수), 상수(true·null 등), 속성 키(JSON·YAML·TOML·XML 속성), 태그(XML·HTML).
  2. H2. 여러 줄에 걸친 블록 주석·여러 줄 문자열("""…""", 템플릿 리터럴, 원시 문자열)은 줄을 넘어서도 이어서 칠한다.
  3. H3. 표에 없는 파일은 예전처럼 한 색이다. diff 의 지운 줄은 그 줄만 따로 칠한다. 바탕색(diff·고른 줄)은 문법 색과 겹쳐 그대로 보인다.
  4. H4. 색은 라이트·다크 테마마다 따로 정한 팔레트를 쓴다. 읽기 보기는 색을 계산하는 동안 한 색으로 먼저 보이고, 다 되면 색을 입힌다. 편집 보기는 EditorHighlightMaxChars(200,000 글자)를 넘으면 칠하지 않는다.

마크다운 미리보기

  1. M1. .md·.markdown 파일 탭(커밋 파일 탭 포함)은 미리보기로 열린다. 도구 줄의 "미리보기"·"원문" 으로 바꾸고, 원문은 읽기 보기(문법 색·diff·줄 코멘트 그대로)다. 고른 쪽은 탭마다 앱이 켜져 있는 동안 남는다.
  2. M2. 미리보기가 그리는 것: ATX(#~######)·setext(===·---) 제목, 문단(줄바꿈은 공백, 줄 끝 공백 둘·\ 는 줄바꿈), **굵게**·*기울임*·~~취소선~~·`코드`, 링크 [글](주소)·<주소>·본문의 http(s)://, 이미지는 "🖼 대체 글" 링크, 글머리·번호 목록(중첩)과 작업 목록 - [ ]·- [x](☐·☑), 인용 >(중첩), 울타리 코드 블록(```언어 — 언어가 H1 표에 있으면 문법 색)·들여쓴 코드 블록, 가로줄, GFM 표(열 정렬 :--·:-:·--:). 그 밖(HTML 태그, 각주, 수식)은 글자 그대로 보인다.
  3. M3. 링크를 누르면 http·https·mailto 는 시스템 브라우저로 열고, 상대 경로(docs/a.md, ../README.md)는 이 파일의 폴더 기준으로 푼 파일의 파일 탭을 연다(R9). # 로 시작하는 문서 안 링크는 아무 일도 하지 않는다.
  4. M4. 미리보기 글자는 골라 복사할 수 있고, 디스크가 바뀌면(R13) 다시 그린다. 파일이 잘렸으면 "앞 512 KiB 만 보입니다" 가 붙고 읽은 만큼만 그린다. diff 요약(D2)은 미리보기에서도 도구 줄에 보인다.
  5. M5. 미리보기에서도 "편집" 을 누를 수 있고, 편집 보기(E2)는 원문을 고친다. 편집을 마치면 들어가기 전의 보기(미리보기·원문)로 돌아간다.
스코프에서 뺀 것 새 파일·폴더 만들기, 이름 바꾸기·지우기(트리 편집), 되돌리기·다시하기 기록(입력 칸 기본 동작 말고), 찾기·바꾸기, 자동 들여쓰기·괄호 짝 넣기, 자동 저장, 커밋 파일 탭 편집, 이미지 불러와 그리기, 미리보기와 원문 나란히 보기, 가로 빠른 스크롤. 지시는 "edit 할 수 있는 기능" 이라 열린 파일의 내용을 고쳐 저장하는 것까지로 둔다. 파일 만들기·지우기는 셸 탭에서 한다.

공통 구현

domain
FileRepository.writeFile(path, text): Result<Unit>(suspend 명령)과 WriteFileUseCase. 순수 함수 syntaxLanguageOf(path): SyntaxLanguage?, highlightSyntax(text, language): List<SyntaxToken>(전체 글 기준 위치), highlightLines(text, language): List<List<SyntaxToken>>(줄 기준 위치, 줄 나누기는 String.lines() 와 같다), parseMarkdown(text): List<MarkdownBlock>(블록: 제목·문단·코드·인용·목록·표·가로줄, 인라인: 글·코드·강조·굵게·취소선·링크·이미지·줄바꿈), resolveRelativePath(file, link): String?(M3)
data
OkioFileDataSource.writeFile 가 FileSystem.write(path) 로 덮어쓰고, 성공하면 그 경로의 observeFile 에 다시 읽을 신호를 보낸다(E8). UnsupportedFileDataSource.writeFile 은 실패다
UI
:core:designsystem 의 JarvisFastScroller(LazyListState·ScrollState 두 가지 입력). FileEditHost(앱 수명 싱글턴, 탭 id 마다 편집 상태·저장. LineCommentHost 와 같은 모양으로 화면을 떠나도 남는다 — E7)와 TerminalViewModel 의 탭별 마크다운 보기 선택(M1). TerminalFileViewer 가 도구 줄·읽기 보기·FileEditor·MarkdownPreview 를 고른다. 색은 SyntaxPalette(라이트·다크)
결정: 문법 색과 마크다운은 직접 짠 가벼운 해석기로 한다. dev.snipme:highlights, com.mikepenz:multiplatform-markdown-renderer 를 버렸다. 둘 다 Compose Multiplatform 버전에 묶여 있어 1.12.1 과 맞는 판을 따로 확인해야 하고, UI 모듈은 wasmJs 까지 컴파일하므로 네 타깃을 다 퍼블리시해야 한다. 또 읽기 보기는 diff·줄 코멘트를 줄마다 겹치므로 렌더러가 통째로 그리는 화면을 쓸 수 없고 토큰 위치만 필요하다. 해석기는 domain 의 순수 함수라 commonTest 로 확인한다.
결정: 편집 보기는 파일 전체를 입력 칸 하나에 넣는다. 줄마다 입력 칸을 두는 방식은 줄을 넘는 고르기·붙여넣기·지우기를 직접 만들어야 한다. 전체를 하나로 두면 고르기·복사·붙여넣기·실행 취소를 Compose 입력 칸이 준다. 잘린 파일(512 KiB 초과)은 뒷부분을 모르므로 편집하지 않는다(E1).
결정: 저장은 원자적 이동 없이 그 파일에 바로 덮어쓴다. 임시 파일에 쓰고 옮기는 방식은 심볼릭 링크를 일반 파일로 바꾸고, 하드 링크를 끊고, 권한·확장 속성을 잃는다. 편집 대상은 사용자가 셸에서도 만지는 작업 트리 파일이라 원래 파일을 그대로 두는 쪽을 골랐다.
결정: 빠른 스크롤 막대는 직접 그린다. Compose 의 VerticalScrollbar 는 데스크톱(desktopMain)에만 있고 Android 에는 없다. 공통 코드 하나로 두 타깃에 같게 보이도록 pointerInput 과 drawBehind 로 만든다. LazyListState 는 전체 높이를 모르므로 보이는 항목의 평균 높이 × 항목 수로 어림한다.

한계

  • 문법 색은 정규 문법 수준의 토큰 나누기라 문맥을 모른다. Kotlin 문자열 템플릿 ${…} 안도 문자열 색이고, 소프트 키워드(data·by 등)는 이름으로 쓰여도 키워드 색이다. 중첩 블록 주석(/* /* */ */)은 첫 */ 에서 끝난다.
  • 마크다운은 CommonMark 전체가 아니다. 강조 구분자는 가까운 짝을 찾는 방식이라 ***a** b* 같은 겹친 경우가 다르게 보일 수 있고, 참조 링크([a][1]), 각주, HTML 블록, 이미지 그리기는 없다.
  • 편집 보기의 입력 칸은 탭 글자를 글꼴의 탭 폭으로 그려 읽기 보기(공백 네 칸)와 들여쓰기 폭이 다를 수 있다.
  • 편집 보기는 파일 전체를 한 문단으로 배치해서, 수만 줄 파일은 타자마다 배치가 느릴 수 있다. 200,000 글자를 넘으면 색을 끈다(H4).
  • 편집 중에 탭을 닫거나 앱을 끄면 묻지 않고 버린다(E7).
  • 한글 등 입력기로 조합하는 중에는 Esc 를 입력기가 먼저 받아 조합을 끝내는 데 쓴다. 한 번 더 눌러야 E5 가 동작할 수 있다.
  • 저장 뒤 diff 표시는 다음 git 폴링(JVM 3초) 때 따라온다.
  • UTF-8 이 아닌 파일은 읽을 때 깨진 글자가 저장하면 그대로 파일에 쓰인다(U+FFFD).
