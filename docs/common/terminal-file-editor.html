파일 탭 편집·꾸며 보기·빠른 스크롤

사이드 바의 파일 트리와 파일 탭 오른쪽에 끌어서 옮기는 빠른 스크롤 막대를 두고, 파일 탭은 열자마자 편집 보기로 들어가 고친 내용을 알아서 저장하며, 코드 파일은 문법 색으로, 마크다운 파일은 렌더링한 미리보기로 보인다.

사용자 지시

파일 매니저에서 FastScroller 추가하고 edit 할 수 있는 기능 추가해줘. 그리고 md, kt, swift 같은 파일들 예쁘게 보도록 구현할 수 있어?

2026-09-25 대화.

파일 viewer는 자동으로 편집 모드로 들어가고 autoSave로 알아서 저장하도록 구현해줘.

2026-09-25 대화. 이 지시로 E2–E7·M1·M5 를 고쳤다. "편집" 을 눌러 들어가고 "저장"·"닫기" 로 끝내던 흐름이 없어졌다.

용어

파일 매니저
사이드 바의 "파일" 구획(트리)과 거기서 연 파일 탭을 함께 가리킨다
빠른 스크롤 막대
지시의 "FastScroller". 목록 오른쪽 끝의 세로 막대와 그 안의 손잡이. 손잡이를 끌면 목록이 그 비율의 자리로 곧장 옮겨 간다
읽기 보기
파일 탭의 고칠 수 없는 화면(사이드 바 R11, diff 줄 표시·줄 코멘트 포함). 편집할 수 없는 파일은 이 보기만 있고, 편집할 수 있는 파일은 "읽기 보기" 버튼으로 들어간다(E5)
편집 보기
파일 전체를 고칠 수 있는 글 입력 칸. 편집할 수 있는 파일 탭을 열면 처음부터 이 보기다
자동 저장
지시의 "autoSave". 고친 뒤 잠깐 손을 멈추면 누르지 않아도 파일에 쓰는 것(E3)
미리보기
마크다운 파일을 제목·목록·표·코드 블록 등으로 그린 화면
문법 색
확장자로 고른 언어의 키워드·문자열·주석·숫자 등에 다른 색을 칠하는 것

요구사항

빠른 스크롤 막대

  1. S1. 파일 트리, 파일 탭의 읽기 보기·편집 보기·미리보기는 내용이 보이는 높이보다 길면 오른쪽 끝에 빠른 스크롤 막대를 보인다. 내용이 다 보이면 막대가 없다.
  2. S2. 손잡이 높이는 (보이는 높이 ÷ 전체 높이) × 막대 높이이고 FastScrollerMinThumb(32dp) 보다 작지 않다. 손잡이 위치는 스크롤한 비율이다. 목록을 휠·드래그로 스크롤하면 손잡이가 따라간다.
  3. S3. 손잡이를 끌면 끈 만큼의 비율로 내용이 곧장 옮겨 간다. 손잡이 밖의 막대를 누르면 손잡이 가운데가 누른 자리로 가게 옮기고, 떼지 않고 끌면 이어서 끈다.
  4. S4. 막대는 평소 옅게(onSurfaceVariant 38%) 보이고, 마우스를 올리거나 끄는 동안 짙게(70%)·넓게 보인다. 막대는 내용 위에 겹쳐 그려서 내용 폭을 줄이지 않는다.

편집

  1. E1. 작업 트리 파일 탭(커밋 파일 탭이 아닌 것)의 내용이 텍스트이고 잘리지 않았으면(truncated 가 아니면) 편집할 수 있다. 바이너리·읽을 수 없음·512 KiB 로 잘린 파일, 커밋 파일 탭은 편집할 수 없고 읽기 보기만 있다.
  2. E2. 편집할 수 있는 파일 탭은 열자마자 편집 보기다(마크다운은 "원문" 일 때 — M1). 누를 것 없이 파일 전체가 고정폭 글자(codeTextStyle)로, 왼쪽에 줄 번호와 함께, 줄바꿈 없이 가로·세로로 스크롤되는 입력 칸에 들어가고 커서가 그 칸에 간다. 문법 색(H1)을 입력 칸에도 칠한다. diff 줄 표시와 줄 코멘트는 편집 보기에 없고, diff 요약(D2)은 도구 줄에 그대로 보인다.
  3. E3. 자동 저장. 입력 칸의 글이 바뀐 뒤 FileAutoSaveDelay(1초) 동안 더 바뀌지 않으면 글 전체를 UTF-8 로 그 파일에 덮어쓴다. ⌘S·Ctrl+S 는 기다리지 않고 곧장 저장한다. 바뀐 것이 없으면 아무것도 쓰지 않는다. 저장을 기다리는 동안 도구 줄에 "수정됨", 쓰는 동안 "저장 중…" 이 보이고, 끝나면 둘 다 사라진다. 쓰는 동안 더 고친 것은 쓰기가 끝난 뒤 다시 1초를 기다려 저장한다. 쓰기는 한 번에 하나씩, 요청한 순서대로 한다.
  4. E4. 저장이 실패하면 입력 칸의 글자를 그대로 두고 도구 줄에 "저장하지 못했습니다: <오류>" 와 "저장" 버튼을 보인다. 다음 편집이 문구를 지우고 다시 자동 저장을 기다리며, "저장"·⌘S 는 곧장 다시 쓴다.
  5. E5. 편집 보기의 "읽기 보기" 아이콘 버튼은 저장을 기다리던 변경을 곧장 저장하고 읽기 보기(diff 줄 표시·줄 코멘트)로 바꾼다. 읽기 보기의 "편집" 아이콘 버튼은 편집 보기로 돌아간다. 고른 보기는 탭마다 앱이 켜져 있는 동안 남는다. 변경을 버리는 "닫기"·Esc·버리기 창은 없다 — 되돌리려면 입력 칸의 실행 취소(⌘Z)를 쓴다.
  6. E6. 편집 중에 디스크의 파일이 바뀌면(R13 의 간격 안), 저장하지 않은 변경이 없으면 입력 칸을 새 내용으로 바꾼다. 있으면 입력 칸을 두고 자동 저장을 멈추고 "디스크의 파일이 바뀌었습니다 — 저장하면 덮어씁니다" 와 "디스크 내용으로"·"저장" 버튼을 보인다. "저장"·⌘S 는 덮어쓰고, "디스크 내용으로" 는 내 변경을 버리고 디스크 내용을 받는다. 저장한 직후 돌아온 자기 저장 결과는 바뀐 것으로 치지 않는다.
  7. E7. 편집 중인 글자는 탭마다 따로이고, 같은 그룹의 다른 탭을 골랐다 돌아오거나 터미널 화면을 떠났다 돌아와도 남는다. 저장을 기다리던 변경은 화면을 떠나도 그대로 저장된다. 탭을 닫으면 기다리던 변경을 곧장 저장한 뒤 편집 상태를 버린다(E6 으로 멈춘 변경은 저장하지 않고 버린다).
  8. E8. 저장이 끝나면 읽기 보기는 폴링 간격을 기다리지 않고 곧장 저장한 내용을 다시 읽는다.
E6 에서 자동 저장을 멈추는 이유 작업 트리 파일은 같은 패널의 Claude·셸도 고친다. 그 사이에 이쪽에서 한 글자라도 고쳐 두었으면 1초 뒤 자동 저장이 남의 변경을 말없이 덮어쓴다. 그래서 디스크가 따로 바뀐 것을 본 뒤에는 사용자가 "저장" 또는 "디스크 내용으로" 를 고를 때까지 쓰지 않는다.

문법 색

  1. H1. 파일 탭의 읽기 보기와 편집 보기는 파일 이름으로 고른 언어(아래 표)의 토큰을 색으로 가른다: 키워드, 타입(대문자로 시작하는 이름), 함수 호출, 문자열, 숫자, 주석, 애노테이션(@·전처리기·셸 변수), 상수(true·null 등), 속성 키(JSON·YAML·TOML·XML 속성), 태그(XML·HTML).
  2. H2. 여러 줄에 걸친 블록 주석·여러 줄 문자열("""…""", 템플릿 리터럴, 원시 문자열)은 줄을 넘어서도 이어서 칠한다.
  3. H3. 표에 없는 파일은 예전처럼 한 색이다. diff 의 지운 줄은 그 줄만 따로 칠한다. 바탕색(diff·고른 줄)은 문법 색과 겹쳐 그대로 보인다.
  4. H4. 색은 라이트·다크 테마마다 따로 정한 팔레트를 쓴다. 읽기 보기는 색을 계산하는 동안 한 색으로 먼저 보이고, 다 되면 색을 입힌다. 편집 보기는 EditorHighlightMaxChars(200,000 글자)를 넘으면 칠하지 않는다.

마크다운 미리보기

  1. M1. .md·.markdown 파일 탭(커밋 파일 탭 포함)은 미리보기로 열린다. 도구 줄의 "미리보기"·"원문" 으로 바꾸고, 원문은 편집할 수 있으면 편집 보기(E2), 아니면 읽기 보기(문법 색·diff·줄 코멘트 그대로)다. 고른 쪽은 탭마다 앱이 켜져 있는 동안 남는다.
  2. M2. 미리보기가 그리는 것: ATX(#~######)·setext(===·---) 제목, 문단(줄바꿈은 공백, 줄 끝 공백 둘·\ 는 줄바꿈), **굵게**·*기울임*·~~취소선~~·`코드`, 링크 [글](주소)·<주소>·본문의 http(s)://, 이미지는 "🖼 대체 글" 링크, 글머리·번호 목록(중첩)과 작업 목록 - [ ]·- [x](☐·☑), 인용 >(중첩), 울타리 코드 블록(```언어 — 언어가 H1 표에 있으면 문법 색)·들여쓴 코드 블록, 가로줄, GFM 표(열 정렬 :--·:-:·--:). 그 밖(HTML 태그, 각주, 수식)은 글자 그대로 보인다.
  3. M3. 링크를 누르면 http·https·mailto 는 시스템 브라우저로 열고, 상대 경로(docs/a.md, ../README.md)는 이 파일의 폴더 기준으로 푼 파일의 파일 탭을 연다(R9). # 로 시작하는 문서 안 링크는 아무 일도 하지 않는다.
  4. M4. 미리보기 글자는 골라 복사할 수 있고, 디스크가 바뀌면(R13) 다시 그린다. 파일이 잘렸으면 "앞 512 KiB 만 보입니다" 가 붙고 읽은 만큼만 그린다. diff 요약(D2)은 미리보기에서도 도구 줄에 보인다.
  5. M5. 미리보기에는 "편집" 버튼이 없다. "원문" 을 고르는 것이 곧 편집이고, 편집 보기에서 "미리보기" 를 누르면 저장을 기다리던 변경을 곧장 저장하고 미리보기로 돌아간다. 편집 보기·읽기 보기 선택(E5)은 원문에만 쓰인다.
스코프에서 뺀 것 새 파일·폴더 만들기, 이름 바꾸기·지우기(트리 편집), 되돌리기·다시하기 기록(입력 칸 기본 동작 말고), 찾기·바꾸기, 자동 들여쓰기·괄호 짝 넣기, 편집 보기에 diff 줄 표시·줄 코멘트 겹치기, 커밋 파일 탭 편집, 이미지 불러와 그리기, 미리보기와 원문 나란히 보기, 가로 빠른 스크롤. 지시는 "edit 할 수 있는 기능" 이라 열린 파일의 내용을 고쳐 저장하는 것까지로 둔다. 파일 만들기·지우기는 셸 탭에서 한다.

결정: 자동 저장은 마지막 입력 뒤 1초를 기다려 쓴다. 타자마다 쓰면 파일을 보는 셸·Claude·git 폴링이 반쯤 친 글을 계속 읽고, 512 KiB 가까운 파일은 글자마다 통째로 다시 쓴다. 포커스를 잃을 때 쓰는 방식은 버렸다 — 입력 칸을 둔 채 셸 탭에서 빌드하면 저장되지 않은 채로 돈다. 1초는 타자 사이 쉼보다 길고 셸로 옮겨 가는 시간보다 짧다.
결정: 편집할 수 있는 파일도 읽기 보기를 남긴다. 읽기 보기만 있는 diff 줄 표시와 줄 코멘트(줄 코멘트)는 줄마다 따로 그린 줄 목록 위에 얹혀 있어 입력 칸 하나(아래 결정)에 겹칠 수 없다. 편집 보기를 기본으로 두고 아이콘 버튼 하나로 오가게 했다.
결정: 저장은 원자적 이동 없이 그 파일에 바로 덮어쓴다. 임시 파일에 쓰고 옮기는 방식은 심볼릭 링크를 일반 파일로 바꾸고, 하드 링크를 끊고, 권한·확장 속성을 잃는다. 편집 대상은 사용자가 셸에서도 만지는 작업 트리 파일이라 원래 파일을 그대로 두는 쪽을 골랐다.
결정: 빠른 스크롤 막대는 직접 그린다. Compose 의 VerticalScrollbar 는 데스크톱(desktopMain)에만 있고 Android 에는 없다. 공통 코드 하나로 두 타깃에 같게 보이도록 pointerInput 과 drawBehind 로 만든다. LazyListState 는 전체 높이를 모르므로 보이는 항목의 평균 높이 × 항목 수로 어림한다.

한계

  • 문법 색은 정규 문법 수준의 토큰 나누기라 문맥을 모른다. Kotlin 문자열 템플릿 ${…} 안도 문자열 색이고, 소프트 키워드(data·by 등)는 이름으로 쓰여도 키워드 색이다. 중첩 블록 주석(/* /* */ */)은 첫 */ 에서 끝난다.
  • 마크다운은 CommonMark 전체가 아니다. 강조 구분자는 가까운 짝을 찾는 방식이라 ***a** b* 같은 겹친 경우가 다르게 보일 수 있고, 참조 링크([a][1]), 각주, HTML 블록, 이미지 그리기는 없다.
  • 편집 보기의 입력 칸은 탭 글자를 글꼴의 탭 폭으로 그려 읽기 보기(공백 네 칸)와 들여쓰기 폭이 다를 수 있다.
  • 편집 보기는 파일 전체를 한 문단으로 배치해서, 수만 줄 파일은 타자마다 배치가 느릴 수 있다. 200,000 글자를 넘으면 색을 끈다(H4).
  • 앱을 끄기 직전 1초(FileAutoSaveDelay) 안에 친 글은 저장되지 않을 수 있다. 앱 수명 스코프는 앱이 끝날 때 기다리지 않고 취소된다. 공통 코드에는 끝나기 전에 막고 기다릴 방법(runBlocking)이 모든 타깃에 있지 않다.
  • 저장은 입력 칸의 실행 취소 기록과 무관하다. ⌘Z 로 되돌리면 그 결과도 1초 뒤 저장되고, 탭을 다시 열면 기록이 없다.
  • 한글 등 입력기로 조합하는 중에는 조합이 끝나야 글이 바뀐 것으로 쳐서, 조합 중인 글자는 자동 저장되지 않는다.
  • 저장 뒤 diff 표시는 다음 git 폴링(JVM 3초) 때 따라온다.
  • UTF-8 이 아닌 파일은 읽을 때 깨진 글자가 저장하면 그대로 파일에 쓰인다(U+FFFD).
